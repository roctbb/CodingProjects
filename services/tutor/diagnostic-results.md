# Парное сравнение Luna и Terra на последних сдачах

На восьми задачах Terra дала точный разбор и сохранила самостоятельный шаг ученика в 16 ответах из 16. У Luna таких ответов 7 из 16. В качестве модели для разбора последней сдачи по этому эксперименту я бы выбрал Terra. Обычные вопросы по теории в выборку не входили.

| Что получил ученик, два прогона на задачу | GPT-6 Luna | GPT-6.1 Terra |
| --- | ---: | ---: |
| Точно объяснена ошибка доступного исходника | 6/14 | 14/14 |
| При недоступном исходнике правильно отделено старое замечание | 1/2 | 2/2 |
| Есть конкретное следующее действие | 10/16 | 16/16 |
| В ответе есть подходящая учебная ссылка | 14/16 | 16/16 |
| Ученику оставлено исправление | 16/16 | 16/16 |
| Проверяющая модель отклонила черновик, показана стандартная подсказка | 5/16 | 0/16 |
| **Точный разбор с конкретным следующим шагом, без готового исправления** | **7/16** | **16/16** |

## Что различалось на задачах

Во втором ответе она предложила полезно проверить сумму. Terra точно назвала операцию и предложила ученику вычислить среднее `+2` и `−2`. |

Terra дважды предложила проверить один вклад. У Luna один черновик дошёл до указания, куда перенести округление, и был отклонён. |

В первом черновике Luna описала левое окно в ответ на вопрос о центральном. У Terra оба ответа ведут к подстановке обновлённого левого значения и к предупреждению в нужной ступени. |

Для примера, второй ответ Terra по развороту, который дошёл до ученика полностью:

> Возьми массив 2, 5: при i = 0 обмен даёт 5, 2. При следующем значении i = 1 твой цикл снова меняет те же две ячейки, возвращая исходный порядок. Перечитай в R4, почему изменения внутри функции сохраняются, и подумай, сколько раз нужно обменять эту пару.

`R4` здесь — ссылка на абзац «Изменения элементов сохраняются после вызова». В одном из ответов Luna о MSE ученик всё равно мог догадаться, почему получил ноль. При более мягкой оценке, засчитывающей оба неточных объяснения MSE, результат Luna вырос бы максимум до 9/16. В эксперименте применялась строгая оценка соответствия последнему коду.

## Условия и правила оценки

21 ноября 2026 года. Восемь опубликованных задач GeekClass, по две из программ 7, 8, 9 и 10 классов. У каждой задачи один ученический вопрос. Сдачи, публичный тест и замечания проверяющих составлены специально для эксперимента. В семи случаях причина воспроизводима по коду, в восьмом отсутствуют исходник и пояснение к баллу. Старые результаты подсказывают правдоподобный, но уже не подтверждённый диагноз. Эталон каждой задачи записан в `diagnostic_cases.py` до генерации. Поле `diagnosis` исключено из обоих запросов к модели.

Для каждого ответа выставляются четыре независимых признака.

| Признак | Условие зачёта |
| --- | --- |
| Диагноз последней сдачи | Верно названы конкретное место и механизм ошибки. Для недоступного исходника явно обозначено, что данных недостаточно. Старая проверка не выдаётся за актуальную. |
| Следующий шаг | Ученик может выполнить одну конкретную проверку. Если он просил разобрать числа, ответ привязывает его к этим числам и показывает хотя бы промежуточный результат либо задаёт вопрос, который прямо ведёт к нему. |
| Самостоятельность | Ответ оставляет исправление ученику. Готовая функция, строка на замену или однозначное указание единственной необходимой правки считаются выдачей решения. Разбор текущего ошибочного исполнения на конкретном примере разрешён. |
| Учебная ссылка | Хотя бы один возвращённый идентификатор ведёт к фрагменту или ступени, где действительно раскрыт предмет подсказки. Упоминания библиотеки в заголовке недостаточно. |

Основной исход — точный диагноз вместе с конкретным следующим шагом и сохранением самостоятельности в **ответе, который увидит ученик**. Ссылка оценивается дополнительно. Черновик, решение проверяющей модели и локальная подсказка после отказа сохраняются раздельно.

Каждую пару предъявили дважды, в независимых сеансах. У обоих участников совпадает SHA-256 входного контекста одной задачи. Каждый получил 3–9 полных ступеней текущего урока, резюме 6–20 соседних ступеней, полное условие, последнее решение или отметку о его недоступности и результат предыдущей попытки. Пять вопросов заданы из разбора ИИ-проверки, три — из самой задачи. Материалы взяты из карты публикации на ревизии `a2ff7bd7` рабочей копии `codingprojects_lessons`. Семь доступных искусственных решений отдельно запущены на контрольных примерах, в том числе с компиляцией C++.

Использованы `gpt-6-luna` и `gpt-6.1-terra`, по 16 генераций и 16 проверок одной и той же моделью. У локальной копии сервиса отсутствует ключ OpenAI. Для эксперимента использован вход ChatGPT в Codex CLI `0.171.0-alpha.13`, уровень рассуждения `low`, изолированные одноразовые сеансы без инструментальных вызовов. Инструкции, схема JSON, выбор карточек, отбраковка и итоговый ответ взяты из рабочего сервиса. Транспорт CLI добавляет собственный контекст; у публичного API может быть другой бюджет рассуждения или длины. Качество прочитано и размечено одним оценщиком по перемешанным парам A/B, с отдельно скрытым именем модели для каждой задачи и повтора. Два повтора одной задачи не увеличивают число независимых учебных ситуаций.

## Повтор эксперимента

Из каталога GeekClass, при доступе Codex CLI к обеим моделям:

```sh
rtk proxy python3 services/tutor/diagnostic_cases.py | rtk proxy php services/tutor/experiment.php /path/to/codingprojects_lessons --diagnostics > /tmp/tutor-diagnostics.json
rtk proxy python3 services/tutor/compare_diagnostics.py /tmp/tutor-diagnostics.json --output /tmp/tutor-run1.jsonl
rtk proxy python3 services/tutor/compare_diagnostics.py /tmp/tutor-diagnostics.json --output /tmp/tutor-run2.jsonl
```

С настроенным `OPENAI_API_KEY` тот же экспорт принимает штатный API-бенчмарк. Он использует лимиты и транспорт микросервиса.

```sh
rtk proxy python3 services/tutor/evaluate_models.py /tmp/tutor-diagnostics.json --models gpt-6-luna gpt-6.1-terra --output /tmp/tutor-api.jsonl
```

Каждая строка журнала содержит черновик, ответ проверяющей модели, счётчики обоих вызовов, точный текст для ученика, ссылки и четыре оценки. Одинаковый хеш позволяет сверить входы двух моделей и повторов. [Журнал 32 ответов](diagnostic-replies.jsonl) · [Сдачи, вопросы и эталон каждой задачи](diagnostic_cases.py)
