# Отчет об уязвимостях безопасности

## Информация о проекте
- **Тип**: Laravel веб-приложение (образовательная платформа)
- **Версия Laravel**: 12.0
- **PHP**: ^8.2
- **Дата анализа**: 2026-05-11

---

## Критические уязвимости (Critical)

### 1. Master Password Backdoor
**Файл**: `app/Http/Controllers/Auth/LoginController.php:48-51`

**Описание**: В системе аутентификации обнаружен бэкдор, позволяющий войти под любым пользователем используя мастер-пароль.

```php
if ($request->password == config('app.master_pass')) {
    $user = User::where($this->username(), $request->email)->get()->first();
    return $this->guard()->login($user);
}
```

**Риски**:
- Полный доступ к любому аккаунту в системе
- Обход всех механизмов аутентификации
- Компрометация данных всех пользователей

**Рекомендации**:
- Немедленно удалить этот код из production
- Если необходим административный доступ, использовать отдельный механизм с логированием
- Провести аудит логов на предмет использования этой функции

**CVSS Score**: 10.0 (Critical)

---

### 2. Отсутствие JWT Secret в конфигурации
**Файл**: `config/auth.php:105`

**Описание**: JWT секрет берется из переменной окружения без валидации и дефолтного значения.

```php
'jwt_secret' => env('JWT_SECRET')
```

**Файл**: `.env.example` - отсутствует значение для JWT_SECRET

**Риски**:
- Если JWT_SECRET не установлен, токены могут быть null или пустыми
- Возможность подделки JWT токенов
- Несанкционированный доступ через RemoteAuth

**Рекомендации**:
- Добавить валидацию наличия JWT_SECRET при запуске приложения
- Генерировать случайный секрет при установке
- Использовать сильный алгоритм (минимум 256 бит)

**CVSS Score**: 9.1 (Critical)

---

### 3. Open Redirect в RemoteAuthController
**Файл**: `app/Http/Controllers/RemoteAuthController.php:23-27`

**Описание**: Недостаточная валидация URL для редиректа.

```php
$url = $request->get('redirect_url');

if (!$url || !filter_var($url, FILTER_VALIDATE_URL)) {
    abort(422, 'Некорректная ссылка для перехода.');
}
```

**Риски**:
- Фишинговые атаки через легитимный домен
- Кража JWT токенов через редирект на вредоносный сайт
- Социальная инженерия

**Рекомендации**:
- Использовать whitelist разрешенных доменов для редиректа
- Проверять, что URL принадлежит доверенному домену
- Добавить rate limiting для этого endpoint

**CVSS Score**: 8.1 (High)

## Высокие уязвимости (High)

### 4. Слабая валидация email при регистрации
**Файл**: `app/Http/Controllers/Auth/RegisterController.php:62-72`

**Описание**: Проверка на символ "+" в email недостаточна для предотвращения множественных регистраций.

```php
function ($attribute, $value, $fail) {
    if (str_contains($value, '+')) {
        $fail('Адрес электронной почты не должен содержать символ "+".');
    }
}
```

**Риски**:
- Обход ограничений через точки в Gmail (user.name@gmail.com = username@gmail.com)
- Множественные регистрации с одного email
- Спам и злоупотребления

**Рекомендации**:
- Нормализовать email перед проверкой уникальности
- Для Gmail удалять точки и все после +
- Добавить верификацию email

**CVSS Score**: 6.5 (Medium)

---

### 5. Отсутствие CSRF защиты для Telegram Webhook
**Файл**: `app/Http/Middleware/VerifyCsrfToken.php:14-17`

**Описание**: Telegram webhook исключен из CSRF защиты.

```php
protected $except = [
    'telegram/webhook',
    'telegram/webhook/*',
];
```

**Риски**:
- Возможность отправки поддельных webhook запросов
- Спам уведомлений пользователям
- DoS атака через массовые запросы

**Рекомендации**:
- Использовать X-Telegram-Bot-Api-Secret-Token для валидации (уже частично реализовано)
- Сделать секретный токен обязательным
- Добавить rate limiting

**CVSS Score**: 7.5 (High)

---

### 6. Небезопасное хранение Telegram Chat ID
**Файл**: `app/User.php:14-16`

**Описание**: Telegram chat_id хранится в fillable без дополнительной защиты.

```php
protected $fillable = [
    'name', 'email', 'password', 'role', 'school', 'grade_year', 'birthday',
    'hobbies', 'interests', 'git', 'telegram', 'telegram_chat_id', ...
];
```

**Риски**:
- Mass assignment уязвимость
- Возможность привязки чужого Telegram аккаунта
- Перехват уведомлений

**Рекомендации**:
- Удалить telegram_chat_id из fillable
- Использовать отдельный метод для установки chat_id с валидацией
- Добавить подтверждение при изменении

**CVSS Score**: 7.2 (High)

---

### 7. Отсутствие rate limiting для критичных операций
**Файл**: `app/Http/Kernel.php`

**Описание**: Rate limiting применяется только к API (60 запросов в минуту), но не к веб-маршрутам.

**Риски**:
- Brute force атаки на логин
- Спам решений задач
- DoS через массовые запросы

**Рекомендации**:
- Добавить rate limiting для /login (5 попыток в 5 минут)
- Ограничить отправку решений (10 в минуту)
- Добавить CAPTCHA после нескольких неудачных попыток

**CVSS Score**: 7.0 (High)

## Средние уязвимости (Medium)

### 8. Потенциальная XSS через пользовательский контент
**Файл**: `app/Http/Controllers/TasksController.php:67-68`

**Описание**: Использование функции `clean()` для санитизации, но её реализация не проверена.

```php
$task->text = $request->text;
$solution->text = clean($request->text);
```

**Риски**:
- Stored XSS через текст задач и решений
- Кража сессий администраторов
- Дефейс страниц

**Рекомендации**:
- Проверить реализацию функции clean()
- Использовать проверенные библиотеки (HTMLPurifier уже подключен)
- Применять Content Security Policy

**CVSS Score**: 6.8 (Medium)

---

### 9. Информационная утечка через детальные сообщения об ошибках
**Файл**: `.env.example:3`

**Описание**: APP_DEBUG=true в примере конфигурации.

```env
APP_DEBUG=true
```

**Риски**:
- Раскрытие структуры БД через stack traces
- Утечка путей к файлам
- Информация о версиях библиотек

**Рекомендации**:
- Установить APP_DEBUG=false в production
- Настроить централизованное логирование
- Использовать кастомные страницы ошибок

**CVSS Score**: 5.3 (Medium)

---

### 10. Небезопасное сравнение паролей в некоторых местах
**Файл**: `app/Http/Controllers/Auth/LoginController.php:48`

**Описание**: Использование нестрогого сравнения для мастер-пароля.

```php
if ($request->password == config('app.master_pass'))
```

**Риски**:
- Type juggling атаки
- Обход проверки при определенных значениях

**Рекомендации**:
- Использовать строгое сравнение (===)
- Использовать hash_equals() для сравнения секретов

**CVSS Score**: 5.9 (Medium)

---

### 11. Отсутствие валидации размера загружаемых файлов
**Файл**: `app/Http/Controllers/Auth/RegisterController.php:68`

**Описание**: Ограничение 1000KB для аватара при регистрации, но 4000KB при редактировании.

```php
// Регистрация
'image' => 'image|max:1000'

// Редактирование (ProfileController.php:285)
'image' => 'image|max:4000'
```

**Риски**:
- DoS через загрузку больших файлов
- Заполнение дискового пространства
- Замедление работы сервера

**Рекомендации**:
- Унифицировать ограничения (рекомендуется 2MB)
- Добавить проверку типа файла по содержимому
- Использовать отдельное хранилище для файлов

**CVSS Score**: 5.0 (Medium)

---

### 12. Кэширование без инвалидации при критичных изменениях
**Файл**: `app/Http/Controllers/CoursesController.php:195`

**Описание**: Использование кэша для оценок без гарантированной инвалидации.

```php
$marks = Cache::remember("course:{$id}:marks", 5, function () use ($id) {
    return CompletedCourse::where('course_id', $id)->get();
});
```

**Риски**:
- Показ устаревших данных пользователям
- Несоответствие оценок в разных частях системы
- Проблемы с целостностью данных

**Рекомендации**:
- Инвалидировать кэш при изменении оценок
- Использовать tagged cache для групповой инвалидации
- Уменьшить TTL для критичных данных

**CVSS Score**: 4.5 (Medium)
