# Сроки, уведомления и бонусы на занятии

## Правила баллов

У урока есть цепочка сроков `deadline_policies` → `deadline_stages`. У задачи три режима: `inherit` (обычные задачи наследуют урок), `custom` (своя цепочка целиком) и `none`. Звёздные задачи по умолчанию не наследуют сроки. Новые обычные задачи наследуют правила автоматически. Для замены индивидуальных правил всех обычных задач в редакторе урока есть отдельный флажок.

Этап: дата/время в часовом поясе курса и оставшийся процент 0…100. До первого этапа — 100%, в момент этапа начинает действовать его процент, после последнего — последний заданный процент. Он не обязан равняться нулю. Количество этапов не ограничено приложением. Одинаковые моменты запрещены, порядок сортируется сервером. Проценты могут увеличиваться. Сдача всегда остаётся открытой. Итог округляется вверх; за отправленное решение сохраняется минимум 1 балл. За отсутствие сдачи — 0.

`CourseDeadlineService` — общий резолвер для страницы курса, задач, календаря и расчёта баллов. Снимок цепочки (включая отсутствие правил) сохраняется при сдаче в `solutions` и `code_submissions`. Асинхронная проверка переносит снимок исходной отправки. Изменение правил не пересчитывает заработанные оценки; лучшая предыдущая сдача сохраняется. Снятие штрафа и XP-бустер работают поверх снимка.

Миграция `2026_11_14_190000` импортирует старые дедлайны без пересчёта оценок. Старое правило «до конца дня включительно» и граничное сравнение сохраняются. Новые правила задаются до минуты. Даты этапов хранятся в UTC, часовой пояс — IANA. Редактирование защищено версией политики: при конфликте возвращается HTTP 409. История планировщика отменяет всю цепочку; версия после отмены увеличивается, чтобы старые уведомления не ожили. На календаре видны все этапы, охват задач считается по уникальным задачам. В нагрузке баллы работы относятся к первому сроку и не суммируются повторно на последующих этапах.

## Telegram

Действия курса → **Уведомления курса**. Преподаватели подключают личный Telegram в настройках профиля. Личные напоминания преподавателям и сообщения в чаты включены по умолчанию; ученики включают личные напоминания на вкладке «Дедлайны». Уведомления — за 24 часа до каждого этапа и при его наступлении.

Подключение группы:

1. Связать личный Telegram преподавателя с профилем.
2. Создать ссылку в уведомлениях курса и добавить бота в группу. Для темы форума отправить показанную `/start@bot course_TOKEN` внутри темы.
3. Обновить страницу и подтвердить название группы/темы. До подтверждения группа не получает напоминаний.

Токен одноразовый, 30 минут, хранится хеш. Проверяется Telegram ID отправителя и его текущие права в курсе. Личный профиль нельзя привязать к группе. Удаление бота отключает группу. Webhook требует `TELEGRAM_WEBHOOK_SECRET`; при polling публичный webhook без секрета закрыт. Обычный privacy mode бота можно оставить включённым. Поддержаны `message_thread_id`, ограничение частоты и миграция группы в супергруппу. См. [официальный Bot API](https://core.telegram.org/bots/api#sendmessage) и [групповые ссылки](https://core.telegram.org/bots/features#deep-linking).

Уведомления одного урока с одинаковым моментом и процентом объединяются по получателю. В группах не раскрываются скрытые/неоткрытые материалы, индивидуальные результаты не публикуются. Личные ученические напоминания учитывают доступ, скрытые задачи, полное решение и ожидающую проверки сдачу. При изменении сроков, отписке или потере прав очередь перепроверяет актуальность перед отправкой. Исторические сроки после миграции не рассылаются; после простоя напоминание «через сутки» не отправляется за уже наступивший срок. Сообщение о наступлении срока актуально сутки.

`deadline_notification_events` и `deadline_notification_deliveries` — постоянное расписание и журнал доставки с уникальными ключами. После ошибки 429/5xx есть отложенные повторы (до 8 попыток), при 403 группа отключается. Успешные отправки повторно не выполняются. Telegram не имеет idempotency key для `sendMessage`: если соединение оборвалось после принятия запроса, абсолютную гарантию «ровно один раз» дать нельзя. Поэтому неизвестный результат отмечается `uncertain` и повторяется вручную из журнала с предупреждением о возможном дубле. После прерывания воркера такие отправки тоже не повторяются автоматически.

### Запуск на сервере

Серверная настройка в этой задаче не выполнялась. Для выпуска нужны миграции и сборка:

```sh
php artisan migrate --force
npm run build
php artisan queue:restart
```

Laravel scheduler должен работать каждую минуту. Он запускает `telegram:poll --once` и `deadlines:dispatch`. Для уведомлений необходим отдельный воркер:

```sh
php artisan queue:work --queue=notifications --sleep=1 --tries=1 --timeout=90
```

В Docker Compose добавлен сервис `notifications`, независимо от тяжёлых AI/проверочных задач. После развёртывания запустить `docker compose up -d --build php queue notifications scheduler`. Не запускать polling одновременно с зарегистрированным webhook. При webhook зарегистрировать в Telegram секрет и обновления `message`, `my_chat_member`. При polling `getUpdates` получает эти обновления автоматически.

Планирование выполняется в нужную минуту; точное время появления сообщения зависит от очереди, сети и Telegram. Диагностика и ручной повтор доступны на странице уведомлений курса. Автотесты используют подмену HTTP, реальных сообщений не отправляют.

## GC за решение на занятии

В меню прикреплённой задачи, ступени или урока CodingProjects есть **Бонус за решение на занятии**. Сумма — за каждую полностью решённую задачу, `0` отключает бонус. Для урока/ступени охватываются их задачи. Занятие должно иметь дату, время и длительность; исключённые даты и материалы без даты не дают бонуса. Учитывается интервал `[начало, конец)` в часовом поясе расписания. Присутствие в классе дополнительно не проверяется — это согласованное правило по времени сдачи.

Сумма, окно и источник фиксируются при отправке в `class_bonus_snapshot`. При проверке позже начисляется зафиксированная сумма, если задача решена полностью без помощи XP-бустера. Поздний штраф по баллам не отменяет отдельный бонус за работу на занятии. Перенос занятия или изменение суммы не меняет условия уже отправленных работ. Если несколько подходящих материалов перекрываются, выбирается максимальный бонус, они не складываются. Ранее полностью решённые задачи не награждаются за повторную отправку.

`classroom_bonus_awards` с уникальным `(course_id,user_id,task_id)` и блокировка ученика предотвращают повторную выдачу. Одна задача даёт такой бонус один раз в курсе. Выдача и запись монет выполняются одной транзакцией; используются обычная история GC и всплывающее уведомление о монетах. Старым решениям бонус задним числом не выдаётся. На странице задачи во время занятия ученик видит размер бонуса и время окончания. Автоматическая выдача для внешних провайдеров потребует доверенного протокола результатов и пока не включена.
