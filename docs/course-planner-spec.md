# Техническое задание на модуль планирования и сопровождения курса CodingProjects

Версия 1.0 от 10 ноября 2026 года. Статус — проект для реализации.

Первая версия реализована в коде. Фактические команды API, запуск, подключения и границы поставки описаны в [документации реализации](course-planner-implementation.md); ниже сохранена целевая модель развития.

Модуль помогает преподавателю распределять содержание программы по занятиям, связывать занятия с материалами разных систем и вести журнал фактически проведённой работы. Календарь, прямые привязки материалов и сводка по урокам составляют первую поставку. Учёт смысловых единиц и ведомость отметок развиваются отдельными этапами внутри CodingProjects. Бот и автоматические сообщения вынесены за пределы первой поставки.

## Принятые решения

| Область | Решение |
| --- | --- |
| Размещение | Модуль внутри CodingProjects с собственными таблицами, сервисами и JSON API для интерфейса |
| Основная сущность | Занятие конкретного курса группы; учебный урок программы может занимать несколько занятий |
| Содержание занятия | Прямые ссылки на уроки, ступени, задачи и произвольные ресурсы провайдеров; отдельные текстовые записи |
| Промежуточные сущности | Самостоятельной сущности «активность» и назначения работ подгруппам в планировщике нет |
| Провайдеры | Реестр подключений и общий контракт каталога; CodingProjects предоставляет встроенный провайдер программы |
| Первые внешние подключения | GeekExam, GeekBattle и AI Code Battle; каждый может отдавать несколько типов материалов |
| Основная сводка | Количество уникальных материалов каждого выбранного провайдера по урокам и отдельный показатель дедлайнов |
| Типы проверок | Тренировка, контрольная и другие свойства — метаданные ресурсов, а не фиксированные столбцы и сущности ядра |
| План и факт | Хранятся раздельно; прошедшая дата не подтверждает проведение занятия |
| Календарь | Недельные позиции, период действия, исключения и дополнительные даты; пересчёт сохраняет ручные привязки и историю |
| Ведомость | Отдельный экран и модуль оценивания; персональные результаты не превращаются в распределение участников занятия |
| Уведомления | Следующий этап; в первой поставке сообщения не отправляются |

## Цели и границы

Преподаватель должен отвечать на вопросы: что запланировано на дату; что фактически делали; сколько занятий занял урок программы; какие материалы провайдеров к нему относятся; по каким задачам установлены сроки; какие даты перегружены дедлайнами; какие учебные элементы ещё не обеспечены письменной проверкой.

Первая поставка включает календарь, каталог с поиском и постраничной загрузкой, перетаскивание, текстовые записи, скобки уроков, дедлайны, журнал факта, динамическую сводку и календарные агрегаты. Использование материалов не запускает тесты или соревнования, не меняет их содержание и не открывает ученикам уроки автоматически.

За пределами первой поставки: бот, рассылки, учёт посещаемости, индивидуальные маршруты и назначения, автоматическое определение освоения темы учеником, двусторонняя синхронизация Google Sheets и изменение правил XP. Ведомость и разметка смысловых единиц описаны как самостоятельные последующие этапы, чтобы сохранить целостную модель развития.

## Термины и владение данными

**Программа** — содержание, общее для курсов. **Урок программы** — содержательный модуль, состоящий из ступеней. **Курс** — существующий объект CodingProjects с преподавателями и учениками. **Занятие** — конкретная единица планирования работы этого курса. В один день может быть несколько занятий; одно занятие может завершать один урок программы и начинать следующий.

**Провайдер** — зарегистрированный источник контента. **Ресурс** — единица контента с устойчивой ссылкой, типом и метаданными. **Привязка** — техническая связь ресурса непосредственно с занятием. **Учебный элемент** — понятие или умение с наблюдаемым результатом обучения.

Планировщик владеет календарём, планом, журналом и контекстными связями ресурсов с уроками. Провайдер владеет своим содержанием и результатами работ. Встроенный провайдер читает модели CodingProjects. Для задач CodingProjects источником сроков остаётся `TaskDeadline`; срок не копируется во вторую изменяемую таблицу.

Три вида отношений учитываются отдельно: «ресурс добавлен на занятие», «ресурс относится к уроку программы» и «вопрос или критерий проверяет учебный элемент». Совместное нахождение теста и ступени в одном занятии не устанавливает связь проверки автоматически.

## Модель данных

Названия таблиц ниже являются проектными. Для новых таблиц использовать префикс `planner_`. Все изменяемые записи содержат автора, время создания и изменения. Внешние идентификаторы хранятся строками с сохранением регистра.

### Календарь и занятия

| Таблица | Основные поля | Ограничения и смысл |
| --- | --- | --- |
| `planner_courses` | `course_id`, `starts_on`, `ends_on`, `timezone`, `default_duration_minutes`, `revision` | Одна запись на существующий курс; период включителен; длительность положительная |
| `planner_schedule_rules` | `planner_course_id`, `weekday`, `start_time`, `duration_minutes`, `valid_from`, `valid_until`, `position` | Одна недельная позиция; время начала необязательно; несколько позиций в один день допустимы |
| `planner_calendar_exceptions` | `planner_course_id`, `starts_on`, `ends_on`, `schedule_rule_id?`, `reason` | Исключение диапазона дат либо конкретной недельной позиции; причина сохраняется |
| `planner_calendar_slots` | `planner_course_id`, `local_date`, `start_time?`, `duration_minutes`, `origin`, `schedule_rule_id?`, `occurrence_key`, `state` | `origin`: `rule` или `manual`; `state`: `available`, `excluded`, `retired`; ключ повторного расчёта устойчив |
| `planner_sessions` | `planner_course_id`, `calendar_slot_id?`, `title`, `plan_note`, `backlog_position?`, `pinned_at?`, `origin`, `revision`, `deleted_at?` | Занятие без даты находится в «Без даты»; один активный план на календарное место |
| `planner_session_records` | `session_id`, `held_on`, `timezone`, `start_time?`, `duration_minutes?`, `note`, `status`, `plan_snapshot`, `confirmed_at?` | Одна текущая запись факта на занятие; `status`: `draft` или `confirmed`; исправления сохраняются в истории |

`revision` используется для защиты от одновременного редактирования. Состояние календарного места не означает состояние проведения: `available` может относиться и к прошедшей дате с незаполненным журналом.

`occurrence_key` уникален внутри курса. Уникальность активного занятия на месте обеспечивается ограничением БД, учитывающим `deleted_at`. Для заданного времени начала пересекающиеся позиции одной группы отклоняются; при отсутствии времени порядок задаётся `position`. Все ссылки между новыми таблицами проверяют область курса, а ID источника не преобразуется в integer.

Фактическая дата в журнале и время внесения записи различаются. Для ретроспективного ввода создаётся занятие с `origin=retrospective` и пустым исходным планом. Запись можно связать с существующим свободным местом либо создать дополнительное место на соответствующую дату.

### Провайдеры и прямые привязки

| Таблица | Основные поля | Ограничения и смысл |
| --- | --- | --- |
| `planner_providers` | `key`, `display_name`, `adapter_key`, `enabled`, `manifest_version`, `settings` | Уникальный системный ключ; конфигурация адресов и секретов доступна администратору |
| `planner_course_providers` | `planner_course_id`, `provider_id`, `enabled`, `show_in_summary`, `position` | Настройки каталога и сводки конкретного курса |
| `planner_resource_refs` | `provider_id`, `resource_type`, `external_id`, `title`, `open_url`, `source_revision?`, `public_metadata`, `last_checked_at`, `state` | Уникальная тройка `(provider_id, resource_type, external_id)`; описательный кеш, а не копия базы провайдера |
| `planner_session_resources` | `session_id`, `resource_ref_id`, `layer`, `sort_index`, `resource_snapshot`, `fact_state?`, `note?` | Прямая связь; `layer`: `plan` или `fact`; уникальность ресурса внутри занятия и слоя |
| `planner_session_texts` | `session_id`, `layer`, `sort_index`, `text`, `fact_state?` | Произвольные записи без обязательной связи с системным ресурсом |
| `planner_resource_lesson_links` | `session_resource_id`, `lesson_id`, `relation`, `origin` | `relation`: `study` или `related`; `origin`: `native_parent`, `provider_hint`, `manual` |
| `planner_changes` | `planner_course_id`, `actor_id`, `operation_id`, `operation_type`, `before`, `after`, `created_at` | История действий, пакетных изменений и исправлений журнала |

`planner_session_resources` является таблицей непосредственных привязок; отдельного объекта «активность» между занятием и ресурсом нет. Порядок материалов и текстов общий. Сервис перестановки выделяет позиции транзакционно и возвращает единый упорядоченный список интерфейсу.

В слое факта `fact_state` принимает `done`, `partial`, `not_done` или `unconfirmed`. Создание черновика журнала не переводит материалы в `done`. Аналитика факта использует подтверждённые записи; `not_done` и `unconfirmed` исключаются из количества выполненных материалов. Частично пройденные материалы показываются отдельно от завершённых.

Встроенный провайдер определяет родительский урок ступени и задачи. Для внешнего ресурса преподаватель может выбрать связанные уроки в компактном редакторе привязки. Подсказки провайдера не превращаются в подтверждённое покрытие тестом. Ресурс без такой связи остаётся в занятии и попадает в общую категорию «Без привязки к уроку».

Связь `study` означает непосредственную работу с содержанием урока и участвует в построении скобок. Связь `related` используется для сводки внешних материалов. Проверка по прошлой главе может учитываться в её сводке, не увеличивая число занятий изучения этой главы.

### Дедлайны

Для задач CodingProjects адаптер читает и изменяет существующую запись `TaskDeadline` по паре `(course_id, task_id)`, включая действующую политику штрафа. Запись срока в новом интерфейсе должна сразу отражаться в существующих экранах дедлайнов и наоборот. Изменение срока само по себе не запускает массовую перепроверку и не меняет уже выставленные оценки.

Для остальных ресурсов используется `planner_deadlines`: `planner_course_id`, `resource_ref_id?`, `title`, `due_on`, `lesson_id?`, `revision`. У ресурса по умолчанию один текущий учебный срок на курс. Для отдельного срока без внешнего ресурса обязательны название и явная связь с уроком, если он должен участвовать в сводке этого урока.

`due_on` — локальная календарная дата курса. Срок истекает в начале следующего локального дня, что соответствует действующей семантике дат CodingProjects. Точное время дедлайна не требуется для первой поставки.

Учебный срок внешнего материала, установленный в планировщике, не изменяет настройки внешнего сервиса. Если провайдер отдаёт свой срок, интерфейс различает «учебный срок курса» и «срок в источнике»; неподдерживаемая запись в источник не имитируется успешным сохранением.

Перенос материала или занятия не переносит дедлайн. Изменение дедлайна выполняется отдельным действием. Во всех местах отображения одной работы используется один текущий срок; в подтверждённом журнале сохраняется исторический снимок срока.

### Учебные элементы

Разметка добавляется последующим этапом и не является условием использования календаря и каталога.

| Таблица | Назначение |
| --- | --- |
| `planner_learning_units` | Устойчивый ID, программа, тема, название, ожидаемый результат, обязательность, состояние |
| `planner_step_units` | Связь ступени с элементами и роль `introduce`, `practice` или `review` |
| `planner_unit_dependencies` | Необязательные зависимости элементов; циклы отклоняются |
| `planner_resource_unit_links` | Ресурс, его версия, стабильный ключ вопроса или критерия, вариант, элемент, роль `target` или `support` |
| `planner_session_unit_facts` | Подтверждённые изученные элементы и частичное прохождение в конкретном занятии |

Пример: ступень о рекурсии содержит базовый случай, рекурсивный переход и стек вызовов. Вопрос может проверять один из этих элементов. Привязка всего теста к уроку даёт тематическую связь, но не доказывает проверку всех его элементов.

### Снимки и удаление

Привязка сохраняет название, тип, ссылку, версию источника, родительский урок и публичные метаданные на момент добавления. При подтверждении факта создаётся самостоятельный снимок. Обновление каталога не переписывает подтверждённую историю.

Изменившийся материал отмечается как обновлённый; преподаватель может обновить привязку плана отдельным действием. Удалённый ресурс сохраняется как недоступная ссылка со снимком. Удаление или отключение провайдера не каскадирует в журнал. Архивация курса сохраняет план и факт.

## Календарные правила

Количество занятий в неделю вычисляется из недельных позиций. Две позиции в понедельник и две в четверг дают четыре занятия, а не два. Длительность занятия и количество академических часов показываются раздельно; при необходимости для часов задаётся размер академического часа.

Генерация выполняется по локальным датам между `starts_on` и `ends_on` включительно. Сначала применяются недельные позиции с их периодами действия, затем исключения. Дополнительные места создаются явно. Исключение дня может отключить все позиции этого дня либо одну выбранную позицию.

Повторная генерация идемпотентна: совпадающие `occurrence_key` сохраняют свои ID и привязки. Перед изменением уже использованных мест показывается предварительный расчёт: какие даты добавятся, исчезнут из сетки, сохранятся вручную и какие занятия потребуется разместить заново.

Если дата исключена после наполнения занятия, содержимое переводится в «Без даты» либо переносится на выбранное доступное место. Исключённая дата остаётся видимой с причиной. Автоматический сдвиг цепочки является отдельной пакетной командой с предварительным просмотром; проведённые и закреплённые вручную занятия не сдвигаются.

Для переноса сохраняются ID занятия и его материалы, а меняется календарное место. Перенос и исключение не удаляют подтверждённый факт. Исправление фактической даты выполняется через редактирование журнала с записью в историю.

Проверочный пример: период 2–27 ноября 2026 года, по одному занятию в понедельник и четверг — восемь мест. Исключение 9 ноября оставляет семь. Это пример расчёта, а не календарь школьных каникул.

## Скобки уроков и правила подсчёта

Скобка урока строится по уникальным занятиям с прямыми учебными связями `study`. Подпись показывает название урока и количество таких занятий. При переносе, удалении или добавлении материала пересчёт происходит после подтверждённого сервером изменения.

Скобка может проходить через несколько недель. Неучебные даты не увеличивают количество занятий. Если внутри диапазона есть занятия с другим содержанием, разрыв обозначается визуально: скобка не должна создавать впечатление непрерывной работы над уроком.

При переходе между уроками одно занятие входит в обе группы. Интерфейс использует отдельные дорожки скобок и выделение соответствующих материалов; карточка занятия при этом одна. На узком экране название урока и число занятий остаются текстом, а сложные пересечения раскрываются при выборе урока.

В основной сводке столбцы формируются по включённым провайдерам курса. CodingProjects доступен в том же реестре; преподаватель может скрыть его столбец, если достаточно скобок программы. Типы материалов можно раскрыть как дополнительную детализацию внутри провайдера.

Для урока L и провайдера P количество материалов равно числу различных троек `(provider, type, external_id)`, связанных с L в выбранном слое плана или факта. Один ресурс на двух занятиях считается одним материалом; при необходимости рядом показывается число использований. Два варианта одного теста не становятся двумя ресурсами, если провайдер отдаёт тест единой карточкой.

В сводке факта отдельно возвращаются количества завершённых и частично пройденных ресурсов. Один ресурс, завершённый на одном занятии и частично пройденный на другом, входит в завершённые; частичный счётчик содержит только ещё не завершённые материалы. Это правило применяется после отбора подтверждённых записей журнала. Актуальность внешнего каталога показывается отдельным признаком и не отменяет уже подтверждённый факт.

Ресурс, связанный с двумя уроками, участвует в обеих строках. Итог по курсу вычисляется отдельным `distinct`, а не сложением строк. Материалы без связи с уроком видны в отдельной строке и входят в итог курса. Ошибка провайдера и отсутствие разметки не отображаются как подтверждённый ноль.

Для дедлайнов задач CodingProjects показывается `X из Y`: X — количество обязательных видимых задач урока с установленным сроком курса; Y — количество таких задач в выбранной версии программы. Скрытые и дополнительные задачи выводятся отдельными фильтрами; существующая политика сроков задач со звёздочкой сохраняется. При отсутствии подходящих задач показывается «Не применимо».

Для внешних ресурсов без известного полного перечня задач показывается количество сроков без искусственного знаменателя. Наличие дедлайна хотя бы у одной задачи не обозначается как полное покрытие урока сроками.

Календарные графики строятся по неделе, уроку, главе или выбранному диапазону: количество материалов по провайдерам, число сроков, баллы к сдаче и количество учебных занятий. Баллы разных шкал являются отдельными рядами с указанием единицы; XP, баллы теста и рейтинг соревнования не суммируются автоматически. Индивидуальная трудоёмкость и прогноз времени домашних работ не входят в первую поставку.

После разметки учебных элементов дополнительный экран показывает изученные элементы, предусмотренную проверку, запланированную проверку и фактически предложенную проверку. Письменный формат, тренировочность и контрольный характер берутся из метаданных. Итоговая оценка вопроса, проверяющего несколько элементов, не распределяется между ними без явных критериев. Для вариантов теста показывается покрытие каждого варианта и их пересечение; объединение всех вариантов не выдаётся за проверку всех учеников.

## Контракт провайдеров

### Общие правила

Контракт версии `1` описывает каталог и чтение материалов. Подключение нового совместимого провайдера требует регистрации и настройки, а не добавления нового типа занятия или отдельной вкладки интерфейса. Типы `test`, `task`, `competition` в примерах принадлежат провайдеру и не являются закрытым перечислением ядра.

Встроенный адаптер CodingProjects читает данные локально. Внешние адаптеры работают по HTTP через сервер CodingProjects. Браузер обращается только к API планировщика и не получает сервисных ключей или cookie внешних систем.

Сервисный запрос подписывается отдельными учётными данными интеграции. Для JWT обязательны назначение `course-planner`, отправитель, аудитория конкретного провайдера, ID действующего пользователя CodingProjects, область `catalog:read` или `content:read`, время выпуска и срок действия не более 60 секунд. Подпись и разрешённый отправитель проверяются провайдером; ID в query не заменяет авторизацию. Провайдер применяет свою действующую политику доступа к объектам.

В GeekExam ID пользователя соответствует внешнему ID CodingProjects. В существующем GeekBattle локальный пользователь имеет UUID и отдельный `external_id`; интеграция сопоставляет пользователей через `external_id`. Учётные данные и базовые адреса настраиваются администратором на сервере.

### Методы

Предлагаемые пути на стороне совместимого провайдера:

| Метод и путь | Назначение |
| --- | --- |
| `GET /integrations/course-planner/v1/manifest` | Описание провайдера, доступных типов и возможностей |
| `GET /integrations/course-planner/v1/resources` | Ограниченная страница каталога с серверным поиском |
| `GET /integrations/course-planner/v1/resources/detail?type=...&external_id=...` | Карточка конкретного материала |
| `POST /integrations/course-planner/v1/resources/resolve` | Чтение до 100 ссылок одним запросом; доступ проверяется для каждой |
| `GET /integrations/course-planner/v1/resources/children?type=...&external_id=...` | Постраничное чтение дочерних материалов, если объявлена возможность `children` |
| `GET /integrations/course-planner/v1/resources/components?type=...&external_id=...&revision=...` | Публичные ключи вопросов и критериев для разметки элементов; последующий этап |

Параметры списка: `query` до 200 символов, `type` из manifest, `cursor`, `limit`, необязательная ссылка на родителя и контекст курса. Значение `limit` по умолчанию 25, максимум 50. Неизвестные типы отклоняются. Контекст содержит ID курса как справочную область интеграции и не даёт дополнительных прав.

Пример manifest:

```json
{
  "protocol_version": "1",
  "provider_key": "geekexam",
  "display_name": "GeekExam",
  "resource_types": [
    {
      "key": "test",
      "label": "Тест",
      "capabilities": {
        "children": false,
        "components": true,
        "course_deadline": "planner"
      }
    }
  ],
  "pagination": {"mode": "cursor", "default_limit": 25, "max_limit": 50},
  "search": {"server_side": true, "fields": ["title", "description", "tags"]}
}
```

`course_deadline` принимает `planner`, `source` или `none`. В режиме `planner` срок принадлежит курсу в планировщике; `source` означает отдельное чтение срока источника и требует описания его контекста; `none` скрывает действие добавления срока к этому типу. Дополнительные поля manifest допускаются, но неизвестная возможность не активирует неизвестное действие интерфейса.

Пример страницы каталога с одной демонстрационной карточкой:

```json
{
  "protocol_version": "1",
  "provider_key": "geekexam",
  "items": [
    {
      "external_id": "42",
      "type": "test",
      "type_label": "Тест",
      "title": "Производительность алгоритмов",
      "description": "Оценка числа действий и сравнение алгоритмов",
      "open_url": "https://exam.geekclass.ru/tests/42",
      "source_revision": "revision-7",
      "updated_at": "2026-11-10T12:00:00Z",
      "source_state": "draft",
      "public_metadata": {
        "duration_minutes": 25,
        "intent": "training",
        "response_format": "written",
        "points": {"value": 18, "unit": "geekexam.points"},
        "topics": ["Число действий", "Рост времени работы"]
      }
    }
  ],
  "page": {"next_cursor": "opaque-next-page", "has_more": true, "total_count": null}
}
```

ID, версия и URL в примере иллюстрируют форму контракта, а не существующий объект. `open_url` возвращается самим адаптером; интерфейс не собирает ссылки по предположению о маршрутах сервиса. `source_revision` может быть `null`, если источник не умеет версионирование; в этом случае используется локальный снимок с отметкой времени получения.

Краткая карточка не содержит полных условий, ответов, промптов проверки, приватных тестов, посылок и персональных результатов. Объём элемента списка ограничивается 4 КиБ, детали запрашиваются отдельно. Метаданные трактуются как данные и проходят экранирование; произвольный HTML провайдера не исполняется.

### Поиск и постраничная загрузка

Поиск, фильтрация типа и ограничение страницы выполняются на стороне провайдера. Скачивание полного каталога с последующим разбиением в браузере или в адаптере CodingProjects не соответствует контракту. Для существующих непостраничных API необходимо добавить ограниченные методы на стороне источника.

Курсор непрозрачен для клиента и привязан к запросу, фильтрам, порядку сортировки и правам пользователя. Порядок стабилен: после поля сортировки используется устойчивый ID. Изменение запроса или фильтра сбрасывает курсор. При протухшем курсоре источник возвращает `409 cursor_expired`, после чего интерфейс предлагает обновить список с первой страницы.

`total_count` необязателен: если подсчёт дорогой, показывается номер просмотренной страницы и кнопки перехода без выдуманного общего числа. Для возврата на предыдущую страницу клиент хранит стек курсоров; положение восстанавливается отдельно для каждого провайдера и поискового запроса.

Ошибки: `401 integration_unauthorized`, `403 access_denied`, `404 resource_not_found`, `409 cursor_expired`, `422 invalid_filter`, `429 rate_limited`, `503 provider_unavailable`. Ошибка одного подключения не скрывает сохранённый календарь или другие источники. Кешированные материалы помечаются временем обновления; отказ в доступе не подменяется успешным ответом из общего кеша.

### Совместимость источников

В GeekExam уже существуют `GET /api/tests` и чтение теста; в GeekBattle — `GET /api/v1/battles` и чтение батла. Эти списки используют сессию пользователя и возвращают список без контрактной постраничной загрузки. Их нельзя напрямую использовать как масштабируемый каталог первой поставки.

Адаптеры сохраняют существующие функции сервисов. Новые интеграционные методы используют те же правила доступа и отдельные безопасные сериализаторы кратких карточек. Для AI Code Battle требуется реализовать или подтвердить поддержку контракта: в каталоге могут одновременно присутствовать задания и командные соревнования. Готовность этого подключения проверяется контрактными тестами, а не демонстрационными данными интерфейса.

## API планировщика в CodingProjects

Страница модуля: `/insider/courses/{course_id}/planner`. JSON методы размещаются под `/insider/courses/{course_id}/planner/api` с существующей сессионной авторизацией и CSRF для изменений. Для непрозрачных ключей провайдера использовать параметры `provider_key`, `resource_type`, `external_id`; глобальный числовой шаблон маршрута `{id}` не должен применяться к UUID и строковым ключам.

| Метод относительно префикса | Назначение |
| --- | --- |
| `GET /calendar?from=...&to=...` | Настройки, календарные места и краткие занятия диапазона |
| `PUT /calendar/settings` | Изменение периода и недельных правил |
| `POST /calendar/rebuild-preview` | Предварительный расчёт перестройки без записи |
| `POST /calendar/rebuild` | Применение подтверждённого расчёта с проверкой версии |
| `POST /calendar/exceptions` | Исключение диапазона или позиции с причиной |
| `POST /calendar/slots` | Дополнительная дата |
| `POST /sessions` | Создание занятия, в том числе без даты |
| `PATCH /sessions/{session_id}` | Заголовок, примечание и закрепление размещения |
| `POST /sessions/{session_id}/move` | Перенос занятия в другое свободное место |
| `POST /sessions/{session_id}/resources` | Прямая привязка материала или пакетное добавление |
| `POST /sessions/{session_id}/split-lesson` | Преобразование урока целиком в явные ступени и перенос выбранных частей |
| `POST /sessions/{session_id}/texts` | Произвольная текстовая запись |
| `POST /session-content/move` | Атомарный перенос и перестановка материала или текста |
| `DELETE /session-resources/{link_id}` | Удаление привязки, без удаления источника и дедлайна |
| `PATCH /session-texts/{text_id}` | Изменение текста |
| `DELETE /session-texts/{text_id}` | Удаление текстовой записи |
| `PUT /sessions/{session_id}/record` | Сохранение и подтверждение факта |
| `GET /journal?from=...&to=...&lesson_id=...` | Журнал фактически проведённой работы |
| `GET /providers` | Подключённые провайдеры и поддерживаемые типы |
| `GET /providers/{provider_key}/resources` | Страница каталога выбранного провайдера |
| `GET /resources/detail?provider_key=...&resource_type=...&external_id=...` | Детали и актуальность материала |
| `PUT /deadlines` | Изменение срока через единый сервис владельца данных |
| `DELETE /deadlines/{deadline_key}` | Снятие срока; ключ не ограничен числовым шаблоном |
| `GET /summary?layer=plan&from=...&to=...` | Счётчики уроков и агрегаты календаря |
| `GET /history` | Последние изменения курса |
| `POST /history/{operation_id}/undo` | Отмена доступной операции с проверкой текущего состояния |

Мутации передают `operation_id` и ожидаемую `revision`. Повтор того же `operation_id` возвращает результат первой операции. Сервер проверяет принадлежность обеих сторон переноса курсу и выполняет перенос, изменение порядка и увеличение версии в одной транзакции. При конфликте возвращается `409 revision_conflict` и актуальная версия; интерфейс восстанавливает согласованное состояние.

Администратор имеет доступ к модулю курса. Преподаватель должен быть включён в преподавателей этого курса; одной глобальной роли `teacher` недостаточно. Ученики не получают доступ к экрану редактирования первой поставки. Каждая привязка, запись факта и срок проверяются в области курса на сервере.

## UX сценарии

Основной экран содержит занятия по датам и каталог справа. Переключение «План» и «Журнал» меняет слой данных, сохраняя выбранный период. Под календарём находится компактная сводка по урокам; подробный обзор раскрывается на всю ширину. В карточке занятия доступны добавление материалов, текст, перестановка и переход к источнику.

### Первичная настройка

Преподаватель открывает курс, задаёт период, длительность и недельные позиции, затем отмечает каникулы и исключения. Система показывает число доступных занятий и создаёт пустую сетку. Повторный вход открывает сохранённый период и положение календаря. Настройки планирования не меняют даты запуска и завершения существующего курса.

### Каталог большого провайдера

После выбора провайдера загружается первая страница из 25 карточек. Каталог содержит поиск и фильтр типа, полученный из manifest. Ввод запускает запрос после паузы 300 мс; запрос можно отправить сразу клавишей Enter. Старый запрос отменяется, а ответ с устаревшим номером запроса игнорируется.

Видны состояния первой загрузки, перехода страницы, пустого результата, ошибки и повторной попытки. Во время фонового обновления предыдущие карточки остаются видимыми с индикатором обновления. Новый провайдер или фильтр не показывает материалы предыдущего подключения под новым заголовком.

Переходы «Назад» и «Далее» загружают страницы, а не весь каталог. Перетаскивание и добавление через кнопку «+» не сбрасывают запрос, страницу и прокрутку каталога. Выбор занятия также не перезапрашивает каталог. В первой поставке глобальный поиск сразу по всем внешним провайдерам не требуется.

Для программы CodingProjects используется дерево «глава → урок → ступени и задачи» с ленивым раскрытием. Внешние коллекции и дочерние материалы также загружаются по требованию. При удалении материала из каталога уже созданная привязка занятия сохраняется.

### Добавление и разделение урока

Перетаскивание из каталога создаёт ссылку; исходная карточка остаётся в каталоге. На занятии показываются название материала, провайдер, тип и доступные действия. Название открывает детали или исходный сервис; добавление обозначено отдельной кнопкой «+», чтобы переход к материалу не добавлял его неожиданно.

Урок целиком можно добавить одной прямой ссылкой на урок. При добавлении фиксируется список его ступеней. Для распределения по нескольким занятиям команда разделения заменяет эту ссылку явными ссылками на выбранные и оставшиеся ступени в одной операции. Частный вариант интерфейса может сразу создавать пакет ступеней, сохраняя ту же семантику снимка и отмены.

Сервер не допускает двойного учёта ступени, уже включённой в урок целиком на этом занятии: интерфейс предлагает раскрыть урок и выделить часть. Одна и та же ступень на разных занятиях допустима, например для повторения. Привязка задачи для отдельного разбора не означает повторное назначение её срока.

Скобки и счётчики обновляются после добавления. Перенос материала между занятиями перемещает его привязку, сохраняет срок и обновляет группы уроков. При нескольких уроках в одном занятии карточка не дублируется.

### Связь внешнего материала с уроком

Если провайдер отдаёт подходящую подсказку, она показывается при добавлении. Преподаватель может подтвердить урок, выбрать несколько уроков или оставить ресурс без связи. Это необязательное действие в редакторе карточки; отсутствие разметки не блокирует планирование.

Режим `related` используется по умолчанию для внешнего теста или соревнования. Переключение на `study` требуется, только если сам ресурс составляет изучение урока и должен влиять на скобку. Покрытие учебных элементов настраивается отдельно.

### Текстовые записи и доступность

Произвольная запись создаётся непосредственно внутри занятия: например, «Защита проектов» или «Обсуждение олимпиады». Она перемещается и редактируется как текстовый блок и не требует выбора провайдера.

Каждое действие перетаскивания имеет клавиатурную альтернативу: выбор занятия и «Добавить», «Переместить в…», «Выше», «Ниже». На сенсорном экране используется тот же выбор назначения. Контроль сохранения, ошибки и возможность отмены доступны без наведения мыши.

### Переносы и отмена

Перестановка сохраняется автоматически. Пока запрос выполняется, интерфейс показывает состояние сохранения. При ошибке изменение откатывается или явно остаётся несохранённым с повторной попыткой; пользователь не получает ложного подтверждения.

«Отменить» доступно для последней применимой операции, в том числе пакетного переноса и добавления урока. Отмена проверяет версию: чужое последующее изменение не перезаписывается молча. Подтверждённый факт исправляется как новая запись истории, а не исчезает вследствие отмены изменения плана.

Исключение даты сохраняет материалы в очереди «Без даты» или переносит их в выбранное место. Пересчёт сетки, массовый сдвиг и изменение дедлайна не объединяются в одно неявное действие.

### Дедлайн и журнал

Преподаватель задаёт срок в карточке работы либо в обзоре дедлайнов. Одинаковый материал на нескольких занятиях показывает одинаковый текущий срок. На календаре дедлайн виден отдельной отметкой на дату сдачи, даже если на этот день нет занятия.

После занятия преподаватель открывает журнал и выбирает «Проведено по плану» либо отмечает фактически пройденные материалы, частичное прохождение и заметку. Перенесённое содержание можно добавить в следующий план отдельным действием. Черновик журнала сохраняется, но не считается подтверждённым фактом.

Для старой даты можно внести занятие без предварительного плана. Фильтры по датам, главе и уроку дают последовательный ответ «что мы делали». Сравнение показывает исходный план и фактическую запись без подмены одного другим.

### Сводка и разметка

Выбор строки урока выделяет его материалы в календаре. Нажатие на счётчик провайдера раскрывает конкретные ресурсы и даты использования. Нажатие на дедлайны раскрывает задачи со сроками и без них. Нулевые счётчики нейтральны: использование каждого провайдера в каждом уроке не является обязательным.

В расширении смысловых единиц преподаватель открывает ступень, добавляет элементы и связывает их с вопросами или критериями доступного провайдера. Неразмеченный материал получает состояние «Связи не указаны»; оно отличается от подтверждённого отсутствия проверок.

## Ведомость отметок как отдельное расширение

### Соответствие текущему рабочему процессу

Рабочая [ведомость 2026](https://docs.google.com/spreadsheets/d/1sjhobu6DBoiYwSpjEg1woqZQbMuyabJ3e5FRKIn2quQ/edit) содержит отдельные листы для 7, 8 и 9 классов за первый триместр и для 10 класса за первое полугодие. В колонках используются баллы и отметки, ручные отметки за внешние активности, разные знаменатели и нижние границы шкалы. Пометка `(2)` означает вес отметки 2 при подведении итогов.

Показательные формулы: на листе 8 класса `F3` ограничивает отметку за NANDgame десятью и пересчитывает баллы из `E3` относительно 140 баллов по шкале 3–10; `H3` пересчитывает `G3` относительно 24 баллов по шкале 2–10. Часть колонок других листов также ограничивает максимум, а часть формул явно не содержит ограничения. Эти правила задаются параметрами, а не копированием формул по ученикам.

Ведомость реализуется отдельным экраном курса. Строки соответствуют ученикам, колонки — оцениваемым результатам. Колонка может представлять главу, весь курс, тест, проект, олимпиаду или произвольную внешнюю активность. Для олимпиады не создаётся искусственная глава программы. Персональная проверочная является колонкой с выборочно заполненными результатами; это не добавляет назначения участников в календарь занятий.

До реализации и сверки ведомости Google Sheets остаётся рабочим инструментом выставления отметок. Первая интеграция — выгрузка проверяемых баллов из CodingProjects и последующая сверка. Автоматическая двусторонняя запись в существующий файл не входит в этап планировщика и требует отдельной реализации с явным источником истины.

### Данные ведомости

| Таблица | Основные поля и смысл |
| --- | --- |
| `gradebooks` | Курс, название периода, даты, состояние `open` или `closed`, правило итогового округления |
| `gradebook_columns` | Название, порядок, необязательная визуальная группа, `source_type`, ссылка на источник, `score_scope_snapshot`, `bonus_policy`, шкала, `reference_points`, вес, участие в итоге, политика выбора попытки |
| `gradebook_cells` | Колонка, `student_id`, статус, исходные баллы, вычисленная отметка, ручная отметка, основание исправления, версия источника и политики |
| `gradebook_snapshots` | Зафиксированный состав колонок, знаменатели, веса и результаты закрытого периода |
| `gradebook_changes` | История изменения баллов, правил, ручных исправлений и закрытия периода |

`source_type`: `manual_grade`, `manual_points`, `codingprojects_chapter`, `codingprojects_course`, `provider_result`. Ручная колонка не обязана иметь привязку к занятию или материалу провайдера. Визуальная группа колонок не меняет структуру программы.

Статусы ячейки: `not_entered`, `pending`, `graded`, `exempt`. Пустое значение — отсутствие выставленной отметки, а не ноль баллов. Явный числовой ноль — результат, подлежащий пересчёту. Ошибка получения данных провайдера сохраняет прежний результат с состоянием обновления и не выставляет ноль.

### Шкала и веса

Для колонки задаются `grade_min`, `grade_max`, положительный `reference_points`, способ округления, количество знаков `decimals`, ограничение снизу и сверху, положительный `weight` и `include_in_total`. По умолчанию используется линейная шкала с округлением до целого ближайшего значения; половина округляется вверх для неотрицательной отметки.

```text
ratio = points / reference_points
unrounded_grade = grade_min + ratio * (grade_max - grade_min)
rounded_grade = round_half_up(unrounded_grade, decimals)
grade = clamp(rounded_grade, grade_min, grade_max)
```

Ограничение диапазоном включено по умолчанию; для точного воспроизведения исторического правила его можно отключить в конкретной колонке. Начисленные баллы сохраняются без обрезки. Бонусные баллы могут превышать `reference_points`, но при включённом ограничении отметка не превышает `grade_max`.

Примеры: шкала 3–10 и знаменатель 140 дают 3 за 0 баллов, 7 за 70, 10 за 140 и 10 за 161 при включённом ограничении. Шкала 2–10 со знаменателем 24 даёт 6 за 12 баллов. Незаполненная ячейка остаётся пустой во всех этих шкалах.

Если итог периода рассчитывается как среднее отметок с весами:

```text
final_raw = sum(weight_i * effective_grade_i) / sum(weight_i)
```

В расчёт входят выставленные отметки включённых колонок; вес 2 означает коэффициент 2, а не две записи одной работы. Ячейки без отметки и освобождение исключаются из числителя и знаменателя. Рядом показывается полнота заполнения, чтобы предварительный итог не выглядел окончательным. При отсутствии учитываемых отметок итог пустой. Закрытие периода фиксирует его политику и результаты.

`reference_points` — объявленный максимум или порог получения максимальной отметки. Он не берётся из лучшего результата ученика класса и не меняется автоматически после редактирования курса. Для главы сохраняется выбранный состав задач и политика бонусов; изменение состава или знаменателя выполняется отдельным действием с предварительным пересчётом.

`score_scope_snapshot` фиксирует ID задач главы или курса, дату среза и выбранную область содержания. Для CodingProjects сумма берётся по лучшей проверенной оценке каждой выбранной задачи именно в этом курсе. Скрытые задачи по умолчанию исключены. Бонусы либо исключаются, либо добавляются в числитель по явной `bonus_policy`; их наличие не увеличивает объявленный `reference_points`. При создании колонки интерфейс показывает состав задач и фактический максимум вместе с выбранным порогом максимальной отметки.

`CourseStudentPoints.percent`, буквенная шкала `Mark::getMark`, XP и школьная отметка имеют разный смысл. Для новой ведомости исходные баллы и область их подсчёта задаются явно. Введение шкалы 2–10 или 3–10 не меняет существующие буквенные оценки завершённых курсов и награды.

### Результаты провайдеров и переход с таблицы

Импорт результатов — отдельная необязательная возможность провайдера с областью доступа `results:read`. Расширение API отдаёт ресурс, внешний ID ученика, попытку, исходные баллы, максимум, единицу измерения, статус проверки, время и версию результата. Для нескольких попыток колонка явно выбирает лучшую, последнюю проверенную либо конкретную попытку.

ID ученика сопоставляется с существующим пользователем CodingProjects. Совпадение имени не является устойчивым ключом. Ручная коррекция отметки сохраняется отдельно от расчётной, с причиной; повторное получение баллов не стирает её.

Переход выполняется на одном выбранном периоде: настроить колонки и веса, получить исходные баллы, сверить вычисления на обезличенных примерах, затем сравнить ведомости целиком. При импорте исторической таблицы выполняется явное сопоставление учеников и колонок. Первая выгрузка должна содержать стабильные ID учеников и колонок вместе с понятными названиями. Произвольные формулы Google Sheets не исполняются на сервере: используются согласованные параметры шкалы и веса.

Экран ведомости предоставляет ручной ввод, массовую вставку чисел, просмотр исходных баллов и формулы пересчёта, фильтр периода, предварительный итог и закрытие периода. Создание колонок из главы и из ресурса провайдера является удобным действием; наличие материала в календаре само по себе отметку не создаёт.

## Производительность и устойчивость интерфейса

Проверочные объёмы для первой поставки: 136 занятий в учебном году, не менее 500 привязок в курсе и каталог провайдера из 10 000 материалов. Это объёмы испытаний, а не жёсткие пределы модели.

Первоначально загружается диапазон календаря около шести недель, следующий диапазон подгружается отдельно. Счётчики по полному курсу вычисляются сервером и не требуют отрисовки всех карточек. Большие уроки и коллекции раскрываются лениво. Условия, тетрадки, изображения и подробности проверок не включаются в ответ списка.

Размер страницы каталога — 25 карточек, серверный максимум — 50. Ответ страницы с краткими карточками должен укладываться в 256 КиБ. На стенде с 10 000 материалами целевой p95 поиска и страницы — до 1 секунды на стороне провайдера; целевой p95 локальной выборки календаря и сводки — до 500 мс без ожидания внешнего API. Результаты замеров фиксируются вместе с конфигурацией стенда.

Подключение к внешнему сервису ограничивается 1 секундой, общее ожидание — 5 секундами; параметры допускают серверную настройку. Запросы независимых провайдеров не блокируют сохранение локального плана. Кеш списка живёт до 60 секунд, ключ включает провайдера, пользователя и область прав, запрос, фильтры, курсор и размер страницы. Истечение прав не скрывается за общим кешем.

Изменение поискового запроса отменяет прежний запрос, а интерфейс дополнительно проверяет его последовательный номер. В DOM остаётся текущая страница каталога; старые страницы хранятся ограниченно либо восстанавливаются по курсору. Большой каталог не превращается в тысячу невидимых элементов страницы.

Перемещения используют оптимистичный интерфейс с обязательным подтверждением сервера. Параллельные изменения курса разрешаются через `revision`. На узком экране каталог открывается отдельной панелью; основной сценарий остаётся доступен через «Добавить на занятие» без точного жеста перетаскивания.

Настройки периода находятся в новых таблицах: существующие `Course::start()` и `Course::end()` записывают даты жизненного цикла курса. Даты открытия уроков остаются в `LessonInfo`; их изменение не является побочным эффектом размещения ступени в календаре.

Права проверяются как сочетание роли и членства в преподавателях курса. Общий сервис изменения сроков должен использоваться новым модулем и существующими формами, чтобы не появились две политики дедлайнов. Миграции не изменяют существующие решения, оценки и связи заданий с программой.

Перед добавлением ограничений уникальности к существующим срокам необходимо проверить дубликаты и разрешить расхождения отдельным планом данных. Новые составные индексы покрывают календарь курса по дате, материалы по занятию и слою, идентичность ресурса, ссылки на урок и область аудита.

## Этапы реализации

### Этап 1 Основа и календарь

Добавить feature flag, модели, миграции, политику курса и страницу настроек. Реализовать недельные позиции, исключения, дополнительные даты, идемпотентную генерацию, очередь «Без даты» и предварительный расчёт изменений. Проверить существующие курсы без новых настроек: их поведение сохраняется.

Результат: преподаватель получает корректную сетку и может безопасно менять её без потери занятий.

### Этап 2 Программа и прямое планирование

Подключить встроенный провайдер CodingProjects, ленивое дерево программы, прямые ссылки, текстовые записи, пакет урока целиком и разделение на ступени. Реализовать переносы, порядок, скобки, клавиатурную альтернативу, автосохранение, конфликты и отмену.

Результат: содержание программы удобно распределяется по датам и нескольким занятиям без промежуточной сущности «активность».

### Этап 3 Общий каталог провайдеров

Зафиксировать контракт v1 и контрактные тесты. Реализовать реестр и общий HTTP адаптер, серверный поиск, страницы, кеш и состояния отказов. Добавить совместимые методы GeekExam и GeekBattle; подключить AI Code Battle после проверки его реализации контракта. Испытать на 10 000 материалов и медленных ответах.

Результат: материалы нового совместимого провайдера появляются в каталоге без изменения модели занятия и добавления специальных столбцов интерфейса.

### Этап 4 Дедлайны журнал и сводки

Объединить изменение сроков CodingProjects в общий сервис, добавить учебные сроки внешних ресурсов и календарные отметки. Реализовать подтверждение факта, ретроспективный ввод, сравнение с планом и снимки. Добавить сводку по провайдерам, детализацию уроков и календарные графики с раздельными шкалами баллов.

Результат: первая поставка планировщика отвечает на вопросы о будущем плане, фактической работе, материалах и сроках. Пилот проводится на одном выбранном курсе; развёртывание расширяется после проверки сохранности прежних данных.

### Этап 5 Учебные элементы и покрытие

Добавить справочник элементов, связи со ступенями, публичными компонентами ресурсов и вариантами проверок. Разметить один выбранный блок курса, проверить состояния «не размечено», «нет проверки», «запланировано», «проведено» и частичное прохождение. Массовая разметка всех курсов не является условием запуска календаря.

Результат: можно искать конкретные изученные идеи и умения, для которых ещё не подготовлена или не проведена письменная проверка.

### Этап 6 Ведомость отметок

Реализовать отдельный экран, периоды, колонки, параметры шкал, веса, ручные результаты и фиксацию итогов. Сначала подключить баллы CodingProjects и ручной ввод внешних результатов. Затем добавить чтение результатов провайдеров и импорт либо выгрузку для сверки с Google Sheets.

Результат: ведомость воспроизводит подтверждённые правила рабочего файла, включая вес 2, нижние границы 2 или 3, максимальную отметку 10, явный ноль, пустые ячейки и ручные олимпиады. Переход с Google Sheets выполняется после сверки выбранного периода.

На этом этапе определить публикацию плана для учеников, предварительный просмотр объявлений, отмену устаревших сообщений и учёт доставки. Использовать версии курса, историю и публичные темы ресурсов, подготовленные основным модулем.

В первую поставку не добавлять подключение чата, очереди сообщений, рассылку, регистрацию вебхуков или автоматизации отправки. Интерфейс планировщика до этого этапа сохраняет изменения преподавателя без обязательного шага публикации.

## Критерии приёмки

| ID | Проверка | Ожидаемый результат |
| --- | --- | --- |
| A01 | Два занятия в понедельник и два в четверг | Четыре места в полной неделе; длительности учитываются отдельно |
| A02 | Повторная генерация неизменённой сетки | Сохраняются ID, материалы и факты; дубликаты отсутствуют |
| A03 | Исключение даты с материалами | Причина видна; материалы доступны без даты либо перенесены явно |
| A04 | Пересчёт после подтверждённого занятия | Журнал и его дата не переписываются |
| A05 | Разделение урока на три занятия | Одна скобка с числом 3; неучебные дни не учитываются |
| A06 | Два урока в одном занятии | Одна карточка занятия и две корректные связи; материалы не дублируются |
| A07 | Урок целиком и затем выделение ступени | Атомарное разделение; двойного учёта одной ступени в занятии нет |
| A08 | Новый тип материала провайдера | Отображается общей карточкой по manifest без нового типа занятия |
| A09 | Каталог из 10 000 материалов | Серверный поиск, не более 50 карточек в ответе, страницы без полной выгрузки |
| A10 | Быстрый ввод нескольких запросов | Поздний ответ старого запроса не заменяет новый список |
| A11 | Перетаскивание с третьей страницы поиска | Привязка создана; запрос, страница и позиция каталога сохранены |
| A12 | Материал размещён на двух датах | Одна единица материала и два использования в детализации |
| A13 | Один ресурс связан с двумя уроками | Есть в обеих строках; общий итог курса не задваивается |
| A14 | Ошибка или удаление ресурса провайдера | История и сохранённая карточка остаются; ошибка не превращается в нулевой счётчик |
| A15 | Внешний тест связан с прошлой главой как `related` | Есть в сводке главы; скобка изучения не удлиняется |
| A16 | Срок задачи изменён в планировщике | Та же дата видна в существующем экране дедлайнов CodingProjects |
| A17 | Задача перенесена на другую дату занятия | Дедлайн не меняется; удаление привязки также не удаляет срок |
| A18 | Срок приходится на день без занятия | На календаре видна самостоятельная отметка срока |
| A19 | Дата прошла, журнал не заполнен | Отображается неподтверждённое проведение, а не автоматический факт |
| A20 | Журнал частично соответствует плану | Факт хранит выбранные материалы и заметку; исходный план доступен |
| A21 | Материал или запись другого курса в мутации | Сервер отклоняет запрос; одной роли преподавателя недостаточно |
| A22 | Два редактора и отмена старой операции | Конфликт версии отображается; чужое изменение не затирается |
| A23 | Повтор сетевого запроса с тем же `operation_id` | Возвращается первый результат без дублирования |
| A24 | Управление клавиатурой и узкий экран | Материалы добавляются и перемещаются без обязательного drag-and-drop |

Для этапа учебных элементов дополнительно проверяются различие нулевого покрытия и отсутствия разметки, разные варианты проверки и отсутствие произвольного распределения итоговых баллов вопроса по нескольким элементам.

Для ведомости дополнительно проверяются обе шкалы, порог максимальной отметки, округление половин, ограничение бонусных баллов, вес 2, отсутствие учитываемых отметок, пустая ячейка против явного нуля, сохранение ручной коррекции после обновления источника, неизменность закрытого периода и сопоставление учеников по устойчивому ID.

## Проверки и ввод в эксплуатацию

Модульные проверки охватывают календарь, группировку, уникальные счётчики, снимки и правила шкал. Проверки HTTP и БД охватывают доступ курса, транзакции, конфликт версий, идемпотентность, дедлайны и журнал. Контрактные проверки адаптеров используют одинаковые наборы с числовыми и UUID идентификаторами, несколькими типами, курсорами, ошибками доступа и недоступностью источника.

Браузерные сценарии проверяют добавление из каталога, урок целиком, разделение, перенос, отмену, поиск, переходы страниц, устаревшие ответы, работу с дедлайном и фиксацию факта. Проверка производительности проводится отдельно от функциональных тестов и не обращается к рабочим посылкам учеников.

Перед включением выполняются новые миграции, выбранные проверки PHPUnit, сборка Vite и браузерные сценарии. Сначала feature flag включается для одного курса. Выключение флага скрывает модуль и сохраняет данные; существующий курс продолжает работать. Первое включение не открывает уроки, не меняет оценки и не отправляет сообщения.
