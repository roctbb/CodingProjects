# Планировщик: запуск и устройство первой версии

Модуль открывается из меню курса «План занятий» по адресу `/insider/courses/{course_id}/planner`. Доступ разрешён администратору и преподавателям этого курса. Ведомость отметок, разметка смысловых единиц и бот остаются следующими этапами.

## Запуск

1. Применить миграции: `php artisan migrate`. Новая миграция создаёт таблицы `planner_*`; существующие программы и сроки курса не переносит и не переписывает.
2. Собрать клиент: `npm ci && npm run build`.
3. При кешировании конфигурации выполнить `php artisan config:cache` после изменения переменных окружения.
4. Открыть планировщик курса и задать период, часовой пояс и недельные позиции. Перед сохранением отображается предварительный расчёт.

`COURSE_PLANNER_ENABLED=false` отключает маршруты и пункт меню. Без новых таблиц страница показывает сообщение о необходимости миграции. Новые пакеты Composer/npm не требуются.

## Что доступно

Основной вид — неделя на доске. День содержит карточки занятий; выбор материалов открывается модальным диалогом с поиском, типами, провайдерами и курсорными страницами. Выбор нескольких материалов сохраняется между страницами, добавление выполняется одной атомарной командой. Уже добавленные материалы помечены и заблокированы. Обзор курса выбирается в компактном селекторе рядом с периодом; отдельного ряда подвкладок нет. Настройки расписания, провайдеры и история доступны в меню.

В каталоге программы есть селектор главы, включая «Все главы» и «Без главы» при наличии таких уроков. Для заполненного занятия выбирается единственная глава его материалов и связанных уроков. Для нового занятия используется глава из перехода со страницы курса; при прямом входе — глава текущего урока с учётом подгруппы, глава по умолчанию или первая глава программы. Ручной выбор, включая «Все главы», сохраняется до перезагрузки страницы и имеет приоритет при следующих открытиях окна. У внешних провайдеров селектор скрыт.

Поиск и страницы ограничены выбранной главой на сервере. Материалы идут по порядку глав, уроков, ступеней и задач программы. Смена главы возвращает к списку уроков, сохраняя выбранные материалы. Раскрываемый список выбранного позволяет проверить названия и убрать отдельные пункты перед добавлением; конфликт версии сохраняет этот выбор для повторной отправки. Фильтр не ограничивает календарь: занятие может включать материалы разных глав.

Планировщик использует общую палитру платформы: `config/branding.php` → параметры `BRAND_*` → CSS-переменные `--gc-*`. Основной, дополнительный и акцентный цвета продолжают настраиваться через этот механизм. Второстепенный текст и поверхности имеют нейтральные роли, которые не окрашиваются дополнительным цветом бренда. Состояния выделяются тонкими границами и мягкими оттенками настроенной палитры.

- Календарь с несколькими занятиями в день, исключениями диапазонов, дополнительными датами и разделом «Без даты». Пересчёт использует устойчивые ключи недельных позиций. Заполненные занятия с исключённых дат сохраняются без даты; занятия с журналом или закреплённой датой остаются на месте.
- Прямое добавление уроков, ступеней и задач программы, ресурсов внешних провайдеров и текстовых записей. Добавление через «+ Материал» и диалог выбора; перенос уже добавленных материалов выполняется на доске. Материалы можно переносить и упорядочивать через меню; перетаскивать можно и целое занятие.
- Разделение целого урока на сохранённый состав ступеней с распределением между двумя занятиями. Пересечение целого урока с его ступенями в одном занятии отклоняется и при добавлении, и при переносе.
- Каталог с серверным поиском, типами, дочерними материалами и страницами по 25 элементов, максимум 50 через API. Запоздавший результат поиска не заменяет новый. При добавлении материала страница каталога сохраняется.
- Единый список занятий без переключателя плана и факта. У прошедшего или завершившегося по расписанию занятия доступен комментарий о том, что успели. Он не подтверждает посещение, не создаёт SessionRecord и сохраняется на исходной дате при пересчёте расписания. Прошедшая дата сама не означает проведения занятия. Прежний API факта и его записи сохранены для совместимости.
- Снимки материалов и дедлайнов в журнале. Обновление плана из источника выполняется отдельной командой; факт оно не переписывает. При недоступности источника сохранённые карточки остаются доступны.
- Компактные подписи уроков с числом занятий и подсветкой связанных карточек, без дополнительной колонки скобок.
- Сводка уникальных материалов по провайдерам, детализация использований с переходом к дате, текущие дедлайны задач `X / Y` и отдельные внешние сроки. В настройках провайдеров можно отключить добавление материалов или скрыть столбец.
- Недельные графики материалов, дедлайнов и баллов. Единицы баллов разных источников не складываются. Дедлайны в календаре и сводке всегда текущие; карточки журнала показывают исторический срок.
- Отмена последнего изменения и история операций. Комментарий, добавление и перенос можно отменить общей историей; прежние команды факта сохраняют свои ограничения отмены. Конфликт редакций требует обновить состояние; повтор запроса с тем же ключом не создаёт дубликат. Отмена не перезаписывает срок, изменённый через существующий экран задачи.

Сроки задач CodingProjects записываются в существующий `TaskDeadline` через общий `CourseDeadlineService`, который также используют прежние экраны. Перенос или удаление привязки не меняет дедлайн. Во знаменатель покрытия входят только видимые задачи без звёздочки. Это показатель сроков, а не доказательство проверки тем тестами.

## Внешние провайдеры

Реестр находится в `config/course_planner.php`. Встроенный адаптер программы работает без сетевых запросов. Для внешнего провайдера нужны корневой URL и отдельный секрет интеграции; без них источник отображается как ненастроенный и не включается в сводку.

| CodingProjects | На стороне источника |
| --- | --- |
| `PLANNER_GEEKEXAM_URL`, `PLANNER_GEEKEXAM_SECRET` | GeekExam: `COURSE_PLANNER_SECRET`, аудитория `geekexam` |
| `PLANNER_GEEKBATTLE_URL`, `PLANNER_GEEKBATTLE_SECRET` | GeekCodeBattle: `COURSE_PLANNER_SECRET`, аудитория `geekbattle` |
| `PLANNER_AI_CODE_BATTLE_URL`, `PLANNER_AI_CODE_BATTLE_SECRET` | Совместимый API v1, аудитория `ai-code-battle`; адаптер источника поставляется отдельно |

Для каждой пары используется свой случайный секрет достаточной длины, минимум 32 байта. На стороне GeekExam и GeekCodeBattle добавлены отдельные маршруты чтения; их нужно развернуть вместе с новой конфигурацией. Автоматического подключения к рабочим серверам нет. Преподаватель должен уже существовать в источнике: в GeekExam его `id` соответствует ID CodingProjects, в GeekBattle используется `external_id`.

HTTP-адаптер обращается к следующим путям относительно URL:

- `GET /integrations/course-planner/v1/manifest`;
- `GET /integrations/course-planner/v1/resources?query=...&type=...&cursor=...&limit=25`;
- `GET /integrations/course-planner/v1/resources/detail?type=...&external_id=...`;
- `GET /integrations/course-planner/v1/resources/children?type=...&external_id=...` при объявленной возможности `children`.

Контракт manifest и карточек описан в [ТЗ](course-planner-spec.md). В первой версии `resolve` и `components` не вызываются. GeekExam отдаёт тесты; GeekBattle — соревнования, подборки и задания, а также содержимое подборок. У заданий GeekBattle нет отдельной страницы, поэтому `open_url=null`.

Сервер CodingProjects отправляет JWT HS256: `iss=codingprojects`, `aud=provider_key`, `purpose=course-planner`, `sub` — строковый ID преподавателя, `scope="catalog:read content:read"`, срок 60 секунд. Источник проверяет подпись, назначение, аудиторию, срок и собственную роль пользователя. Секреты не попадают в браузер. Карточки не содержат правильных ответов, конфигураций проверяющих программ, закрытых тестов, посылок или приглашений.

Каталог ограничен на сервере источника. GeekExam/GeekBattle используют курсор по ID, встроенный каталог — ограниченный SQL-запрос с курсором смещения. Кеш внешнего каталога живёт 60 секунд и разделён по пользователю, роли, курсу и фильтрам; при привязке доступ заново проверяется через detail без кеша. Таймаут соединения — 1 секунда, всего запроса — 5 секунд, редиректы отключены, размер ответа ограничен. Для нового совместимого провайдера достаточно записи в конфигурации.

## API интерфейса

Все пути ниже относительны `/insider/courses/{course_id}/planner/api`, используют текущую сессию CodingProjects и CSRF для POST:

| Метод | Путь |
| --- | --- |
| GET | `/state?from=YYYY-MM-DD&to=YYYY-MM-DD&layer=workspace\|plan\|fact` — диапазон до 93 дней, сводка всего курса |
| POST | `/calendar/preview` — предварительный расчёт расписания |
| GET | `/providers/{key}/resources` — каталог и manifest |
| GET | `/entries/{id}` — сохранённая карточка целиком, включая ступени урока |
| GET | `/summary/details?layer=plan&lesson_id=1&provider=codingprojects&page=1` — по 25 использований |
| POST | `/commands/{operation}` — изменение с `revision` и уникальным `operation_id` |

Команды: `configure`, `providers`, `add_exception`, `remove_exception`, `add_slot`, `add_session`, `move_session`, `update_session`, `attach`, `attach_many`, `comment`, `refresh_entry`, `split_lesson`, `relations`, `add_text`, `update_entry`, `delete_entry`, `move_entry`, `set_deadline`, `record`, `undo`. Параметры команд валидируются в сервисах. Успешный ответ содержит `revision`, `result`, `replayed`. Конфликт версии — HTTP 409. Перед повтором после неоднозначного сетевого сбоя клиент интеграции должен сохранить исходный `operation_id` и тело запроса.

Встроенный каталог принимает `chapter=ID` (только глава программы курса) и `chapter=0` для уроков без главы. Без параметра возвращаются все главы. Фильтр входит в подпись курсора; курсор другой главы отклоняется. `/state` дополнительно возвращает `chapters` и `course.catalog_chapter_id` для начального выбора.

Архитектура: контроллер/политика → `PlannerService` → `CalendarService`, `PlannerHistory`, `ProviderRegistry`; чтение и агрегаты — `PlannerReader`. Календарь, запись истории и доменные изменения выполняются в одной транзакции с блокировкой редакции курса. Локальные снимки общих карточек не являются источником полномочий.

## Проверка

```sh
vendor/bin/phpunit tests/Feature/CoursePlannerTest.php tests/Feature/CourseDeadlinesTest.php tests/Feature/LessonDeadlinesAndNotebookTest.php
npm run build
npm run ui:check -- --planner-only
```

Тест планировщика использует изолированную SQLite-базу. В нём есть сценарий каталога из 10 000 задач, проверки области курса, сохранности снимков, конфликтов и отмены. Миграция, смешанный каталог, пересчёт, разделение/отмена, дедлайны и журнал дополнительно проверены на отдельной PostgreSQL-базе; основные сценарии интерфейса — в браузере на изолированных данных.

Дальнейшее развитие по ТЗ: редактор периодов действия недельных правил (API уже поддерживает их), пакетное разрешение ссылок и фоновая маркировка изменений источника, дополнительные срезы графиков. Разметка учебных элементов, ведомость и бот реализуются отдельными этапами.


## Совместимость объединённого представления

Клиент читает `layer=workspace`, команды посылает с `unified=true`. Повтор одной ссылки плана/факта показывается один раз, приоритет у плана. Существующие снимки и записи физически не удаляются миграцией. Защита добавления, удаления и переноса учитывает оба прежних слоя. Идентичность ссылки: `(provider_key, resource_type, external_id)` внутри одного занятия; в другом занятии тот же материал допустим.

`attach_many` принимает `session_id` и `items` (1–50 ссылок, каждое содержит `provider_key`, `resource_type`, `external_id`), проверяет доступ ко всем элементам и откатывает пакет при любой ошибке. `comment` принимает `session_id` и `comment` (до 10 000 знаков, null очищает). Срок завершения вычисляется в часовом поясе курса, с датой, временем начала и длительностью. Новая миграция `2026_11_11_180000_add_comment_to_planner_sessions.php` добавляет nullable-поле; страница проверяет его наличие до запуска нового интерфейса.
