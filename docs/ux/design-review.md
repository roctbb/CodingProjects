# Проход по UX-графу и макетам

Сначала проверяется путь пользователя, затем композиция экрана, затем визуальные детали. Изменение одного экрана должно сохранять понятный вход и возврат на соседние узлы. Нельзя улучшать отдельную карточку ценой потери разделения всей страницы.

## Порядок

| Очередь | Путь | Что согласовать в макетах |
| --- | --- | --- |
| 1 | Курсы → курс → ступень → отправка → обратная связь | Главная иерархия, продолжение обучения, карточки самостоятельных блоков, навигация задач |
| 2 | Очередь → проверка → достижение → профиль | Рабочее место преподавателя, попытки, контекст ученика, заметность результата |
| 3 | Курс → планировщик → каталог → занятие → факт → обзор | Перенос материалов, поиск и страницы, дедлайны, связь уроков и занятий |
| 4 | Сообщество → профиль → комната / достижения / GC | Личное и публичное, покупки предметов, ожидание генерации, пустые разделы |
| 5 | Магазин → товар / цифровой предмет / аукцион → заказ | Цена и баланс, подтверждение, выдача, архив и история |
| 6 | Создание курса → глава → урок → ступень → задача | Один набор форм, Markdown/Notebook, раскрытие необязательных настроек |
| 7 | Курс → отчёт / журнал XP / дедлайны / блокировки | Читаемость таблиц, фильтры, переход из результата к конкретному решению |
| 8 | Вход → регистрация / SSO → подтверждение / восстановление | Основное действие, ошибки, возврат, приглашение на курс |
| 9 | Настройки ИИ / магазина / Telegram / комнаты | Единый шаблон настроек, скрытые секреты, результат сохранения и сброса |

## Карточки и общие компоненты

На экране остаются видимые границы самостоятельных сущностей. В курсе это карточки уроков; в ступени — задание, обратная связь и отправка; в профиле — личная информация, комната и достижения. Внутри них текст, строки, разделители, метки и поля не получают дополнительную декоративную рамку без самостоятельного смысла.

Из макетов выделяются общие шаблоны: заголовок страницы, шапка секции, карточка объекта, строка списка, вкладки, форма, таблица, рабочее место проверки, диалог и обратная связь. При переносе это компоненты и токены, а не отдельный CSS-файл для каждого экрана. Палитра берётся из существующего брендинга. В макете основной цвет `#397698`, акцент `#FFA117`, дополнительный `#EACF72`; это иллюстрация текущей темы, а не её жёсткое ограничение.

Для каждого экрана в `system-map.json` перечислены состояния проверки. Общий минимум: заполнено / пусто, ожидание / ошибка / успех, отсутствие права, возврат и сохранение контекста, длинный текст, мобильная ширина. Различия ролей проверяются на одном типе экрана, а не оформляются несвязанными вариантами дизайна.

## Наблюдения по текущему коду

Это вопросы для проектирования и проверки, а не утверждения о визуально подтверждённых дефектах на всех страницах.

1. **Термины.** В обучении используются «урок», «ступень» и «этап». На макетах закрепить «Курс → глава → урок → ступень → задача». «Занятие» относится к календарю. Источник: `steps/partials/nav.blade.php`.
2. **Заголовок и карточка.** `gc-page-header` встречается как самостоятельный заголовок и вместе с `gc-card`. Их отступы нельзя менять одним глобальным обнулением. Источник: `courses/deadlines.blade.php`.
3. **Два входа в заказы.** Вкладка магазина и отдельный экран заказов должны использовать одинаковую таблицу, статусы и действия. Источник: `market/partials/orders_table.blade.php`.
4. **Формы.** Прежний слой CSS содержит локальные оформления форм и редакторов. Переносить их в общие шаблоны после проверки макетов; избегать лишних обёрток редактора.
5. **Навигация на мобильном.** Меню профиля содержит меньше пунктов, чем настольное меню ресурсов. При проектировании предусмотреть доступ к тем же нужным разделам. Источник: `layouts/left-menu.blade.php`.
6. **Граница этапа.** Итоговая ведомость и новый бот сопровождения курса остаются отложенными. Имеющиеся XP и Telegram-настройки отображаются как существующие функции.

## Фиксация результата

Проход по экрану записывается в его узле: проверенные роль и состояние, найденная проблема, конкретное решение, макет и затем подтверждение после переноса. Проверка кода, визуальная проверка и готовность рабочего экрана — отдельные отметки. Скриншоты предыдущего прохода не подменяют проверку нового макета.
