Работа следует этапам: фактический граф → сравнение макетов → перенос выбранного дизайна → повторная проверка. Согласованные концепции перенесены в профиль, сообщество, магазин, личные настройки и рабочие разделы курса. Ориентир — макет плана занятий из обсуждения: спокойная типографика, ясные самостоятельные блоки, компактные действия и небольшие цветовые акценты. Основные карточки остаются; убирается прежде всего третий декоративный уровень вложенности.

## Состав

- `system-map.json` — редактируемый источник: экраны, роли сценариев, состояния, переходы, источники и предполагаемый тип макета.
- `graph.html` — интерактивный просмотр, собранный из `graph.template.html` и данных карты.
- [screens.md](screens.md) — полный каталог экранов и состояний с маршрутами, переходами и исходниками.
- [routes.md](routes.md), `routes.json`, `coverage.json` — фактическое покрытие маршрутов; обновляются из Laravel.
- `access.mmd`, `courses.mmd`, `authoring.mmd`, `review.mmd`, `planner.mmd`, `people.mmd`, `market.mmd`, `admin.mmd`, `shell.mmd`, `external.mmd` — подробные Mermaid-графы по разделам, включая переходы наружу.
- [design-review.md](design-review.md) — последовательность работы с экранами, критерии и обнаруженные вопросы.
- [validation.md](validation.md) — границы и результаты проверки карты и макетов.
- `prototypes.html` — первый набор из семи связанных макетов: курсы, курс, ступень, профиль, сообщество, магазин, личные настройки. Его элементы не отправляют запросы в рабочую систему.

Граф не сводится к URL: настройка рамки, просмотр кубка, действия с решением, формы планировщика и генерация персонажа происходят внутри экранов. Создание задания теперь имеет самостоятельную страницу с общей формой редактирования. API, скачивание, callback, media и действия учитываются отдельно. Например, GET покупки или изменения порядка — действие, а не новая страница. `/insider/testmail` — техническая операция, она не открывается при UX-проверках.

Роли в узлах обозначают пользовательский сценарий. Они не заменяют middleware, policy или проверки контроллера. В `routes.md` приведён фактический middleware каждого маршрута; условия доступа, влияющие на UX, отдельно записаны в узлах. Внешние GeekPaste, GeekExam, GeekBattle, AI Code Battle, Storage, Arena, Силаэдр и Telegram показаны как границы: их внутренние экраны не приписываются CodingProjects.

Список страниц получен из маршрутов и возвращаемых views. Переиспользуемые компоненты, email-шаблоны и layouts не считаются отдельными экранами. `captcha.blade.php` не имеет отдельного зарегистрированного экранного маршрута. Существующие журнал XP и Telegram-привязка не означают реализацию отложенных итоговой ведомости и бота сопровождения курса.

## Обновление

```sh
npm run ux:build
npm run ux:check
```

Первая команда обновляет производные файлы. Вторая сверяет карту с текущим `route:list`: новый маршрут без владельца, пропавший исходник, неизвестный узел и устаревший снимок приводят к ошибке. Команды не выполняют действия пользователей и не посещают URL.

Обновлять нужно `system-map.json` и шаблоны просмотра/макетов. Генерируемые файлы не правятся вручную. Для каждого нового маршрута указывается владелец и тип; для нового экрана — задача пользователя, роли, состояния, источники и переходы.

Статусы различаются: `mapped` — изучен код; `baseline` — был предыдущий визуальный проход; `draft` в дизайне — есть предлагаемый макет; `implemented` — выбранный макет перенесён в рабочие шаблоны. Конкретные проверки перечислены отдельно в отчёте о переносе. Навигация первого макета ограничена семью показанными экранами; это не предложение удалять остальные разделы приложения. Иллюстрация комнаты схематичная и предназначена для оценки композиции.

Ни один из этих статусов сам по себе не означает одобрение дизайна или завершённую проверку всех состояний.

Формы создания и редактирования курсов, глав, уроков, ступеней и заданий — [итерация 14](ui-round-14.md): общие открытые секции, безопасный предпросмотр материала, явный выбор проверки и сохранение черновика при ошибках.
