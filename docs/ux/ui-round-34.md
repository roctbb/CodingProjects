# Удаление на PostgreSQL и проверка уведомления преподавателю

Исправлена ошибка очистки XP-уведомлений: `reward_notices.source_key` — строка, а `code_execution_runs.id` — UUID. PostgreSQL не сравнивает эти типы без преобразования; подзапрос теперь явно приводит ID проверки к тексту. В SQLite исходный запрос не выдавал ошибки, поэтому дополнительно проверено планирование DELETE на PostgreSQL и полное удаление в откатываемой транзакции.

`scripts/integration/solution-removal-postgres.php` требует соединение PostgreSQL в режиме чтения и выполняет только EXPLAIN, без удаления. Дополнительный `solution-removal-postgres-rollback.php` требует явный `ROLLBACK_SUBMISSION_AUDIT=1`: он проверяет удаление завершённой сдачи, всегда откатывает транзакцию и сравнивает исходные записи, начисления, достижения и прогресс. Очередь и уведомления подменены; внешние HTTP-запросы запрещены. Данные не сохраняются, хотя PostgreSQL может пропустить использованные в тесте значения sequence.

Уведомление преподавателю о наступлении каждого рубежа дедлайна предусмотрено в Telegram. Для этого у преподавателя должен быть привязан Telegram, а уведомления преподавателям в курсе — включены. Диспетчер запускается каждую минуту, отправитель работает в очереди `notifications`. Фактическое время отправки зависит от запуска диспетчера и обработки очереди.

Добавлена проверка точной границы: за секунду до срока уведомления `reached` нет, на границе оно ставится в очередь преподавателю, повторная обработка не дублирует отправку. Telegram в тесте подменён. Серверное расписание, состояние очереди и журнал доставок проверены отдельно в режиме чтения.
