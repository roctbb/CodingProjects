# Сдача и проверка внутри Coding Projects — проект UX

Утверждён вариант «В уроке». Основной сценарий — загрузить готовую работу
или вставить код из внешнего редактора. Редактор внутри системы дополнительный.
Интерфейс подключён к серверным API Coding Projects и GeekExam.

До макетов составлен [граф действий](code-submissions-ux.mmd).

## Общие решения для вариантов

- Сдача находится в текущем уроке, сохраняет контекст задачи и программы.
- Условие, рабочий черновик и неизменяемая отправленная попытка различимы.
- Ученику доступны только разрешённые способы сдачи. Добавление файлов
  работает и для текста, и для кода; один файл и проект используют один редактор.
- Состояние сохранения видно рядом с редактором. При конфликте не затирать
  локальный текст; при уходе с несохранённым черновиком предупредить.
- Отправка замораживает работу. Новое редактирование не меняет проверяемый код.
- Ход проверки приходит по WebSocket. После переподключения восстанавливать
  последнее состояние; ошибку соединения отличать от ошибки программы.
- Тесты сначала показываются компактным списком вердиктов. Открытые или
  купленные раскрываются до ввода, эталона, фактического вывода и ошибки.
- Покупка скрытого теста требует подтверждения с конкретной ценой и балансом.
  До подтверждения скрытые поля отсутствуют, повторного списания нет.
- Большие данные скачиваются. Не вставлять мегабайты текста в страницу.
- История сохраняет исходники, файлы, коммит, результаты и настройки запусков.
- Учителю показываются все тесты и закрытые критерии. Ученику эти поля
  не выдаются. Анализ авторства — отдельный рекомендательный блок без автоштрафа.
- Перепроверка сохраняет прежнюю оценку до нового результата.
- На телефоне форма и результаты остаются в одной колонке; длинные исходники
  и тесты раскрываются по запросу.

## Варианты для выбора

| Вариант | Компоновка | Когда удобен |
|---|---|---|
| В уроке | Условие сверху, редактор ниже, результат под ним | Выбран пользователем: основной сценарий сдачи готовой работы |
| Рабочее место | Условие слева, редактор и тесты справа, компактная история | Регулярное программирование, работа с условием и кодом одновременно |
| По шагам | Условие → решение → проверка, отдельный экран отправленной попытки | Начинающие ученики, разные форматы заданий, пошаговый сценарий |

Выбор: «В уроке» на компьютере и телефоне. Условие → загрузка файлов или
вставка кода → отправленная версия и результат → история. Палитра, навигация
и общие компоненты соответствуют существующему UI B+.

## Учитель

Редактор: «Условие» / «Ответ и проверка» / «Материалы». Тип проверки и формат
ответа независимы. Закрытый блок отмечен «Видно только преподавателям».
Для теста есть ввод, ожидаемый вывод, публичность и загрузка большого файла.
Материалы различаются на доступные ученику, шаблоны, ресурсы исполнения и
приватные материалы ИИ. Перед сохранением доступен предпросмотр ученика.

Просмотр работы: существующая очередь и выбор ученика; рядом исходники,
полный отчёт, ручная оценка или перепроверка. Массовая перепроверка применяется
к последней работе каждого ученика; выбор версии настроек обязателен и явен.

## Границы макетов

Демонстрационные баллы, имена, баланс и содержимое тестов вымышлены.
Кнопки в макетах меняют только локальное состояние. Реальные монеты,
сдачи, оценки и публикация задачи не затрагиваются.

## Получение наград

Подтверждённая оценка → реальный прирост суммарного XP → повышение звания →
достижение, если опубликовано → начисления GC → полное выполнение задачи.
Карточки последовательно появляются поверх урока, не блокируют форму и имеют
кнопку закрытия. Счётчик XP доходит от прежнего значения до нового; звание и
монеты получают отдельную короткую анимацию. При уменьшенной анимации движение
и частицы отключаются.

Событие создаётся в транзакции с наградой. Повторные коллбэки, перепроверка без
прироста и обновление страницы не начисляют и не показывают ту же награду ещё
раз. Получение в нескольких вкладках сериализуется сервером. Неуспешная сдача
не создаёт поздравления. Достижение может прийти позже основной оценки.
