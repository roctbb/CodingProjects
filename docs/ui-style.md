# Архитектура и правила интерфейса

## Состояние и направление

В проекте современная сборка Vite, Bootstrap 5.3, Sass и CSS custom properties. Они позволяют менять палитру без пересборки. Проблемой был каскад: почти 10 тысяч строк в `app.scss`, отдельный CSS планировщика и несколько сотен строк правил внутри Blade-шаблона брендинга. Компоненты местами имели собственные цвета, тени и оформление в зависимости от страницы. Наличие переменных само по себе не обеспечивало единого интерфейса.

Теперь у интерфейса одна точка входа `resources/assets/sass/app.scss` и один результат `public/build/css/app.css`. Sass-модули разделены по ответственности, а не по страницам:

| Модуль | Ответственность |
| --- | --- |
| `_vendor.scss` | Bootstrap, шрифты и CSS библиотек; настройки Sass для Bootstrap |
| `_tokens.scss` | Цветовые роли, поверхности, типографика, интервалы, размеры, радиусы и тени |
| `_base.scss` | Общие правила текста, таблиц, полей, кнопок и других базовых элементов |
| `_legacy.scss` | Существующие схемы экранов и прежние исключения, временный слой совместимости |
| `_components.scss` | Единое оформление компонентов и связь с палитрой; загружается последним |

Собственные модули подключаются через `@use`. Устаревающий Sass `@import` остаётся внутри интеграции Bootstrap: это ограничение используемой библиотеки. Переписывать Bootstrap ради синтаксиса не требуется. CSS Layers пока не вводятся: смешивание слоёв с прежними правилами без слоёв изменило бы их приоритет.

`layouts/partials/brand-theme.blade.php` публикует **только значения CSS-переменных**. В нём нет правил для кнопок, вкладок или страниц. Планировщик использует общий пакет CSS; его JavaScript больше не импортирует отдельный файл оформления. `notebook.css` остаётся техническим оформлением вывода Jupyter, а не второй системой дизайна сайта.

Миграция прежних стилей не завершена: `_legacy.scss` пока большой, содержит локальные селекторы и буквальные цвета. Перенос этого кода сохраняет совместимость; он не означает, что весь старый код стал современной системой компонентов. При изменении экрана повторяющиеся правила нужно переносить в общий компонент и удалять их прежние определения. Не добавлять новые переопределения в конец legacy.

## Палитра и токены

Источник настроенных цветов — `config/branding.php`, который читает `BRAND_*` из окружения. `App\Support\Branding` проверяет значения, формирует палитры и контрастный текст кнопок. Параметры окружения могут поступать из YAML конфигурации развёртывания; отдельного YAML-парсера палитры в приложении нет.

Цепочка применения: конфигурация → Branding → переменные палитры → смысловые роли → компоненты.

| Роль | Применение |
| --- | --- |
| `--gc-primary`, `--gc-primary-hover` | Основное действие, ссылки |
| `--gc-accent` | Награды, монеты, праздничные детали |
| `--gc-control-surface`, `--gc-control-border` | Белая поверхность поля и заметная нейтральная рамка |
| `--gc-selected-surface`, `--gc-hover-surface` | Разные состояния выбора и наведения |
| `--gc-focus-color` | Видимый клавиатурный фокус |
| `--gc-completion` | Прогресс и выполнение; по умолчанию основной цвет |
| `--gc-reward-bg` | Небольшие праздничные и наградные детали |
| `--gc-reward-emphasis`, `--gc-reward-border` | Более заметная акцентная метка и её граница: текущий урок, скидка, поздравление; обычный текст остаётся контрастным |
| `--gc-project-track`, `--gc-project-spot` | Маршрут глав курса и точечный акцент выбранной главы, иконок заголовка и текущего дня; оттенки вычисляются из палитры темы |
| `--gc-success`, `--gc-warning`, `--gc-danger` | Сообщения о результате, предупреждении и ошибке |
| `--gc-pending-bg`, `--gc-pending-ink` | Спокойное ожидание проверки в журнале, отчёте и открытой работе; предупреждения используют отдельную роль |
| `--gc-background`, `--gc-surface`, `--gc-surface-variant` | Фон страницы, самостоятельный блок, вспомогательная поверхность |
| `--gc-on-surface`, `--gc-on-surface-muted`, `--gc-border` | Текст, пояснения, разделители |
| `--gc-panel-border`, `--gc-control-border` | Мягкая граница самостоятельной панели и более заметная рамка поля |
| `--gc-backdrop` | Общее затемнение под диалогом и мобильной панелью; в тёмном отображении не превращается в белую завесу |
| `--gc-space-*`, `--gc-radius-*`, `--gc-control-height*` | Интервалы и геометрия |

Цвет бренда не прописывается в компоненте через HEX/RGB. Нужно выбрать смысловую переменную. Допустимы `color-mix()` с токенами для слабых заливок. Основной прогресс не становится зелёным при достижении процента; Bootstrap не задаёт отдельную палитру для обычных действий.

Светлый фон нейтральный `#eef1f5`, панели белые, вспомогательная поверхность `#f3f5f9`. Основной текст `#1d2b40`, второстепенный `#56647a`, границы `#d5deea`. Фон не окрашивается вторичным или акцентным цветом бренда. В текущей локальной теме основной цвет изменён с приглушённого `#397698` на насыщенный `#345bd1`; оранжевый `#ffa117` сохранён. Цвета по-прежнему задаются настройками `BRAND_*`, компоненты используют токены. Оранжевый виден на наградах, монетах и небольших праздничных деталях; крупные области не окрашиваются целиком. Сохранены тёмная палитра и `BRAND_DARK_*`. Изображения, стикеры, комнаты и награды сохраняют собственные цвета как учебный контент.

## Типографика и размеры

Стилистическая отправная точка — «Тихая аркада» из AI Game Engine. CodingProjects сохраняет собственную настроенную палитру.

### Референсы и границы заимствования

Арена остаётся основным визуальным ориентиром: белые самостоятельные поверхности, насыщенное основное действие, ясные заголовки и компактная геометрия. Остальные референсы используются для отдельных задач, а не как повод смешивать несколько палитр:

- **Discord** — [настольный интерфейс](https://discord.com/blog/player-release-q12025) и [You Bar, 2026](https://discord.com/blog/you-bar): текущий контекст остаётся узнаваемым, личность участника видна через аватар и оформление, основные действия легко доступны. В CodingProjects это быстрые ссылки на курсы для обеих ролей, проверка в нижней навигации преподавателя и плотная галерея с заметными рамками. Палитра и многоколонная структура Discord целиком не переносятся.
- [Linear — A calmer interface for a product in motion](https://linear.app/now/behind-the-latest-design-refresh): содержание важнее обрамления, стабильная навигация, компактные вкладки, мягкие границы и работа с настроенной темой.
- [Google Classroom — обновлённая главная](https://support.google.com/edu/classroom/answer/17231999?hl=en): различать приоритеты преподавателя и ученика. Для CodingProjects это очередь проверки у преподавателя, текущая работа и сроки у ученика.
- [GitHub Projects — представления](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project): доска, таблица и фильтры как рабочие способы смотреть на одни данные. В планировщике не требуется копировать многоуровневую навигацию инструмента целиком.
- [Khan Academy — student dashboard](https://support.khanacademy.org/hc/en-us/articles/46935588089997-How-do-I-use-the-student-dashboard-in-Khan-Academy): понятное следующее действие и видимый учебный прогресс. В CodingProjects роль живых акцентов также выполняют купленные рамки, комнаты, награды и фотографии ребят.

Подробный разбор и результаты применения — [итерация 8](ux/ui-round-8.md).

Это проектная интерпретация референсов, а не обещание воспроизвести их функции. Рабочие таблицы остаются плотными; социальные экраны сохраняют заметную личность участника. Наведение даёт слабую подсветку поверхности или ссылки, а выбранное состояние — более устойчивый акцент. Крупная синяя заливка карточки при наведении не используется.

- Golos Text 400/500/600 поставляется локально через npm, без внешнего сервиса шрифтов.
- Основной интерфейс 14/20, таблицы 13/20, подписи 12. Заголовок страницы 28 на широком экране и 24 на телефоне; секции и названия карточек 16. Заголовки используют общий `--gc-font-weight-heading: 600`; подписи, строки и навигация сохраняют 400/500.
- Интервалы 4/8/12/16/24/32; радиусы карточки 10, поля и кнопки 6, диалога 12 пикселей.
- Кнопки и поля 36, компактные 32; на сенсорном устройстве минимум 44 пикселя.
- На сенсорном устройстве нативные поля используют текст не меньше 16 px, чтобы фокус в мобильном Safari не увеличивал страницу. Компактный текст остальных элементов сохраняется.
- Основные карточки имеют тонкую границу. Выраженные тени предназначены для всплывающих элементов.

## Структура страницы и карточки

**Самостоятельные блоки сохраняют карточки.** Урок, задание, крупная секция профиля или боковая панель должны явно отделяться от соседних блоков. Плоская страница, в которой всё разделено только пробелами, ухудшает читаемость.

Внутри карточки используются заголовки, строки, списки, отступы и разделители. Не нужно оборачивать каждый показатель и каждую строку в свою карточку. Второй уровень допустим, если это отдельный интерактивный объект; третий уровень декоративных карточек не используется. Поля ввода, метки и учебные изображения не считаются декоративной вложенностью.

Общие примитивы:

| Класс | Назначение |
| --- | --- |
| `<x-gc-page-header>`, `.gc-page-header`, `.gc-page-masthead` | Компактная белая шапка с заголовком и действиями; общая поверхность для связанных вкладок и поиска. Внутри визитки — `:embedded="true"`, без дополнительной рамки |
| `<x-gc-panel>`, `.gc-panel-heading`, `.gc-panel-body` | Самостоятельная панель с тихим заголовком без обязательной черты |
| `.gc-entry`, `.gc-rows`, `.gc-row` | Строки участников, достижений, курсов, покупок и операций |
| `.gc-toolbar`, `.gc-filters`, `.gc-filter` | Поиск и фильтры без дополнительной карточки |
| `.gc-catalog-grid`, `.gc-catalog-card` | Адаптивный каталог по доступной ширине |
| `.gc-person-grid`, `.gc-person-card` | Плотная галерея: портрет слева на компьютере, сверху на телефоне; видимые рамки, полные имена и звания |
| `<x-gc-roster>` | Один список слева на компьютере и в панели выбора на телефоне: очередь проверки и ученики отчёта |
| `<x-gc-workspace-toolbar>`, `.gc-workspace-field` | Общая поверхность рабочих фильтров и действий, одинаковые подписи полей; программа, план, журнал и отчёт |
| `.gc-card`, `.gc-section` | Рамка самостоятельного блока; section допускает шапку и тело |
| `.gc-section-header` | Заголовок внутри секции с общими отступами и без декоративной линии |
| `.gc-list`, `.gc-list-row` | Список с одной внешней рамкой и строками внутри |
| `.gc-metrics`, `.gc-metric` | Сетка кратких показателей, каждый показатель — самостоятельный блок |
| `.gc-auto-columns` | Колонки, перестраивающиеся по ширине самого блока, включая положение рядом с сайдбаром |
| `.gc-page-tabs` | Общие компактные вкладки с заливкой основным цветом и контрастным текстом выбранного пункта; горизонтальная прокрутка |

Например, блок заданий строится как `.gc-section` → заголовок и содержимое. Список прогресса учеников внутри него состоит из строк. Оформление кнопки определяется её ролью `btn-primary`/`btn-outline-secondary`, а не селектором `.course-page .btn`.

Примитивы применены к списку курсов, странице курса, ступени и профилю. Дни рождения — часть боковой панели с лёгкими строками и небольшими метками дат. Пункты действий преподавателя собраны в меню с текстовыми названиями. Профиль, сообщество, магазин и личные настройки используют общие заголовки, панели и строки; Telegram находится в аккаунте, покупки и история GC — в магазине. Идентификаторы вкладок, формы, права и данные JavaScript сохранены.

## Правила следующих изменений

1. Сначала использовать существующий общий компонент. Если поведение повторяется, расширить компонент для всех экранов.
2. Новые токены добавлять в `_tokens.scss`, новое общее оформление — в `_components.scss`. Локальному селектору допустимо задавать компоновку, но не новую палитру кнопок, вкладок и карточек.
3. Не создавать `profile.css`, `course.css` и аналогичные пакеты. Не помещать оформление компонентов в Blade или JavaScript. Динамические значения вроде ширины прогресса допустимы.
4. Удалять старое правило при переносе ответственности. Не решать конфликт ещё одним более специфичным селектором или `!important`.
5. Проверять самостоятельность блоков и вложенность, затем мобильную ширину, пользовательскую палитру и оба режима отображения.

Проверки: `npm run styles:check`, `npm run build`, `php artisan test --compact`. Проверка стилей запрещает буквальные цвета в общих компонентах и CSS-правила в шаблоне палитры; legacy и оформление Jupyter явно исключены до их отдельной миграции.

Геометрия обычных полей, подписей, кнопок и таблиц задаётся в `_base.scss`; оформление выбранных состояний и компонентов — в `_components.scss`. Повторное объявление перенесённых базовых примитивов в legacy запрещает `styles:check`. Общая таблица использует текст 13/20, нейтральную шапку и отступы ячеек 12 px. Не переопределять эти параметры отдельно для магазина, журнала и настроек.

Bootstrap-модали и нативные диалоги используют одну поверхность темы, радиус 12 px и мягкую тень. Шапка и панель действий не отделяются декоративными линиями. Отступы 24 px на компьютере и 16 px на телефоне; внутри полей действуют обычные интервалы. В шаблоне не нужны `border-0`, `rounded-3` и `shadow-sm` для оформления оболочки модали: её внешний вид принадлежит общему компоненту.

## Планировщик

По умолчанию открывается неделя на доске: день — колонка, занятие — самостоятельная карточка, материалы — строки без вложенных карточек. Недели переключаются стрелками, «Обзор курса» выбирается в том же компактном списке рядом с периодом. Второго ряда вкладок и переключателя «План / Факт» нет.

Каталог открывается нативным модальным диалогом из «+ Материал» конкретного занятия. Провайдер, серверный поиск, тип, дочерние материалы и курсорная пагинация остаются внутри диалога. Можно выбрать несколько материалов на разных страницах и добавить одной атомарной командой. Уже прикреплённые материалы отмечены и недоступны для повторного выбора. Идентичность — провайдер + тип + внешний ID; защита повторов действует и на сервере. Escape и закрытие возвращают фокус, список ограничен по высоте.

Прошедшее занятие получает действие «Как прошло занятие»: обычный текстовый комментарий рядом с тем же списком материалов. Прошедшая дата сама не подтверждает проведение. Комментарий не создаёт отдельный слой факта; пересчёт расписания сохраняет его на исходной дате. Старые записи и API факта совместимы с объединённым чтением. Перенос материалов и занятий остаётся на доске и в контекстных меню.

## Ежедневная сводка и навигация

На главной странице курсов важны личный баланс, опыт и дни рождения. Аватар заполняет верх личной карточки и ведёт в профиль. XP объединён с рангом и шкалой, числовое значение одно. Активные и пройденные курсы ученика используют одну сетку. Именинники сгруппированы по датам: сегодня и следующие шесть дней, без ограничения числа людей и без скрытых групп. Все имена показаны одинаковыми компактными строками, без аватаров и плашек пользовательских званий. Панель остаётся белой; сегодня выделено подписью. Праздничная иконка использует чистый акцент темы, рядом немного статичных декоративных точек; коричневой смеси с текстом и жёлтой фоновой плашки нет. Общие примитивы: `.gc-summary-line`, `.gc-name-list`, `.gc-date-group`, `.gc-occasion-heading`.

Крупное число и компактный график в шапке «Моих курсов» ведут в «Пульс». В шапке преподавателя для сводки используется средний слот `<x-gc-page-header>`. При отсутствии событий рядом с нулём выводится пояснение «Пока нет активности».

В карточках курсов нет повторяющихся стрелок: ссылка занимает карточку целиком, заголовок и граница реагируют на наведение и фокус. Название крупнее пояснения, иконка отображается общим `<x-gc-course-icon>`. В каталоге цена стоит слева, компактное действие справа; общий `<x-gc-purchase-footer>` одинаков для физических и цифровых товаров. Мобильные кнопки сохраняют область нажатия не меньше 44 пикселей.

## Иконки курсов и рабочая область

`<x-gc-course-icon>` отображает один из 16 контурных SVG Lucide Static 1.72.0, включённых в `resources/icons/courses` вместе с лицензией. Они наследуют основной цвет темы, не требуют внешнего запроса или клиентской библиотеки. `CourseIcons` хранит закрытый каталог и автовыбор по названию. `courses.icon_key` содержит выбранный ключ либо `NULL` для автовыбора. Существующие курсы получают подходящую иконку сразу, без перезаписи данных; ручной выбор доступен при создании и редактировании через общий компонент с нативными радиокнопками. Каталог свёрнут в `<details>`: сначала видны текущая иконка и действие «Изменить». Постеры для комнат продолжают генерироваться отдельно; растровый постер не используется как маленькая интерфейсная иконка.

На странице курса уроки сохраняют белую поверхность и при наведении; выделяются граница и ссылка. Вертикальной декоративной направляющей и отдельной колонки кружков нет, номер находится внутри карточки. Выпадающее меню использует `--gc-surface`, а не фон страницы. Клавиатурный фокус показывает действия урока.

Для глав применяется общий `<x-gc-chapter-timeline>`: одна подпись текущей главы, счётчик позиции и точки. Кнопка текущего названия открывает большой список с поиском; её область нажатия отделена от таймлайна. Цвет выбранной позиции — основной цвет темы, без акцентного подчёркивания. Нативный range имеет область касания 44 px; перетаскивание показывает предварительный выбор, отпускание переводит на главу. Вертикальный жест прокручивает страницу. Клавиатура поддерживает стрелки, Home/End и отмену Escape. Доступность повторяет `ProgramChapter::isAvailableForUser`, включая персональный ранний доступ; преподаватель своего курса и администратор видят все главы. Закрытая точка возвращает текущую позицию и пояснение. Для страницы без JavaScript предусмотрена обычная GET-форма.

## Приоритет информации об участнике

Шапка профиля использует общий заголовок с портретом и дополнительной сводкой: аватар 96 px с персональной рамкой, имя, ранг, купленное звание и прогресс к следующему рангу. На телефоне портрет 80 px; короткое имя остаётся рядом, длинное располагается под портретом на полную ширину. Ранг и прогресс следуют за именем. Левая часть единой визитки содержит личность, открытые контакты и биографию, правая — комнату без дополнительной вложенной карточки. Школа и дата рождения относятся к «О себе» внутри визитки. Видимость почты и скрытой даты рождения сохранена; корректные Telegram и HTTP(S)-ссылки доступны по нажатию.

Названия курсов в профиле используют спокойный общий `.gc-quiet-link`: первые три видны сразу, остальные раскрываются. Обучение, непустые достижения и наклейки идут последовательными разделами ниже визитки. Коллекция наклеек показана сразу владельцу и посетителю. В сообществе заметны аватар, ранг и купленное звание; прогресс-бара следующего ранга нет. XP остаётся второстепенной подписью. Оформление этих элементов остаётся в общих компонентах, отдельного CSS профиля или сообщества нет.

Активный пункт меню обозначен мягкой заливкой, цветом иконки и весом текста 500; боковая цветная скобка не применяется. Выбранная вкладка залита основным цветом с контрастным текстом и счётчиком, без подчёркивания. Невыбранные вкладки прозрачные. В ленте персональные рамки относятся к аватарам, а не к границе всего события. Пустой график не рисует толстую нулевую линию.


## Результат общего аудита 11 ноября 2026

У поиска и остальных полей один владелец поверхности, рамки и фокуса. Группа поиска подсвечивается целиком через `:focus-within`; её обёртка не обрезает индикатор. Наведение на ссылку-карточку меняет нейтральную рамку и оттенок заголовка без синей заливки, подъёма и тени. Выбор обозначается мягкой заливкой, клавиатурный фокус — отдельным контуром. Графики Plotly читают основной и акцентный цвета из тех же переменных темы.

`<x-gc-form-actions form="…" label="…" />` задаёт одну компактную закреплённую панель сохранения. На телефоне она располагается над нижней навигацией. Связь с формой через нативный `form` сохраняет браузерную валидацию и CSRF. Дубли названия, режима и даты из боковых колонок редакторов убраны; самостоятельные функции, например ручной ранний доступ и предпросмотр товара, остаются.

Лента событий одноколоночная, группируется по дням, фильтруется на сервере по доступному курсу и типу события. Плотная галерея сообщества показывает до 20 участников на странице; аватары 80 px, персональные рамки, звания и ранг сохраняются. Отсутствующая фотография отображается инициалами; дизайн не перекрашивает приобретённые рамки.

В журнале закреплённая колонка ученика на телефоне ограничена по ширине; звание доступно в подсказке. Показывается одна глава: выбранная, текущая глава курса либо первая. Выбор находится перед таблицей, режима «все главы» нет. Метки состояний одновременно объясняют оформление баллов и фильтруют учеников по наличию соответствующей работы; счётчики и поиск работают совместно. Состояния: без баллов, частично, выполнено, на проверке, заблокировано. Баллы ограничены текущим курсом. Сводка отчёта и признак проверки ячеек берутся из `Solution::pendingReview()`, как очередь. Нулевой максимум не даёт состояния «Выполнено».

Выдача достижения состоит из вариантов выбора и одной формы. Регистрация разделена на аккаунт и профиль ученика; необязательные сведения свёрнуты, обязательные поля и серверные правила сохранены. Без JavaScript оба шага регистрации видны одновременно. Общие инициализаторы находятся в `components/interface-forms.js`, включая предпросмотр стикера после готовности DOM.


## Принятый первый вариант

`<x-gc-course-header :course="$course" active="…" />` — единая шапка программы, плана занятий, журнала, отчёта и дедлайнов. Название курса, описание и порядок навигации не меняют позицию при переходе; локальный заголовок раздела и действия идут ниже. Видимость разделов зависит от существующих прав и флага планировщика. На телефоне навигация прокручивается горизонтально, выбранный раздел обозначен `aria-current` и автоматически попадает в видимую часть ленты. Сенсорные вкладки и управление паролем имеют область нажатия 44 px; общее правило размеров расположено после legacy, чтобы старые поля не уменьшали эту область.

`<x-gc-person-row>` задаёт один формат преподавателей и рейтинга: аватар, имя, личное звание и подпись, небольшое место справа только для рейтинга. Длинное имя и звание обрезаются внутри своей колонки, полный текст доступен в подсказке. `<x-gc-copy-value>` даёт код приглашения и доступное действие копирования с живым сообщением о результате.

Профиль использует общую `.gc-profile-hero`: одна карточка, личность/контакты/«О себе» слева, комната справа. Подробности в `docs/ux/profile-proposal.md`. На телефоне порядок совпадает с DOM: личность → контакты → биография → комната → обучение → достижения → наклейки. Служебный комментарий остаётся отдельным разделом по прежним правам.

Вход — компактная карточка поверх фотографии учеников с логотипом и названием системы внутри, заголовком «Войти в аккаунт», подписанными полями и показом пароля. Случайная фотография из существующего набора `/images/bg/1…16.jpg` сохраняется по просьбе пользователя; крупной отдельной иконки над формой нет. SSO, восстановление, запоминание входа и серверные ошибки сохраняются. Геометрия и цвета заданы общими стилями; отдельный пакет оформления входа не создаётся.


## Вторая итерация: ежедневная работа и чтение

Ученик сначала видит учебные действия и сроки, затем каталоги. Статистические плитки, повторяющие количество курсов и средний прогресс, убраны. Карточки «Моих курсов» содержат одну основную ссылку без повторных быстрых переходов в план, журнал и проверку. Эти действия доступны внутри курса, очередь проверки сохраняет самостоятельную сводку.

На странице курса ученика «Продолжить» и следующая ступень находятся внутри текущего урока. Сроки задач собраны у соответствующего урока, текущий раскрыт. Повторных блоков продолжения и длинного списка тех же задач справа нет. У преподавателя сроки остаются в боковой области, чтобы программа и управление уроками занимали первый экран. Рейтинг показывает тройку лидеров и самого ученика, если он ниже; остальные доступны по раскрытию. Проценты уроков и общий XP используют основной цвет, без красного наказания за нулевой прогресс.

`CourseDeadlineList` задаёт одинаковые доступность и выполнение для главной, курса и списка сроков: учитываются открытие/ранний доступ урока, скрытая задача и решения именно этого курса. Низкая выставленная оценка не убирает задачу из напоминаний; дедлайн действует до конца указанного дня. Превью сочетает недавнюю просрочку с ближайшими сроками, чтобы старый долг не вытеснял будущие задачи.

Конспекты сохраняют размер основного текста 16 px и ограниченную длину строки. Подчёркивания под заголовками убраны. `.gc-code-example` выносит копирование над кодом, не накладывая кнопку на строки; длинный код и `.gc-table-scroll` доступны с клавиатуры. На узком экране есть раскрываемое оглавление, на широком — прокручиваемое боковое. Переключение на задачу скрывает индикатор чтения теории. Ноутбуки используют общие `.gc-notebook*`: текст не получает отступ под номера кода, а на телефоне номера ячеек переносятся над кодом. Сами ячейки, результаты и формулы сохраняются.


## Согласованный рабочий UI · 11 ноября 2026

Журнал сначала показывает одну колонку итогов на урок выбранной главы. Нажатие на заголовок или итог показывает отдельную таблицу задач этого урока ниже; глава не расширяется автоматически до всех задач. Поиск и фильтры учитывают состояния всех задач, включая закрытые колонки. Таблицы растут по высоте содержимого: вертикальная прокрутка одна, у страницы. По горизонтали таблица прокручивается внутри, имя закреплено.

Отчёт и проверка используют общую `.gc-master-detail`: компактный список слева, выбранный человек/работа справа. На телефоне селектор расположен перед содержимым. Отчёт сохраняет поиск и сортировку списка на широком экране, графики, главы, задачи и сигналы GeekPaste. Общая очередь проверки сразу открывает первую работу; текущая работа, проверка, перепроверка и пропуск остаются доступны.

Ступень — рабочая тетрадь с переключателем теории/задач. На телефоне список ступеней раскрывается под заголовком, с видимым текущим положением. Теория ограничена по ширине; оглавление, код, таблицы, формулы и ноутбуки сохраняются. У преподавателя личная сдача доступна по отдельному раскрытию после прогресса учеников.

Формы используют `.gc-form-layout` и последовательные секции. Параметры ИИ и Telegram видны сразу; они не спрятаны под спойлером. У редакторов одна панель сохранения. Каталог выбора иконки и опасное восстановление настроек — отдельные действия, а не скрытые параметры формы.


Учебные состояния оформляются через `gc-task-state`, календарные подписи — через `gc-deadline-label`. Ожидание проверки использует общие pending-токены; полученное достижение — обычную ссылку основного цвета. `gc-panel` в режиме `embedded` не создаёт вторую рамку внутри уже оформленной панели. Шапка задачи общая для кода, текста и квиза; служебные действия преподавателя отделены от полосы учебных вкладок. См. [итерацию 10](ux/ui-round-10.md).


Социальная карточка `gc-person-card` группирует имя, роль, ранг/XP и пользовательское звание рядом с аватаром. Размер портрета учитывает максимальную покупную рамку, обёртка рамки не сжимается. Контакты используют `gc-contact`: видимая подпись и область нажатия всей строки. `gc-page-navigation` переиспользует общие кнопки. На сенсорном экране ссылки пагинации и интерактивный баланс имеют высоту 44 px. См. [итерацию 11](ux/ui-round-11.md).


Каталог магазина собирает поиск, доступность, скидку и категории на одной общей поверхности `gc-workspace-toolbar`. Цена и компактная кнопка справа используют `gc-purchase-footer`; длинный текст раскрывается через `gc-expandable-text`. Превью цифровых товаров резервирует место для полной рамки и отдельной подписи категории. Окно рамки использует `gc-dialog`, токены теней и нейтральные поверхности; правила заменённых превью и старого окна удалены из legacy. Акции выделяются акцентным цветом темы в метке скидки, иконке и границе; фон баннера остаётся нейтральным, отдельной сезонной палитры нет. Основные действия сохраняют primary. См. [итерацию 12](ux/ui-round-12.md) и [уточнение акцентов](ux/ui-round-24.md).


В Пульсе общая шапка содержит компактную сводку; лента остаётся самостоятельной панелью с группировкой по дням. Категории используют прокручиваемые `gc-filters--scroll`, график — `gc-pulse-chart`. В проверке поиск и фильтры живут внутри общего roster, чтобы на телефоне не отодвигать ответ. Формы оценки перенесены из legacy в компоненты, используют токены размеров и обычные подписи над полями. Перепроверка — состояние ожидания с основным цветом темы; предупреждения GeekPaste сохраняют собственную семантику. Покупные рамки остаются в социальной ленте; в учительской очереди их нет. См. [итерацию 13](ux/ui-round-13.md).


Формы создания и редактирования используют общие компоненты authoring: шапка на поверхности, одна рабочая колонка на общую ширину страницы, одна карточка с открытыми секциями и подписями над полями. Числовые поля допускают пару колонок, основной текст занимает всю ширину. Параметры не прячутся в аккордеоны. `gc-field` объединяет подпись, подсказку и ошибку; `gc-toggle` оставляет переключатели простыми строками. Редактор Markdown получает цвет, рамку, текст, курсор и состояния toolbar из тех же токенов; отдельные dark-правила EasyMDE из legacy удалены. Панель сохранения не выходит за основную форму и располагается над общей мобильной навигацией. Размеры кнопок панели редактора на touch-устройствах — не менее 44px. См. [итерацию 14](ux/ui-round-14.md).


Вход сохраняет согласованную композицию с затемнённой фотографией на весь экран и компактной формой по центру. Не заменять её отдельной колонкой с фото. Регистрация и восстановление используют тот же фон, общие поля и `gc-auth-heading`; для регистрации допускается более широкая карточка и видимые шаги. Параметры профиля внутри шага остаются открытыми. Личные настройки используют существующую колонку формы и открытые секции, без внутренних карточек для каждого способа входа. Подробности — [итерация 15](ux/ui-round-15.md).


Уточнения итерации 16: формы `.gc-form-layout` используют всю доступную ширину основного контента, включая настройки и создание заданий. Ступень сохраняет сплошной серый рейл и единую белую область заголовка, вкладок и конспекта. Список глав открывается из текущего названия большим меню с поиском в длинной программе. Наклейки профиля видны без раскрытия. См. [итерацию 16](ux/ui-round-16.md).

Рейл ступени использует спокойный оттенок палитры через `--gc-workbook-rail`; текущая ступень — мягкую заливку `--gc-workbook-current-bg` и контрастный текст `--gc-workbook-current-ink`. Сплошная яркая заливка для неё не применяется. Изображения конспекта отображаются без декоративной рамки, подложки и внутренних отступов, с сохранением подписей, исходных пропорций и ссылки на полный размер. Это не меняет оформление покупаемых рамок аватаров.


Селектор главы повторяет согласованные макеты: номер и название слева, компактные точки справа, стрелка раскрытия у названия. На телефоне счётчик и название стоят друг над другом внутри одной кнопки, точки остаются справа в той же строке. Отдельные кнопки предыдущей/следующей главы убраны; сохраняются выбор на таймлайне, клавиатура и большой список с поиском. Меню учитывает границы окна и нижнюю мобильную навигацию. Это изменение использует действующую тему. Вариант B+ выбран пользователем и перенесён в общие токены и компоненты; см. [итерацию 17](ux/ui-round-17.md) и [уточнение компактности](ux/ui-round-23.md). Будущие уведомления о наградах и развитие GeekPaste записаны в [плане следующих этапов](ux/follow-ups.md).


B+ разделяет роли навигации и контента. `--gc-sidebar-*` задают поверхность, текст, наведение и выбранный пункт рейла/мобильной шапки. Они не подменяют обычные `--gc-selected-surface` и `--gc-nav-active-bg` внутри форм и страниц. В светлом режиме рейл получается из нейтрального цвета текста и настроенного primary; в тёмном использует прежнюю поверхность темы. Активный пункт учитывает вычисленный контраст кнопки. Не помещать светлые карточки вокруг маленьких иконок курсов в меню.

В карточках каталога используется выбранный пользователем вариант с иконкой сверху: `gc-course-icon` размером 24 px на подложке 48 × 48 px перед названием. Цвет и подложка следуют primary/info/accent темы; большая обложка и дополнительная подпись категории не используются. Прогресс ученика, статусы, запись на курс и даты архива сохраняются.

`gc-lesson-reward` показывает существующую наклейку урока: серую до получения через CSS `grayscale(1)`, цветную после, с доступной подписью состояния. У изображения нет серой подложки или рамки: прозрачность исходного файла сохраняется. Стикер справа выровнен по верхнему краю названия, а не по центру длинного списка ступеней. Размер блока — 104 px у обычного урока и 144 px у текущего; на телефоне 80 и 104 px соответственно. Слева остаются название и описание, а на компьютере также список ступеней текущего урока. На телефоне ступени используют ширину карточки. Меню преподавателя занимает отдельную ячейку над изображением. Без наклейки используется иконка 48 px. В преподавательском просмотре наклейка показана цветной как часть содержания урока. Декоративная иллюстрация рядом с наградой не добавляется. `gc-lesson-outline` даёт список ступеней без вложенной карточки; он присутствует только у текущего урока и открыт по умолчанию. У остальных уроков показан статический счётчик ступеней; название ведёт в сам урок. Кнопка продолжения находится у урока. Покупные рамки и комнаты сохраняют собственное оформление, как и фотографический фон входа.

Оранжевый акцент используется точечно для живых событий и наград: отметка текущего урока, поздравления, достижения и скидки. Он берётся из `--gc-accent`, включая пользовательскую и тёмную палитры. Метки используют обычный контрастный текст; маленькие декоративные иконки и маркеры — сам акцент. `gc-panel` принимает необязательную иконку заголовка; она включена у достижений и наклеек профиля. Не окрашивать целые страницы, учебные тексты или кнопки навигации ради декоративной выразительности.


Преподаватель курса отмечает общий текущий урок через меню урока и может снять отметку. Он показан крупнее и раскрыт для обеих ролей; выбранная преподавателем ещё закрытая глава не открывается ученику автоматически. При отсутствии доступной отметки ученик видит собственное продолжение. Цвет наклейки следует существующему порогу выдачи (>90%), правила начисления награды не меняются.

В отчёте преподавателя уроки без задач и пустые главы не показываются. Урок с задачей без баллов сохраняется с подписью «Без оценки». Если во всём курсе пока нет открытых уроков с заданиями, отображается объяснение вместо пустых раскрытий и неприменимых фильтров. Контекст ученика и график чтения остаются доступны. Строка урока содержит название, состояние, XP и компактный прогресс; раскрытые задачи идут общим списком, с заголовками ступеней при необходимости и переносом длинных названий. См. [итерацию 20](ux/ui-round-20.md).


Если преподаватель закрепил общий текущий урок, просмотр другой главы не назначает второй текущий урок. В панели над программой доступен переход «К текущему уроку», включая возврат внутри длинной главы. У преподавателя текущий урок имеет явное действие «Открыть урок»; статистика доступна при наличии учеников, ближайшие сроки предшествуют справочной информации в правой колонке. См. [итерацию 21](ux/ui-round-21.md).


## Сдача и оценивание задачи

Выбран вариант «Рабочий лист»: теория и задача имеют одинаковый белый фон.
Условие находится в верхней карточке и по умолчанию раскрыто. Общая карточка
сдачи объединяет ученика и стрелки навигации, выбранную попытку, отметку просмотра.
На широком экране имя и селектор располагаются в одной строке.
Статус и зачтённый XP находятся здесь же. Оценка за работу и применённый штраф объясняют итог внутри
этой же карточки; второго конкурирующего числового итога нет. Учитель видит исходник
на всю ширину, затем отчёт и оценивание рядом; на узком экране оценивание идёт первым.
Исходник раскрыт по умолчанию, его можно свернуть. Один селектор сдач не дублируется
списком истории; журнал проверок и обычная/усиленная перепроверка с комментарием
находятся в меню результата. Одна текстовая кнопка сохраняет оценку, отдельная стрелка
переходит к следующему ученику. Длинный Markdown-комментарий можно расширить;
редактор EasyMDE загружается при открытии оценивания и даёт кнопки Markdown без
отдельного предпросмотра. При переключении сдач черновик сохраняется, обработчики
предыдущего редактора освобождаются. Обычная и усиленная перепроверки доступны
через троеточие; для исторической работы результат привязан к выбранной сдаче.
Текстовые файлы, включая README.md, читаются внутри карточки; несколько файлов
можно скачать одним ZIP с сохранением путей и исходных байтов.
Загрузка сохраняет прежнюю поверхность и черновик оценки. Акценты ученика — иконка задачи,
награда GC и фактический прогресс к наклейке урока; используются токены темы
и существующий компонент наклейки. Подробности — [task-checking-flows.md](ux/task-checking-flows.md).

Синий выделяет действия, выбранные режимы и прогресс. Оранжевый акцент выделяет
монеты, награды и текущую задачу. Макеты и контрольный стенд задают оба цвета
явно; настройки бренда остаются общими для главной, курса и задач.
Статистика урока показывает читаемые строки в двух колонках на широком экране
и в одной на узком: полное имя, XP и короткая полоса прогресса. Сводка располагается в одну строку. По нажатию
открывается отчёт выбранного ученика с раскрытым нужным уроком. Пагинация
остаётся по 25 учеников, сводка относится ко всему классу.

Действия со штрафом и бустером используют сохранённый Solution и действующие цены
сервера. Учитель снимает штраф бесплатно, ученик — за GC; бустер применяется до
штрафа и ограничен максимумом задачи. Перед покупкой показаны точный итог и цена;
повторный запрос не списывает монетки ещё раз. Подарки питомцев учитываются.
Открытие скрытых непройденных тестов и дополнительная AI-попытка остаются возле
соответствующего действия. Отчёт показывает XP выбранной главы, ровные строки уроков
и вложенных задач с общей колонкой баллов, сигналы авторства и переход к конкретной работе.
Глава выделена синим заголовком с оранжевым акцентом; каждый урок имеет свою
карточку. Белое раскрытие разделено на подписанные ступени, задания отделены
тонкими линиями, переход к работе обозначен стрелкой. Отдельного спойлера анализа
предупреждений нет; реальные сигналы авторства и действия сохранены. Прогресс расположен
под итогом урока. Форма сдачи имеет собственную карточку с заголовком «Ваше решение»
(«Пробное решение» у учителя), файлом/языком и действием отправки. Внутренние отступы
есть у карточки бинарного файла и текстового ответа; заголовок «Ответ» не повторяется.
Код сохраняет стык с краями своей карточки. Небольшие тесты показываются текстом,
ссылка скачивания остаётся только для крупных или бинарных данных.
Подпись объясняет штраф последней сдачи, если в зачёт пошла другая лучшая работа;
на телефоне подпись использует всю ширину строки, а переход доступен по иконке.

Компактный блок сроков показывает текущий штраф и следующий дедлайн. До первого
срока — «Без штрафа», после последнего — только действующий штраф. Полное
расписание раскрывается по нажатию. Открытая страница автоматически обновляет
строку при переходе границы, используя время сервера и те же правила границ,
что и начисление баллов.
