# Организация фронтенда

## Общие входы

`vite.config.mjs` собирает общие стили и существующие JS-входы. `resources/assets/js/vendor.js` — совместимая точка подключения для Blade, а не хранилище логики всех экранов. Имена входов и глобальные API сохранены; отдельный пакет дизайна для каждой страницы не вводится. Правила стилей и палитры — в [ui-style.md](ui-style.md).

До DOM-инициализации задаются `window.axios`, `window.autosize`, `window.flatpickr`, `window.hljs`, `window.bootstrap`, локаль и CSRF-заголовок. Они пока нужны встроенным интеграциям существующих шаблонов. Их удаление требует отдельной миграции потребителей; перемещение кода в модуль само по себе этого не разрешает.

## Стили

`_components.scss` задаёт порядок смысловых модулей в `sass/components/`: чтение, выбор, элементы управления, навигация, поверхности, участники, каталог, обучение, планировщик, рабочие пространства, награды и формы. Это части одного `app.css`, а не отдельные CSS страниц. Покупные рамки и звания имеют отдельный общий модуль `avatar-decoration`: художественная палитра предметов не подменяет тему интерфейса. Старые перекрытые объявления удаляются только после проверки конкретного конечного владельца в каскаде. Порядок сохраняет каскад существующего интерфейса; первичное разделение проверено побайтовым совпадением собранного CSS. `styles:check` рекурсивно проверяет вложенные модули и запрещает случайные цвета вне владельцев палитры.

Главный контроллер планировщика сокращён с 667 до 317 строк. Общее состояние остаётся у `index.js`. Представления и каталог получают `getState()`, поэтому после загрузки новой ревизии читают актуальные данные, а не сохранённую при создании ссылку. Каталог хранит только собственное состояние выбора и поиска; изменение занятий идёт через переданные `ensureSession` и `mutate`. Номер запроса и `AbortController` защищают поиск от устаревших ответов. Серверные проверки прав, дублей, пересечений и ревизий сохраняются.

Формы планировщика получают тот же объект `dialog` и общий `mutate`; отдельных HTTP-клиентов и параллельных владельцев ревизии у них нет. Изменение выбранного занятия и диапазона проходит через `setTarget` и `setRange`. Предварительный расчёт расписания не сохраняет настройки до подтверждения второй формы.

Редактор рамки нормализует пользовательские значения в `avatar-frame-config`, а `avatar-frame-preview` применяет их ко всем превью и полям стоимости. Художественная палитра самой покупной рамки независима от палитры интерфейса. Диалог и обработчики редактора запускаются прежним единственным инициализатором из `vendor.js`.

Каждый модуль экспортирует функцию инициализации, вызываемую общей точкой входа. Сам импорт не должен регистрировать повторные глобальные обработчики. Внутренние зависимости (`bootstrap`, `autosize`, `linkify-html`) импортируются там, где используются. Публичные глобалы пока служат только совместимости.

Обычные примеры кода подсвечивает Highlight.js; ячейки Notebook — Prism по явному вызову. Общий head устанавливает `Prism.manual` до загрузки библиотек. Единственный владелец вставки Notebook — `notebook-render.js`; он отправляет событие обновления оглавления и вызывает MathJax для новых ячеек. Повторная вставка из `content-media.js` удалена.

Повторяемая браузерная проверка: `npm run ui:baseline` перед изменением, `npm run ui:compare` после сборки, либо `npm run ui:check` для самостоятельного прохода. Стенд использует собственный сервер и синтетическую SQLite-базу. Описание сценариев, палитры и артефактов — [scripts/ui-checks/README.md](../scripts/ui-checks/README.md).

## Порядок инициализации

Комната, формы и главы запускаются прежде прикладных улучшений. Сначала создаётся модуль чтения, затем вкладки получают его `refresh()` как обратный вызов. Ссылки профиля и общие элементы управления инициализируются отдельно. После вставки изображений/ноутбуков снова вызывается `reading.refresh()` для появившихся заголовков и кода, выполняется подсветка. После этого создаются Markdown-редакторы, навигация, действия ИИ, графики и обработчики отправки.

Перестановка вызовов требует проверки вкладок, hash-ссылок, оглавления и Jupyter: эти части зависят от подготовленного DOM. Новая логика привязывается к устойчивому `data-*` контракту, а не к тексту кнопки или декоративному классу. Без динамического частичного обновления DOM не требуется вводить общий сложный механизм повторной инициализации; при его появлении жизненный цикл нужно описать отдельно.

## Аватары в разных контекстах

`<x-gc-avatar :user="$user" />` сохраняет выбранное оформление. В социальных контекстах — профиль, сообщество, общие рейтинги — это поведение по умолчанию независимо от роли зрителя.

`<x-gc-avatar :user="$user" :frame="false" />` показывает изображение/инициалы без покупной рамки и эффектов. Используется в сугубо преподавательской работе: отчёт и очереди проверки. Признак задаётся конкретному использованию компонента, не глобальному пользователю или CSS-селектору роли. Он не меняет купленный предмет, срок действия или настройки рамки.

## Дальнейшее упрощение

Выделение модулей сохраняет существующее поведение. Общая работа hash теперь отделена от чтения, но прежний долг устранён не полностью: `index.js` планировщика ещё содержит прикладные команды и формы, `collection-filters.js` — несколько видов коллекций, а legacy — действующее оформление отдельных экранов. При следующем содержательном изменении нужно выделять общий механизм только при совпадении контракта, а не создавать универсальный контроллер на основе похожих названий классов.

Стили продолжают собираться одним входом: vendor → токены → база → совместимость → общие компоненты. Каркас приложения (`gc-layout`, `gc-main`, `gc-content`, backdrop и мобильная компенсация навигации) принадлежит базе. Конспекты, медиа чтения, подсветка кода и множественный выбор принадлежат общим компонентам. Цвета подсветки задают `--gc-syntax-*`, поверхности кода — `--gc-code-*` и `--gc-inline-code-*`; тёмная тема меняет значения токенов без второго набора правил для каждого языка разметки. Контекстный шрифт комментария проверки сохраняется правилом `solution-feedback__content` после общей типографики Markdown.

Старые варианты переключателя глав, карточки урока и карточки проверки удалены; `styles:check` запрещает возвращать эти селекторы, дубли каркаса и мигрировавшие общие элементы в legacy. В согласованном изменении экрана переносится его повторяющееся оформление и удаляются прежние определения. Не добавлять новое переопределение в конец legacy или стили внутри JS/Blade.

Горизонтальные вкладки оборачиваются в `<x-gc-tab-strip>`. Компонент не меняет роли и адреса вложенной навигации: ссылки остаются ссылками, Bootstrap-вкладки — вкладками. Кнопки прокрутки появляются только при нехватке ширины; без JavaScript список сохраняет обычную горизонтальную прокрутку. Отступ после навигации задаётся обёртке. Не добавлять отдельную автопрокрутку на каждом экране.

`gc-page-masthead` объединяет заголовок и связанные вкладки, поиск или действия одной белой поверхностью. Отдельный `gc-page-header` имеет ту же поверхность; внутри общей шапки оформление не дублируется. Для заголовка внутри уже оформленной визитки используется `<x-gc-page-header :embedded="true">`. Размеры, рамка и цвет задаются в общем слое компонентов.

`App\Support\WorkspaceNavigation` возвращает доступные текущие курсы и единое описание глобальных переходов. Blade использует эти данные в боковой и нижней мобильной навигации, не дублируя условия роли и выбранного адреса. Список курсов ограничен восемью; открытый доступный курс остаётся видимым. Подробности и референсы — [итерация 8](ux/ui-round-8.md).

`<x-gc-workspace-toolbar>` группирует период, поиск, фильтры и действия на одной общей поверхности. Используется планом, журналом и отчётом. `gc-workspace-field` задаёт одинаковые подписи полей. Адаптация недели, контекст ученика в журнале и фильтры уроков отчёта описаны в [итерации 9](ux/ui-round-9.md). Фильтрация отчёта выполняется только для активной панели ученика; скрытые задачи по-прежнему создаются из template при первом раскрытии.

`<x-gc-roster id="…" labelledby="…">` содержит единственный список рабочего пространства. На компьютере это левая колонка, на телефоне — Bootstrap responsive offcanvas; внешняя компоновка получает `gc-roster-workspace`. Содержимое использует `gc-roster-surface`. Компонент общий для отчёта и проверки; кнопки открытия и заголовок со связанным ID задаёт конкретный экран. Данные, формы и ссылки внутри списка не копируются для другого размера экрана.

Журнал сохраняет обзор всей главы. На телефоне выбор урока закрывает обзор и переводит фокус к разбору; возврат снова открывает обзор. Таблицы раскрываются на полную высоту; локальная прокрутка остаётся только по горизонтали. `table-navigation` инициализируется также для новой таблицы разбора, без повторных обработчиков на существующих элементах. В отчёте список учеников один: на компьютере он расположен слева, на телефоне открывается через responsive offcanvas. Подробности задач хранятся в инертном template и вставляются один раз при раскрытии; графики активности сохраняют собственный прежний жизненный цикл.

На странице дедлайнов группировка идёт по дате и уроку, без вложенных карточек задач. Поиск учитывает задачу, ступень и урок. Для ученика состояния относятся к его выполнению; для преподавателя фильтры описывают календарный срок, а не результаты класса. Оформление списка сроков, условия при проверке и мобильных заказов перенесено в общие компоненты, заменённые правила из legacy удалены.

Проверки: `npm run styles:check`, `npm run frontend:test`, `npm run build`, `npm run ux:check`, `php artisan test --compact`. Сборка сначала запускает проверку стилей и регрессионные JS-тесты. Для изменения компоновки — снимки с обеими ролями, телефоном, длинным содержимым, пустыми состояниями и выбранной пользовательской палитрой. Для чистого перемещения JS — сравнение вычисленных стилей и снимков плюс проверка интерактивных сценариев. JS-тесты проверяют актуальность состояния, экранирование и контракт HTTP, а не структуру файлов. Контрольный проход этой итерации — [frontend-refactor-2026-11-14.md](ux/frontend-refactor-2026-11-14.md).

Следующий проход, с переносом общих стилей чтения и выделением форм планировщика и редактора рамки: [frontend-refactor-2026-11-14-2.md](ux/frontend-refactor-2026-11-14-2.md).


В программе курса сводка ученика переставляется перед уроками на телефоне без копии DOM. `gc-panel` и `gc-deadline-preview` поддерживают встроенный режим `embedded`; он используется внутри самостоятельной панели, а не вместо рамки самостоятельного блока. Общая шапка задачи — `steps/partials/task_header`, состояния и сроки — `gc-task-state` и `gc-deadline-label`. `gc:task-checked` передаёт `taskId` и `mark` из ответа формы в модуль тетради; он обновляет подпись вкладки, не пересчитывая оценки. Решения и детали квиза остаются в своих существующих шаблонах. Подробности — [итерация 10](ux/ui-round-10.md).


Сообщество использует `gc-person-card`, профиль — `gc-contact`; компактные переходы страниц — `gc-page-navigation`. `CommunityNavigation` переносит только запрос, роль и страницу галереи в ссылку профиля и восстанавливает их с якорем карточки. Серверная пагинация ограничивает выдачу 20 записями. Поиск и переключатели роли работают GET-формой без отдельного JS-контроллера. Профиль на телефоне переставляет единственные экземпляры контактов, комнаты и резюме через CSS; раскрытие достижения по ссылке обслуживает существующий `interface-forms.js`. См. [итерацию 11](ux/ui-round-11.md).


Магазин использует `gc-workspace-toolbar`, `gc-purchase-footer`, `gc-promotion-badge` и `gc-expandable-text`. Каталог и выбор товаров акции имеют разные задачи: каталог фильтруется локально, редактор акции загружает страницы с сервера. `promotion-picker` хранит временный выбор отдельно от применённого; компактное отображение выбранных товаров не удаляет скрытые поля формы. Своя рамка открывается в нативном `dialog` с общими стилями, замкнутым Tab и возвратом фокуса.

`MarketOrders` выполняет поиск до пагинации, отдельно ограничивая активную очередь и историю 25 заказами. Оба адреса заказов используют единственный `market/partials/order-workspace`; ссылки выдачи и отмены сохраняют фильтр, страницу и вкладку. Возврат разрешён только на адреса магазина того же origin. После удаления последнего заказа страницы запрос возвращает последнюю существующую страницу. См. [итерацию 12](ux/ui-round-12.md).


Пульс использует общий `gc-pulse-chart` и ту же геометрию, что краткий график на главной. Расчёт сигнала остаётся в `CoursePulse`. Серверный поиск применяется до пагинации, а график ограничен доступным выбранным курсом; подпись поясняет, что он отражает все типы событий за 24 часа. Поиск и категории работают обычными GET-формой и ссылками.

Проверка сохраняет один responsive roster с очередью, поиском и фильтрами. На компьютере это левая колонка, на телефоне — тот же DOM в offcanvas. `ReviewWorkspace` задаёт разрешённые курсы, фильтры и последовательность перехода. Обновление оценки не пересчитывалось: UI передаёт прежние поля и отдельный `review_solution_id` для восстановления только нужной формы. `review-attempt` переиспользуется текущей попыткой и раскрываемой историей. Раскрытие истории по якорю обслуживает существующий `interface-forms`, без второго обработчика. `SqlTextSearch` задаёт безопасные шаблоны поиска и регистр для SQLite/Cyrillic; имена SQL-колонок берутся только из кода. См. [итерацию 13](ux/ui-round-13.md).


Формы курсов, глав, уроков, ступеней и задач используют `gc-authoring-page`, `gc-form-section`, `gc-field`, `gc-toggle` и `gc-markdown-field`. Это одна колонка с открытыми секциями и подписями над полями. Общая панель сохранения ограничена телом основной формы; отдельное ручное открытие урока сохраняется собственной формой. У создания и редактирования есть общие partials; задача создаётся на самостоятельной странице вместо большого диалога.

`form-workspace.js` связывает ошибки с полями, фокусом, индикатором изменений и состоянием отправки. Он управляет применимостью ответа и инструкции достижения, не скрывая параметры. `markdown-editor.js` отвечает за единственный экземпляр EasyMDE, переключение Notebook без изменения текста и асинхронный предпросмотр. Предпросмотр использует POST `/insider/authoring/preview` с CSRF и тем же безопасным `parsedown_math`, что чтение материала. Запросы отменяются при смене текста; есть кэш, повтор после ошибки, подсветка кода и MathJax. Автосохранение чужого поля по общему имени не включается: старые потребители могут явно запросить его с уникальным ключом URL + поле. См. [итерацию 14](ux/ui-round-14.md).


`account-forms.js` объединяет показ пароля, проверку совпадения, два шага регистрации с доступной навигацией и локальное превью выбранного аватара. Эту логику больше не хранит общий `interface-forms.js`. Без JavaScript регистрация показывает обе секции и обычную кнопку отправки. `form-workspace.js` переиспользуется авторскими формами, профилем и аккаунтом: подписи, ошибки, фокус, отправка и восстановление после истории браузера остаются общими. Регистрация управляет фокусом ошибок внутри своих шагов. Экран входа сохраняет утверждённое оформление: затемнённая фотография на весь фон и компактная форма по центру. Используются прежние 16 фотографий, без отдельной колонки с изображением. Подробности — [итерация 15](ux/ui-round-15.md).


`chapter-timeline.js` обслуживает также выпадающий список глав: поиск, фокус, ограничение меню размером окна и сброс при повторном открытии. Ссылки и закрытые главы определяет прежняя серверная навигация. `gc-form-layout` больше не ограничивает ширину редакторов и настроек; они следуют ширине основного контента.

Кнопка названия главы со счётчиком и range таймлайна занимают отдельные ячейки одной строки; области нажатия не перекрываются. На телефоне счётчик расположен над названием внутри кнопки. Один и тот же компонент используется при любом количестве глав. Режим `embedded` позволяет объединить выбор главы, действия преподавателя и компактную сводку сроков в одну поверхность.


В B+ общая мобильная шапка и карточки курса перенесены из legacy в `_components.scss`. Смысловые цвета рейла отделены от обычных выбранных состояний форм. Каталог использует общий `gc-course-icon` с модификатором размера и подложки; выбран компактный вариант с иконкой над названием. В программе курса используются `gc-lesson-reward` и `gc-lesson-outline`: первая показывает существующую наклейку урока и состояние её получения, второй — ступени без вложенной карточки. При отсутствии наклейки остаётся маленькая иконка `CourseIcons`. Декоративная иллюстрация, дублирующая награду, удалена. Каталог иконок поддерживает выбор преподавателя и автоматическое определение, без генерации при открытии страницы.

Завершённые курсы используют ту же карточку и каталог иконок; сохранённая отметка не получает отдельный дизайн карточки. Для товара общий partial `market/partials/form-preview` связан с формой атрибутом `data-market-preview`. Инициализатор подключается через `vendor.js`; создание и редактирование больше не содержат копию встроенного скрипта. Состояния изменения и отправки принадлежат общему `form-workspace.js`.

Оформление редактора комнаты перенесено из большого `<style>` в Blade в единый `_components.scss`. Геометрия слоёв и динамические координаты остаются данными редактора; поверхности, поля, текст, статусы и действия используют общие токены. Логику генерации персонажа этот перенос не затрагивает.


Общий текущий урок хранится в `courses.current_lesson_id`, а не в программе, чтобы параллельные курсы выбирали его независимо. `Course::currentLessonFor()` проверяет принадлежность программе, наличие ступеней и прежние права доступа. POST `courses.current-lesson` разрешён преподавателям этого курса и администратору. Явная выбранная глава имеет приоритет над главой закреплённого урока; без закрепления применяется личное продолжение ученика. При закреплении просмотр другой главы не подставляет другой текущий урок: существующая отметка доступна через ссылку возврата.

`CourseReportLessons::groups()` собирает только открытые уроки с задачами и непустые главы, не меняя исходную коллекцию программы. Для графика просмотров контроллер использует все открытые ступени, включая теоретические. Раскрываемые задачи отчёта по-прежнему создаются лениво из `<template>` общим `course-report.js`; оформление строк и групп ступеней принадлежит `_components.scss`.


Список ступеней `gc-lesson-outline` рендерится только у текущего урока. Остальные карточки содержат статический счётчик без скрытого списка ссылок. Заголовок карточки, место стикера, действия и нижняя строка имеют единственного владельца в `_components.scss`: соответствующая группа `course-path-*` перенесена из legacy, заменённые размеры и старые цветовые исключения прогресса удалены.

`CourseLessonView` согласует действие карточки и подсказку ступени: чтение, продолжение, проверка, улучшение и повторение. Получение наклейки при прежнем пороге выше 90% не объявляет все задачи полностью решёнными. `CourseStudyOutcome` задаёт следующее действие завершённой главы и режим повторения завершённого курса; наличие ещё закрытых уроков исключает преждевременное объявление главы пройденной. Расчёт XP и выдача наград остаются в существующих сервисах.

`CourseLessonStatistics` формирует сводку по всей группе, включая нулевой результат отсутствующих записей. Подробности загружаются GET `courses.lesson-statistics` только после открытия панели, по 25 учеников; авторизация и принадлежность урока проверяются сервером. `course-stats.js` сохраняет раскрытие, отменяет устаревшие запросы страниц и позволяет повторить запрос после ошибки. Размер группы не скрывает преподавательские инструменты.

Страница программы загружает ступени и задания выбранной главы; решения ограничены текущим учеником и курсом. Нельзя задавать ограничение eager loading первым вызовом и затем повторно загружать неограниченную вложенную связь: это отменяет исходное ограничение. URL библиотеки графиков задаётся метатегом `gc-plotly-src`; общий инициализатор создаёт единственный script только при открытии реального графика. Подробности — [итерация 23](ux/ui-round-23.md).


## Рабочая область сдачи задачи

`code-checking/workspace.js` управляет постоянной областью редактора и результата,
компактной историей и автосохранением с ревизией. `detail-cache.js` отменяет
устаревшие запросы и хранит четыре завершённых результата на 15 секунд; изменения
сбрасывают кэш. `review-panels.js` содержит оценивание с локальным черновиком
обратной связи и анализ авторства. `components/code-checking.js` отвечает
за канонические ссылки, список учеников и переходы без принудительной прокрутки.
Компоновка и адаптация находятся в общем `_code-checking.scss`.
Требования, ограничения истории и сценарии — в [task-checking-flows.md](ux/task-checking-flows.md).
