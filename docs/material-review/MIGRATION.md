# Перенос накопленного ревью

Исходная мастерская: `/Users/roctbb/PycharmProjects/codingprojects_lessons/tools/audit-reviewer`. Основной источник — полная `.data/review.sqlite3`, а не выгрузка решений. Рабочий Python-сервер не переносится.

## Последовательность

1. Подготовить отдельную тестовую базу Coding Projects. Использовать синтетические материалы либо отдельно подготовленную тестовую копию. Проверить соединение до любой записи.
2. Выполнить предварительный отчёт:

```bash
php artisan materials:review legacy-plan --actor=ADMIN_ID --sqlite=/path/review.sqlite3
```

3. Изучить таблицы, предложения и `unmapped`. Для источника задать постоянный `source_id`, который сохраняется при последующих копиях и запусках.
4. Составить JSON-сопоставление по [examples/legacy-mapping.json](examples/legacy-mapping.json). Для каждого файла или его устойчивого ID указать `program_id`, `lesson_id`, `entity`, `id`, `field`. Для предложений без файловой привязки использовать `proposal_targets`: массив целей в порядке связанных частей. `lessons` задаёт контекст вопросов и планов. `images` позволяет явно привязать исторический вариант изображения.
5. Сверить соответствия с актуальными снимками платформы и сохранёнными результатами прежней публикации с ID. Совпадение названий не является основанием для привязки.
   Если цель менялась между редакциями предложения, укажите её в `versions[proposal_id][fingerprint][part_index]`. У такого соответствия приоритет над общей целью предложения и файла. Для уже опубликованной редакции можно передать `publications[proposal_id][fingerprint]` со списком полей. Каждая запись содержит ту же цель и `sha256` полного опубликованного значения поля из журнала публикации. Адаптер сверяет текущие значения всех перечисленных полей и проверяет, что автор принял именно эту редакцию. Расхождение возвращает версию к обычной проверке фрагментов.
6. Повторить предварительную проверку с сопоставлением:

```bash
php artisan materials:review legacy-plan --actor=ADMIN_ID --sqlite=/path/review.sqlite3 --mapping=/path/mapping.json
```

7. После проверки отчёта выполнить импорт **в тестовую базу**:

```bash
php artisan materials:review legacy-import --actor=ADMIN_ID --sqlite=/path/review.sqlite3 --mapping=/path/mapping.json
```

8. Повторить команду, проверить отсутствие дублей, открыть редакции в интерфейсе, сверить решения и изображения. Проверить `materials:review validate` для каждого черновика. Опубликованное содержание тестовой платформы должно остаться прежним.
9. Настоящий перенос и развёртывание выполнить отдельным этапом после проверки отчёта. Команда импорта не публикует.

## Что сохраняется

Все таблицы источника архивируются в `material_review_legacy`, включая исходное имя таблицы, стабильный ключ строки и типизированный JSON. Двоичные значения сохраняются в base64 с указанием кодировки. В частности сохраняются `source_files`, `source_versions`, `proposal_versions`, `choices`, `choice_events`, `author_edits`, `image_variants`, `image_reviews`, `builds`, `operations`, `mappings`, каталоги и документы аудитов.

Сопоставленные предложения становятся предложениями платформы с первоначальным решением и заметкой автора. Авторские изменения также присутствуют в `proposal_versions` прототипа и проходят тот же адаптер. При отсутствии исходного обоснования используется пометка **«Причина не указана в исходном аудите»**. Исходный текст аудита сохраняется в происхождении.

Изображения сохраняются отдельными версиями ресурсов. Оригинальные BLOB и связи между вариантами остаются в полном архиве даже без разрешённого соответствия программе. Повторная передача того же источника и строки не создаёт дубля. Привязки сохраняются отдельно от исходной истории.

## Статусы отчёта

- `ready`: операция имеет явную цель и точный фрагмент применим к актуальному снимку.
- `already_applied`: полное состояние изменяемых полей совпало с результатом воспроизведения операций на сохранённом исходнике. Такое принятое предложение не включается в повторное применение.
- `stale_base`: точная операция не воспроизводится на актуальном состоянии. Решение автора сохраняется, публикация блокируется.
- `mapping_error`: отсутствует явное соответствие либо цель не найдена в указанной программе.
- `question`: нужно решение автора без готового изменения.
- `plan`: структурная рекомендация ещё не содержит готового материала.
- `image_usage_required`: варианты изображения сохранены и видны, но для применения нужно явно указать место использования. Для такого изображения добавьте в его сопоставление поле `old` с точной ссылкой в материале; для нескольких мест — `uses` со списком полных целей и ссылок. Выбранные автором исторические варианты сохраняются по ID из решения.

Отсутствие старого фрагмента не считается доказательством публикации. Локальная запись файлов в прототипе также не доказывает изменение таблиц учебной платформы. Состояния сборок и публикаций сохраняются как исторические свидетельства, а не как команда повторного применения. Уже выполненное на платформе изменение следует подтвердить полной сверкой основы и результата; такие неоднозначности остаются на ручном разборе.

Исходная SQLite открывается `SQLITE3_OPEN_READONLY`. Адаптер вызывает SQLite backup, читает и удаляет только собственную временную копию. Не нужно останавливать мастерскую ради согласованного чтения. Для полноценного внешнего резервного хранения мастерской дополнительно сохраняют всю `.data` по её собственной инструкции.
