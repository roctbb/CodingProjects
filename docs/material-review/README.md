# Ревью учебных материалов

Административный раздел: `/insider/material-review`. В меню пользователя: **Ресурсы → Ревью программ**. Разработка и проверки выполняются на синтетических SQLite-базах. Рабочая база, сайт, курсы и исходная SQLite-база локальной мастерской при разработке не изменяются.

## Рабочий процесс

1. Выбрать программу, урок и черновую редакцию. Курсы показываются как область воздействия общей программы.
2. Разбирать предложения по уровням: **замысел урока**, **структура и содержание**, **локальная редактура**. Характер предложения задаётся независимо: ошибка, учебная трудность, стиль, вопрос.
3. Сначала выбрать редакцию урока. Альтернативы можно сравнить с основой и между собой. Независимые изменения переносятся отдельным явным действием; пересекающиеся изменения блокируются.
4. Принять, отклонить или отложить предложение. Вопросы и структурные планы без готового содержания не имеют действия принятия исполняемой правки. Ответы сохраняются отдельно от ученического материала.
5. Ручные изменения сохраняются отдельными авторскими предложениями с историей и отменой. Изменение предложенного варианта создаёт новую версию, которую нужно рассмотреть заново. Редактор Jupyter работает с ячейками и допускает добавление текстовой ячейки.
6. Просмотреть итоговый материал, различия, план урока, затронутые задачи и курсы. Отдельно опубликовать выбранную редакцию.
7. **Завершить и перейти к следующему** сохраняет прогресс разбора, но не публикует. Новые предложения открывают разбор урока заново. Есть отдельный переход без завершения.

Принятие предложения, выбор редакции, завершение разбора и публикация — разные действия. До публикации обычные страницы и Markdown/Jupyter-экспорт продолжают использовать прежний материал.

Интерфейс использует существующую оболочку сайта, заголовки, кнопки и семантические токены оформления. На широком экране материал находится между навигацией и предложениями; на узком экране боковые панели сворачиваются. Обоснования и комментарии раскрываются по запросу, изменения текста показываются непосредственно в материале. Стили ограничены разделом ревью и его диалогами.

## Архитектура

- `Program`, `Lesson`, `ProgramStep`, `Task` остаются источником опубликованного содержания. Веб-интерфейс и Artisan используют `App\MaterialReview\Review`, `Plan`, `Documents`, `Publishing`, `Resources` и `LegacyImport`.
- `material_review_revisions` содержит неизменяемые полные снимки уроков с ID, порядком, всеми отдельными задачами, настройками проверки и использованием ресурсов. Notebook-ступени не исключают отдельные задачи из снимка.
- `material_review_drafts` содержит набор основ, выбранное состояние и монотонную версию. Один черновик может охватывать несколько уроков одной программы. Несколько черновиков от одной основы являются альтернативами.
- `material_review_proposals` хранит версии предложений, обоснования, зависимости, альтернативы и решение автора. Пригодность рассчитывается независимо от решения. Поэтому принятое предложение может оставаться конфликтным.
- `material_review_events` сохраняет действия и данные версий. Принятые предложения воспроизводятся в стабильном порядке с проверкой зависимостей. Восстановление не требует модели.
- `material_review_publications` хранит состояние до и после применения, соответствия временных ключей, изменения оценок и дедлайнов. Черновик публикуется однократно.
- `material_review_resources` хранит неизменяемые версии файлов, оригинальные и безопасные данные, MIME и SHA-256. `material_review_progress` хранит общий прогресс по программе и уроку.
- Обычные Eloquent-редакторы сохраняют опубликованный материал сразу. Наблюдатель фиксирует версии. Проверка перед публикацией повторно читает реальные таблицы и обнаруживает также изменения, сделанные в обход наблюдателя.

Для сравнения используется структура идентичностей: поля урока, ступеней и задач, принадлежность, порядок, архивирование и настройки проверки. Трёхстороннее сравнение накладывает только изменённые поля на актуальное содержание. Независимая ручная правка другого поля сохраняется. Изменение затронутого поля, состава или порядка вызывает явный конфликт. Похожие фрагменты автоматически не подбираются.

Публикация блокирует программу и затронутые сущности, повторяет проверку и выполняется одной транзакцией вместе с пересчётом статистики. Временные ключи разрешаются в постоянные ID один раз. Существующие ID, попытки, тесты и независимые настройки сохраняются. Пересчёт при публикации не выдаёт награды и не вызывает модель.

## Правила задач и истории

- Исключение задачи означает скрытие. Исключение ступени архивирует её и скрывает оставшиеся задачи. Переименование и перенос сохраняют ID. Скрытые задачи сохраняют существующее правило видимости для учеников с попытками; архивная ступень доступна как история без новой сдачи.
- При уменьшении максимума текущая оценка ограничивается новым максимумом. Исходные результаты проверки и штрафы сохраняются; отдельное ограничение сохраняется и при последующих действиях над старой работой. Увеличение максимума не добавляет баллы старой работе: ученик сдаёт новую попытку.
- Общий XP и статистика пересчитываются. Уже выданные монеты, достижения и сохранённые итоги завершённых курсов не отзываются и не выдаются заново.
- У новых отправленных работ сохраняется снимок условия. Для исторических работ без достоверного снимка версия отмечается неизвестной. Собственная история доступна после переноса задачи в закрытый урок; новые попытки используют доступность нового урока.
- Новые формы отправляют версию условия. При конфликте введённый текст сохраняется в браузере. Старые клиенты без версии продолжают работать; для защиты от устаревшего условия им следует передавать `material_revision` или `X-Material-Revision`.
- При переносе задачи дедлайн нового урока имеет приоритет; при отсутствии такого правила сохраняется прежняя фактическая цепочка задачи. Расчёт выполняется для каждого курса. Снимки дедлайнов уже отправленных работ сохраняются.
- Восстановление публикации создаёт новый проверяемый черновик. Новые сущности исключаются из маршрута с сохранением попыток. Восстановление ограниченных оценок блокируется, если эти оценки позднее изменили.

## Интерфейс для Codex

Команда возвращает одну строку JSON: `{"ok":true,"data":...}` либо `{"ok":false,"error":"...","message":"...","details":...}` и ненулевой код завершения. Нужен `--actor` с ID администратора. Эта проверка применяется и к чтению приватных снимков.

```bash
php artisan materials:review catalog --actor=ADMIN_ID
php artisan materials:review snapshot --actor=ADMIN_ID --lesson=LESSON_ID
php artisan materials:review revision --actor=ADMIN_ID --revision=REVISION_UUID
php artisan materials:review create --actor=ADMIN_ID --input=create.json
php artisan materials:review propose --actor=ADMIN_ID --draft=DRAFT_UUID --draft-version=VERSION --input=proposal.json
php artisan materials:review update --actor=ADMIN_ID --draft=DRAFT_UUID --draft-version=VERSION --input=update.json
php artisan materials:review validate --actor=ADMIN_ID --draft=DRAFT_UUID
php artisan materials:review feedback --actor=ADMIN_ID --draft=DRAFT_UUID
php artisan materials:review resource --actor=ADMIN_ID --input=resource.json
php artisan materials:review export --actor=ADMIN_ID --draft=DRAFT_UUID
php artisan materials:review import --actor=ADMIN_ID --input=package.json
```

`--input=-` читает стандартный ввод. `--draft-version` обязателен при добавлении предложения или обновлении черновика. После изменения нужно прочитать новую версию из ответа. Для сохранения повторного запроса используйте устойчивый ID черновика и `external_id` предложения. Новое содержание с тем же внешним ID сохраняется новой версией, прежнее решение остаётся в истории.

В Artisan отсутствует действие публикации. Модель читает материалы и обратную связь, подготавливает предложения и черновики. Администратор публикует через браузер.

Схема: [v1.schema.json](v1.schema.json), JSON Schema 2020-12. Определения: `create`, `proposal`, `update`, `document`, `operation`, `resource`, `package`, `mapping`. Валидация принадлежности, полноты сущностей, версии, зависимостей и прав выполняется сервисом платформы дополнительно к форме JSON.

Примеры в [examples](examples):

- `create-draft.json`, `local-proposal.json` — черновик и точная локальная правка;
- `structure-proposal.json` — новая ступень, перенос существующей задачи и связанное изменение заметок;
- `full-edition.json` — полная альтернативная редакция;
- `question.json` — обсуждение замысла без готовой замены;
- `notebook-proposal.json`, `image-proposal.json` — ячейка Jupyter и конкретное использование иллюстрации;
- `update-draft.json` — ручная правка с ожидаемым значением поля;
- `legacy-mapping.json` — явное сопоставление наследуемых файлов и предложений.

ID и UUID в примерах условные. Полную редакцию следует готовить из реального снимка: в ней перечисляют **все** существующие ступени и задачи, включая скрытые и notebook-задачи. Пропущенные поля существующей сущности наследуются от основы; явный `null` задаёт новое значение. Пропущенные сущности вызывают ошибку, а не удаление. Для исключения ступени используются `archived` и явная судьба задач; для задачи — скрытие или перенос. Новые сущности имеют ключи `new:имя`.

`checking` сохраняет настройки и ссылки на версии проверки. Пропуск этого поля наследует основу. Изменения конфигурации проверки сохраняются отдельным предложением `kind: unsupported` с описанием требуемой настройки; их нельзя принять как готовое исполняемое изменение. Новая задача по умолчанию имеет ручной способ проверки. Существующие тесты и настройки не пересоздаются.

Для переноса частей полной редакции можно объявить `transfer_groups`: ID, название, обоснование и полный набор путей изменений из результата проверки. Связанные поля включают в одну группу; пересекающиеся группы запрещены. Без такого объявления полная редакция рассматривается целиком. Самостоятельные принятые предложения доступны для переноса как логические группы. При переносе нескольких независимых групп сохраняются отдельные предложения и зависимости.

Для Jupyter предпочтителен `cell_id`. Индекс используется только в контексте конкретной основы. Изменённая кодовая ячейка теряет прежние результаты и счётчик выполнения; другие ячейки, метаданные и вложения сохраняются. Никакой код не исполняется при импорте, просмотре или принятии.

## Ресурсы и архивные пакеты

Загрузка ресурса принимает `program_id`, `name`, base64-поле `data` и при необходимости MIME/UUID. Поддерживаются PNG, JPEG, GIF, WebP, SVG, PDF и обычный текст размером до 20 МБ. SVG очищается от активного содержания и внешних зависимостей; оригинал сохраняется отдельно. Активный оригинал не отдаётся через маршрут просмотра.

Снимки фиксируют локальные иллюстрации из каталога `public` и локального диска платформы, не переписывая исходные файлы. Ресурсы из пользовательских папок не читаются. Внешние URL и недоступные ресурсы отмечаются `captured: false`: платформа не загружает произвольные сетевые адреса. Встроенные изображения и результаты Jupyter находятся в снимке тетрадки.

Экспортированный пакет содержит идентификатор установки, снимок, основы, итоговую редакцию, все предложения и решения, события, историю редакций и публикаций, журналы ограничений оценок и дедлайнов, относящийся к черновику архив прототипа и используемые ресурсы с двоичными данными. Команда печатает оболочку `ok/data`; для последующего импорта сохраните непосредственно объект `data`. Например, обработайте вывод штатным JSON-инструментом, не редактируя опубликованные таблицы SQL.

Архив имеет подпись установки: его нельзя редактировать и затем импортировать как историю решений автора. Новые и изменённые материалы передают через `create`, `propose` и `update`. При переносе самой установки нужно сохранить её идентификатор и ключ подписи в резервной копии базы. Максимальный JSON-пакет — 256 МБ.

Пакеты другой установки отклоняются. Одинаковые числовые ID из независимых баз не сопоставляются автоматически. Для переноса на другую установку необходим отдельный проверенный план соответствия идентичностей; простая подмена `installation_id` недопустима. Архивы ZIP не распаковываются: базовый перенос выполняется JSON-пакетом с base64-ресурсами, поэтому пути файлов из пакета не используются для записи в файловую систему.

## Перенос локальной мастерской

Подробности: [MIGRATION.md](MIGRATION.md). Адаптер открывает исходную SQLite только для чтения, создаёт согласованную копию через SQLite backup и работает с копией. Он сохраняет все строки всех таблиц, включая BLOB, версии источников, авторские правки, события решений, сборки, публикации и варианты изображений.

Явное сопоставление определяет программу, урок, тип сущности, постоянный ID и поле. Названия не используются как доказательство соответствия. Неоднозначные связи попадают в отчёт. Принятые устаревшие изменения остаются принятыми, но конфликтными; отклонённые не возвращаются в ожидающие. Никакой перенос сам по себе не публикует материал.

## Проверки и запуск

```bash
php artisan test --compact --filter=MaterialReviewTest
php artisan test --compact
npm run build
node scripts/ui-checks/material-review.mjs
```

Тест модуля создаёт схему во временной SQLite в памяти и применяет новую миграцию только туда. Браузерный сценарий создаёт собственную синтетическую базу и сервер на свободном порту `127.0.0.1`, подменяет внешние вызовы и закрывает только свои процессы. Требуются PHP SQLite3, DOM, Fileinfo, Composer-зависимости, Node.js и Playwright CLI. `npx --yes --package @playwright/cli playwright-cli install-browser` устанавливает браузер, если его ещё нет.

Артефакты браузерной проверки: `output/playwright/material-review/`: изображения широкого и узкого экранов, отчёт и журнал тестового сервера. Данные не входят в Git. Примеры JSON также проверяются по опубликованной схеме.

Результаты выполненных проверок: [VALIDATION.md](VALIDATION.md).

Новую миграцию необходимо применить при отдельном развёртывании. До её применения раздел возвращает понятный статус недоступности; стандартные редакторы и учебные страницы продолжают работать. Во время разработки миграция к рабочей базе не применяется.

## Границы первой версии

- Генерация аудитов и изображений выполняется снаружи сайта.
- Одновременная работа нескольких авторов не имеет отдельного пользовательского процесса; версии защищают от устаревших вкладок и внешних изменений.
- Полная перестройка глав и программ, независимые программы для отдельных курсов и перенос идентичностей между установками требуют отдельных действий.
- Неподдерживаемые настройки проверки остаются видимыми рекомендациями. Автоматическая семантическая проверка соответствия нового условия существующим тестам не выполняется: это предмет ревью.
- Старые работы без сохранённого условия не получают выдуманную историческую редакцию. Недоступные внешние файлы нельзя включить в воспроизводимый архив без предоставления их содержимого.
