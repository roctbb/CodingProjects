# Памятка для чата в проекте конспектов

Опубликованные материалы находятся в модели данных Coding Projects. Локальные Markdown/Jupyter — экспорт и архив. Не редактируй опубликованные таблицы SQL и не публикуй предложения от имени автора.

1. На сервере Coding Projects выполни `php artisan materials:review catalog --actor=ADMIN_ID`. Получи `installation_id`, программу, главы, уроки и связанные курсы.
2. Прочитай урок: `php artisan materials:review snapshot --actor=ADMIN_ID --lesson=LESSON_ID`. Используй полученный ID базовой редакции. В снимке есть все ступени и задачи, включая отдельные задачи notebook-ступеней, настройки и ресурсы.
3. Передай модели снимок вместе с программой, главой, контекстом связанных курсов и учебными целями из материалов. Для переноса между уроками прочитай каждый затрагиваемый урок и включи все основы в один черновик.
4. Создай черновик по `docs/material-review/examples/create-draft.json`: `php artisan materials:review create --actor=ADMIN_ID --input=create.json`. Сохрани UUID и версию ответа.
5. Сохрани локальное предложение: `php artisan materials:review propose --actor=ADMIN_ID --draft=DRAFT_UUID --draft-version=VERSION --input=proposal.json`. Укажи устойчивый `external_id`, короткую причину, `scope` и `intent`. Масштабы: `lesson` — замысел, `structure` — структура и содержание, `local` — локальная редактура. Характер: `error`, `learning`, `style`, `question`.
6. Для полной альтернативы создай отдельный черновик с теми же основами и полным `targets`. Начинай с реального снимка. Сохрани ID всех прежних ступеней и задач, явно укажи скрытие и архивирование, новым сущностям дай `new:ключ`. Не используй отсутствие сущности как удаление. Общая причина должна объяснять новый ход урока; независимые логические изменения оформляй отдельными предложениями с собственными причинами.
7. Прочитай обратную связь: `php artisan materials:review feedback --actor=ADMIN_ID --draft=DRAFT_UUID`. Решения, комментарии и история находятся в ответе. Для следующего варианта сохрани новое содержание предложения; прежнее решение не переносится автоматически. Ручное обновление черновика использует `update` с актуальным `--draft-version` и обоснованием.
8. Проверь результат без публикации: `php artisan materials:review validate --actor=ADMIN_ID --draft=DRAFT_UUID`. Исправь ошибки принадлежности, версий, точных фрагментов, зависимостей и структуры. Не подбирай похожий абзац автоматически. Код и графики подготавливай снаружи; импорт их не исполняет.
9. Накопленную мастерскую переносит `legacy-plan`, затем `legacy-import` с полной SQLite и проверенным JSON-сопоставлением. Начинай с тестовой базы и инструкции `docs/material-review/MIGRATION.md`. Выгрузка только решений не заменяет историю и изображения.

Для чтения ответа команды учитывай оболочку `ok/data`. Схема и примеры: `docs/material-review/v1.schema.json`, `docs/material-review/examples/`. Веб-ревью доступно администратору по `/insider/material-review`; принятие, завершение и публикация — отдельные действия.
