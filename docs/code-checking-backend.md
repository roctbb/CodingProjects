# Серверная интеграция с GeekExecutor

Coding Projects — источник задач, приватных критериев, тестов, исходников,
файлов, результатов, покупок и проверок плагиата/AI. Отдельный проект
`/Users/roctbb/PycharmProjects/GeekExecutor` занимается только исполнением.
Фронтенд подключён в выбранном варианте «В уроке»: загрузка готовой работы,
необязательный редактор, результаты и история рядом с условием.
[UX и награды](ux/code-submissions-design.md).

[Аудит полноты переноса GeekPaste и границы S3](geekpaste-migration-audit.md)
описывает обнаруженные незакрытые пункты. Наличие команды импорта не означает
готовность к удалению старого учебного хранения.

[Изолированный стенд и проверенные сценарии](executor-qa.md) — запуск Coding
Projects, GeekExam и GeekExecutor с настоящими Docker, Celery, WebSocket и S3.

## Развёртывание первого этапа

Выполнить обычные Laravel-миграции. Новая миграция
`2026_11_14_120000_create_code_checking_tables.php` и
`2026_11_14_130000_expand_task_submissions.php` создают/дополняют отдельные таблицы и
не удаляет старые решения. Настроить:

```dotenv
GEEKEXECUTOR_URL=https://executor.example
GEEKEXECUTOR_SOCKET_URL=https://executor.example
GEEKEXECUTOR_SECRET=отдельный-случайный-секрет-не-короче-32-символов
CODE_EXECUTOR_CALLBACK_URL=https://codingprojects.example
CODE_AI_DETECTION_ENABLED=true
```

Первый адрес доступен серверу, второй — браузеру. На стороне исполнителя
`CODING_PROJECTS_URL` должен совпадать с публичным `APP_URL` Coding Projects;
`JWT_SECRET` совпадает с `GEEKEXECUTOR_SECRET`. Без отдельной настройки для
обратной совместимости используется `auth.jwt_secret`; для развёртывания
рекомендуется отдельный ключ, которого нет у лёгкого GeekPaste. URL файлов и callbacks проверяются
по allowlist origin. Работники Laravel и scheduler должны быть запущены.
Для файлов увеличены лимиты PHP/nginx до 50/55 MiB; внешний reverse proxy тоже
должен пропускать такие запросы. Все данные лежат на приватном диске
`storage/app-private/code-checking`, отдельно от публичного `/media`.

Не включать новую сдачу для старой задачи, пока для неё не сохранена закрытая
конфигурация и не выполнено преобразование старого environment-checker в IO.
В редакторе задачи нужно выбрать «Сдача в Coding Projects» и сохранить конфигурацию.

## API интерфейса

Все `/insider` маршруты требуют сессию, подтверждённую учётную запись и CSRF
для изменений. Права проверяются сервером: свой курс, принадлежность задачи
программе курса, авторство решения либо преподавание в этом курсе.

| Маршрут | Доступ и назначение |
|---|---|
| `GET /insider/courses/{course}/tasks/{task}/checker` | Открытые параметры формата сдачи |
| `GET/PUT …/checker/private` | Преподаватель: язык, тип проверки, приватные инструкции, эталон, IO-тесты и лимиты, разрешение покупки |
| `POST …/checker/fixtures` | Преподаватель: большой файл теста, до 32 MiB |
| `GET/POST …/code-submissions` | История / новая попытка; `request_id` UUID и `code`, `file` или `files[]` |
| `GET /insider/code-submissions/{uuid}` | Код, файлы, состояние, результат, разрешённые тесты и подписка |
| `GET …/{uuid}/files/{index}` | Оригинальный файл с повторной проверкой прав |
| `GET …/{uuid}/subscription` | Обновление токена Socket.IO |
| `POST …/{uuid}/recheck` | Преподаватель; по умолчанию прежний снимок, `latest_configuration=true` — текущая конфигурация |
| `POST …/checker/extra-attempt` | Дополнительная GPT-попытка после исчерпания часового лимита |
| `GET /insider/code-test-reports/{run}` | Отфильтрованный отчёт |
| `POST …/{run}/tests/{test}/purchase` | Открытие теста; необязательное `expected_price` |
| `GET …/{run}/tests/{test}/{field}` | Скачивание разрешённого поля `input/expected/actual/error` |
| `GET /insider/settings/code-executor/status` | Только администратор, статус исполнителя |

Приватная конфигурация — отдельная модель, исключённая из обычной сериализации.
Пример записи:

```json
{"language":"cpp","check_type":"tests","test_mode":"io","private_instructions":"…","allows_test_reveals":true,"test_config":{"tests":[{"is_public":false,"input":"2 3\n","output":"5\n"}]}}
```

`input/output` также принимают дескриптор файла, полученный из `checker/fixtures`.
Большие значения не копируются в каждый снимок: хранится SHA-256 и размер.
Файлы и критерии неизменяемого запуска сохраняются отдельно от редактируемой
задачи. Новые попытки используют новые настройки, обычная перепроверка — старые.

Сдача принимает до 2 MiB текста/исходника на поле и до 50 MiB файлов суммарно.
По умолчанию 20 файлов, преподаватель может разрешить до 100. Формат сдачи,
язык и тип проверки независимы. `submission_modes`: `text`, `files`, `code`
(один исходник), `project` (несколько исходников), `repository`. Язык
`text` подходит для текста, Excel и изображений. Старые значения языка
`ipynb/zip/image/xlsx/github` принимаются как совместимые псевдонимы формата.

Пример многофайловой сдачи:

```json
{"request_id":"UUID","mode":"project","language":"python","text":"Пояснение","editor_files":[{"path":"main.py","content":"from lib import f\nprint(f())"},{"path":"lib.py","content":"def f(): return 42"}]}
```

Multipart: `files[]`, соответствующие `file_paths[]` для вложенных путей,
`mode`, `language`, `text`, `request_id`. JSON `files` может использоваться
как псевдоним `editor_files`. `allowed_extensions`, `allowed_languages`,
`max_files/max_file_bytes/max_total_bytes` ограничивают допустимую сдачу.

Репозиторий сдаётся как `mode=repository`, `repository_url`, необязательный
`repository_ref`. Поддерживаются публичные репозитории GitHub. Coding Projects
сам фиксирует SHA коммита, сохраняет ZIP и файлы с ограничениями размеров и
путей; повторная доставка использует зафиксированный SHA. Состояние
`preparing` видно до отправки исполнителю. Произвольные URL, приватные
репозитории, симлинки и небезопасные пути не принимаются. Исполнитель не ходит
в GitHub. Python использует стандартную библиотеку, C++ — C++17; произвольные
Dockerfile/скрипты сборки и установка зависимостей не исполняются.

### Дополнительные серверные ручки

| Маршрут | Назначение |
|---|---|
| `GET/POST …/checker/files` | Файлы условия, шаблоны и ресурсы; запись преподавателем |
| `GET/DELETE …/checker/files/{id}` | Скачать с проверкой доступа / мягко удалить |
| `GET …/checker/fixtures/{sha256}` | Скачать файл теста, принадлежащий этой задаче |
| `GET …/checker/legacy` | Преподавателю: исходные определения перенесённых задач |
| `GET/PUT/DELETE …/code-draft` | Черновик / сохранить / восстановить шаблон |
| `GET …/code-draft/files/{index}` | Загруженный файл своего черновика |
| `POST …/code-submissions/recheck-latest` | Преподавателю: последние решения каждого ученика |
| `PUT /insider/code-submissions/{id}/grade` | Ручная оценка и комментарий преподавателя |
| `GET …/{id}/runs/{run}` | Исторический запуск, полный снимок только преподавателю |
| `GET …/{id}/task-files/{index}` | Файлы задания из неизменяемого снимка |
| `GET …/{id}/repository/archive` | Оригинальный ZIP зафиксированного репозитория |
| `GET …/{id}/legacy-source` | Оригинальная сериализация старого решения |
| `PUT …/{id}/integrity/review` | Преподавателю: снять/вернуть предупреждение, закрытый комментарий |

У файлов задания `kind=attachment/starter/resource`. `is_public` управляет
доступом ученика, `include_in_check` — передачей в AI-проверку.
`read_only` у starter запрещает подмену. Скрытые файлы разрешены только как
attachments: ресурсы, доступные выполняемому коду, должны быть публичными.
Тесты и приватные критерии никогда не монтируются внутрь ученической песочницы.

Черновик использует `revision`: каждый PUT/DELETE требует текущую ревизию,
конфликт возвращает 409. Для сохранения загруженных файлов передаются их
индексы `keep_files` и `draft_revision`; передать чужой blob ID нельзя.
Сдача черновика: `use_draft=true`, `draft_revision`, `request_id`. Черновик
не запускает проверку и не расходует платные попытки. Сдача замораживает файлы,
шаблоны, условие и закрытые настройки; редактирование задачи их не меняет.

Ручная проверка хранится локально (`awaiting_review`), без запуска исполнителя.
Сбой выполнения не применяет нулевую оценку. При перепроверке прежняя оценка
сохраняется до нового результата; ID исторического запуска остаётся доступен.

## Данные и покупки

Служебный API находится под `/api/executor`, принимает подписанные callbacks
с проверкой purpose, audience, TTL и SHA-256 точных байтов тела. JSON разбирается
из исходного тела: Laravel TrimStrings/ConvertEmptyStringsToNull не меняют
значимые пробелы, переносы и пустые ответы тестов.

Каждый запуск имеет UUID. Повтор отправки с тем же `request_id` не создаёт
вторую попытку. Outbox Laravel повторяет передачу задания; результат
применяется один раз под блокировкой запуска. Поздние события не открывают
завершённый запуск, старый результат не подменяет текущую перепроверку.
`code-checking:recover` восстанавливает незавершённую отправку; scheduler
вызывает его каждую минуту.

Типовой отчёт содержит номер, идентификатор содержимого теста, публичность,
вердикт, ввод, эталон, фактический вывод и ошибку. Короткие поля идут в JSON,
длинные — отдельными файлами; сначала подтверждается наличие файлов. Один и
тот же большой ввод/эталон хранится один раз. Усечённый вывод отмечен отдельно.

Ученик получает только статусы закрытых тестов. Ни данные, ни превью, ни
идентификаторы файлов закрытых полей в ответ не включаются. Преподаватель
получает полный отчёт. Покупка открывает конкретную версию теста навсегда
для ученика и задачи, включая следующие попытки; перестановка не меняет
покупку. Меняются данные, способ сравнения или лимиты — меняется версия.

Цена — `code_test_reveal` в системном магазине, по умолчанию 5 GC. Кошелёк,
списание и право доступа обновляются одной транзакцией под блокировкой
пользователя. Повторная покупка не списывает деньги. Нельзя купить публичный,
пройденный тест, ошибку компиляции/инфраструктуры, тест другого ученика,
заблокированной задачи или задачи с отключёнными покупками. Оценка не меняется.

Если ученик спрашивает в чате о тестах, помощник может бесплатно открыть примеры из завершённой проверки его решения. Число бесплатных открытий на ученика и задачу ограничено формулой `min(3, floor(N / 3))`, где `N` — число тестов в отчёте. При восьми тестах доступны два примера, при девяти — три. Если подходящих непройденных тестов меньше, чат показывает только их. Разрешение преподавателя на открытие тестов действует и для помощника.

В чате появляются короткие фрагменты ввода, ожидаемого и фактического вывода. Полные данные доступны в отчёте. Сервер сохраняет право доступа по идентификатору содержимого теста в `code_test_purchases` с признаком `from_tutor`. Оно действует и после новой посылки. Покупка ранее открытого примера стоит ноль монет.

Проверки плагиата и AI запускаются отдельным Laravel job и не участвуют в
выставлении оценки. Сходство ищется среди решений других авторов той же задачи
по токенным отпечаткам; собственные повторные попытки исключены. Данные
совпавших чужих решений доступны только преподавателю. AI-анализ — рекомендация
для проверки преподавателем, а не утверждение об авторстве. Изображения/XLSX
и несохранённые GitHub-репозитории пропускаются при анализе исходного кода.
Тетрадки больше 8 MiB также пропускаются этим анализом; сама AI-проверка
решения остаётся доступной. Число отпечатков ограничено 4096 на попытку.

## WebSocket без polling

Ответ сдачи/просмотра содержит `subscription`: URL, namespace `/executions`,
событие `execution_progress`, `execution_id`, `token`, `expires_at`.
Браузер подключается напрямую к GeekExecutor, передаёт `auth.token`,
использует `transports: ['websocket']`. Дополнительных запросов к Coding
Projects на каждый этап нет.

События: `queued → preparing → compiling → testing → publishing → completed`,
для AI — `grading`, для неуспеха инфраструктуры — `error`. Счётчики обозначают
количество завершённых тестов. Данные тестов в канал не передаются. Последнее
состояние отправляется при каждом подключении. После `completed/error`
интерфейс один раз получает сохранённое решение из Coding Projects.

## Последующие этапы переноса

Администратор входит в консоль GeekExecutor по
`/insider/settings/code-executor/login` или через главную исполнителя.
В `GEEKEXECUTOR_PUBLIC_URL` нужен адрес, доступный браузеру; `GEEKEXECUTOR_URL`
может быть внутренним. Секрет `GEEKEXECUTOR_SECRET` должен совпадать с
`JWT_SECRET` исполнителя. Только роль `admin` может получить подтверждение
`executor-login` (60 секунд, audience `geekexecutor`, привязка к state браузера).
Callback фиксирован конфигурацией; произвольный `redirect_url` не используется.
Изменений интерфейса Coding Projects для этого входа не требуется.

1. Развернуть GeekExecutor и эту серверную версию Coding Projects; сохранить
   старую БД GeekPaste. Новые academic-проверки направляются в новый сервис.
2. Экспортировать старые данные командой GeekPaste
   `flask export-academic-storage --output /private/new-export-directory`.
   Экспорт содержит tasks/solutions/similarities JSONL, исходные артефакты,
   доступные оригиналы ZIP, оценки, даты, комментарии и отметки AI/плагиата.
   Manifest хранит количества и хеши; отсутствующие исторические ZIP отмечены.
   Экспорт не меняет БД и не затирает существующий каталог.
3. Запустить подготовленный импорт (см. ниже), сопоставить пользователей,
   курсы, задачи и старые ссылки; конвертировать environment-тесты и репозитории,
   сверить файлы и количества. Старый вывод скрытых тестов, который никогда не
   сохранялся, восстановить из экспорта невозможно; новая проверка создаёт
   полноценный отчёт.
4. Только после сверки и резервной копии добавить удаляющую миграцию GeekPaste.
   В текущем изменении нет ни импорта production-данных, ни их удаления.

## Подготовленный импорт старых решений

Сначала проверить экспорт без записи:

```bash
php artisan code-checking:import-legacy /private/export --map=/private/map.json --source-timezone=UTC
```

`map.json`: `{"tasks":{"старый ID":12},"courses":{"старый ID":7},"users":{"старый ID":2}}`.
Сопоставление задач обязательно; курсы и пользователи по умолчанию сохраняют ID.
Указать реальный часовой пояс старого сервера, если даты в экспорте не UTC.
Команда проверяет manifest, SHA-256 всех JSONL и исходных blob, сопоставления
и конфликт с ранее импортированным определением. Повторный импорт имеет
детерминированные UUID и не дублирует решения.

Запись включается только явно: добавить `--apply --actor=<ID администратора>`.
Команда сохраняет старые исходники, ZIP при наличии, оценки запуска, даты,
критерии, результаты анализа авторства и совпадения. Существующие Solution
связываются по старому ID; их оценки и даты не пересчитываются. Новые XP,
монеты и AI-запросы не создаются. Если текущая конфигурация задачи уже задана,
импорт её не перезаписывает. Environment-checker помечается
`requires_conversion` и не запускается до явного перевода в IO. Исторические
данные, которых не было в старом хранилище, не восстанавливаются выдуманными.
Команда не меняет и не удаляет БД GeekPaste. Production-импорт выполняется
отдельно после развёртывания и сверки.

## Интерфейс и награды

Редактор преподавателя поддерживает ручную проверку, тесты и ИИ, способы
сдачи, языки, расширения и ограничения файлов, приватные критерии, эталон,
материалы и шаблоны. Для тестов доступны правила сравнения, обработка
завершающих пробелов, абсолютная/относительная погрешности, лимиты времени,
памяти, вывода, процессов и swap. Каждый тест может переопределить сравнение,
время и объём вывода; пустое поле наследует общее значение.

В режиме групп преподаватель задаёт названия и баллы, затем распределяет
тесты. Группа засчитывается целиком, если пройдены все её тесты. Сумма баллов
должна равняться максимуму задания; пустые группы и тесты без группы мешают
сохранению с объяснением ошибки. После исправления форму можно сохранить без
перезагрузки. Файл ввода/эталона хранится в БД и сохраняет точные байты при
редактировании остальных настроек. Ученику приватная конфигурация не выдаётся.

Сдача и черновики используют AJAX с CSRF, без навигации страницы. Для
PHP-загрузок multipart PUT передаётся POST с `_method=PUT`. После терминального
события WebSocket интерфейс получает сохранённый результат и уведомляет
существующую навигацию урока. История отделена от редактируемого черновика.

Таблица `reward_notices` используется для XP, званий, достижений, GC и
первого полного выполнения задачи. XP вычисляется по реальной разнице
суммарного опыта после применения оценки (с учётом лучших прежних работ и
штрафов). Максимум определяется сохранённой оценкой, а не локальной анимацией.
Записи создаются в транзакции; повторный callback не создаёт вторую награду.
`POST /insider/rewards/claim` атомарно отдаёт следующую карточку ровно одному
окну. Анимации конечные; предусмотрены закрытие и prefers-reduced-motion.

## Постоянное хранение оригиналов

Миграция `2026_11_14_140000_complete_native_submission_storage` добавляет
`code_artifact_contents`: код, текст редактора, сырые исторические записи,
вводы и ответы тестов сохраняются в БД. Данные с NUL кодируются base64 внутри
этой таблицы, сохраняя точные байты и совместимость с PostgreSQL TEXT.
`code_artifacts` хранит размер, SHA-256 и, для оригиналов, диск/ключ/дату сверки.

Для S3 задать `CODE_ORIGINALS_DRIVER=s3`, `CODE_S3_ENDPOINT`, `CODE_S3_REGION`,
`CODE_S3_BUCKET`, `CODE_S3_ACCESS_KEY_ID`, `CODE_S3_SECRET_ACCESS_KEY`.
`CODE_ORIGINALS_PREFIX=originals`; path-style включается при необходимости
через `CODE_S3_PATH_STYLE=true`. Нужен приватный bucket с правами чтения,
записи и проверки объектов для приложения. До настройки S3 оригиналы
сохраняются на отдельном приватном локальном диске `code_originals`.
При локальном режиме этот каталог должен быть постоянным томом.

Загрузка перед подтверждением проверяет размер и SHA-256 прочитанного
объекта. ETag не используется вместо контрольной суммы. Постоянная ссылка
ведёт в Coding Projects: после проверки прав она превращается в подписанную
ссылку S3 на 300 секунд. `?proxy=1` отдаёт файл потоком с сервера и используется
для превью без зависимости от CORS bucket. Исполнитель всегда получает поток
через свой подписанный API, без редиректа на посторонний origin.

Замена материала (`POST .../checker/files/{attachment}/replace`) создаёт
новую версию. Прежняя помечается удалённой только в текущем задании;
снимки старых работ и их оригиналы сохраняются. Очистки объектов в этом
релизе нет. Код, загруженный файлом, получает оригинал и текстовую копию в БД.

Подготовка существующего локального хранилища:

```bash
php artisan code-checking:prepare-storage
php artisan code-checking:prepare-storage --apply --actor=ADMIN_ID
```

По умолчанию выполняется только сверка. Явная запись копирует и проверяет
объекты, сохраняет тексты в БД и меняет локацию лишь после проверки. Повторный
запуск допустим; прежние локальные байты не удаляются. Команда не запланирована
в scheduler и не выполняется автоматически при миграции схемы.

## Дополнения к историческому импорту

`--report=/private/new-report.jsonl` создаёт приватный поимённый отчёт
предварительной проверки. Отчёт содержит ошибки и причины неполноты каждой
записи, включая отсутствующие оригиналы, повреждённые контейнеры, переименование
пути и необходимость конвертации. Исходное имя хранится отдельно от безопасного
пути исполнения. Отсутствующий base64 не превращается в пустой оригинал.

Изменившаяся уже импортированная запись блокирует обычный apply. После сверки
можно явно передать `--refresh-changed`: новый исторический запуск сохраняется
рядом с прежним, включая прежние исходники. Текущую ручную или новую проверку
повторный импорт не затирает. Старые определения задач версионируются;
настройки, уже сохранённые учителем, импорт не заменяет. Для IO параметры
нормализуются общими правилами; неподдерживаемая конфигурация остаётся архивом
с блокировкой исполнения. Язык берётся из конкретной отправки.

Все совпадающие ссылки Solution обновляются; оценки, submitted/checked,
XP/GC и достижения не пересоздаются. Отправка без Solution остаётся архивной;
её запрос преподавателю создаёт неоценённую запись в существующей очереди.
Исторические отчёты показывают только сохранённые публичные поля и вердикты.
Скрытые входы/выводы из текущих тестов в историю не подставляются, покупка
несуществующих исторических полей недоступна.

Вспомогательные файлы экспорта v2 (окружения, зашифрованные настройки AI,
имена, снимок Redis) сохраняются как приватные оригиналы. Их download доступен
только админу по `/insider/settings/code-executor/legacy-exports/{SHA256_manifest}/files/{name}`.
Окружение — архив для последующей проверенной конвертации, а не автоматически
исполняемый код. Настройки AI можно отдельно проверить/перешифровать командой
GeekExecutor `flask --app executor_server import-legacy-ai --directory ... --key-file ...`
с явными `--apply --actor=...` для записи. Секреты не выводятся в терминал.

## Совместимость и действия пользователя

Coding Projects больше не регистрирует `/api/geekpaste/*`. Старые клиент,
синхронизация признаков авторства и исходящие запросы лимитов/перепроверки
удалены. Оценивание native-работ выполняется внутренним сервисом. Старые
колонки `geekpaste_*` в Solution сохраняются для существующих отчётов.

Для старых ссылок подготовлен `/legacy/geekpaste/{id}/{view|raw|zip|image|xlsx}`.
GeekPaste включает редиректы только после сверки импорта:
`LEGACY_REDIRECTS_ENABLED=true`. Частное решение требует доступа через курс;
публичное показывает только отправленный текст и файлы, без тестов/критериев,
оценок и анализа авторства. Неимпортированный ID возвращает 404.

В workspace доступны сравнение двух попыток одного ученика, запрос учителю,
отдельная отметка просмотра и фильтр непросмотренных, управление публичной
ссылкой и ручная оценка через новый immutable run. Результат старой проверки
не изменяется при открытии ручной оценки. Все действия выполняются AJAX.

## События чата задачи

Сервис `task-chat` входит в Compose GeekClass. Миграция `2026_11_21_220000_notify_task_chat_changes` связывает сообщения, решения, запуски и отчёты с PostgreSQL LISTEN/NOTIFY. Веб-сервер проксирует Socket.IO по `/task-chat/socket/io/`. Клиент передаёт курс, задачу и ученика при подписке. Прежний адрес WebSocket обслуживает ранее открытые версии клиента. Перед подпиской сервис проверяет сессию и доступ к этому диалогу через Laravel. Кадр `changed` сообщает о сохранении изменений. Историю участник читает через обычный авторизованный маршрут чата. Кадр `ready` запускает сверку после подключения или переподключения.

Для новых ИИ-проверок GeekClass запрашивает у исполнителя формат `criteria-v1`. Результат может содержать массив `criteria` с названием, начисленными баллами, максимумом и пояснением. Строки хранятся у конкретного запуска. При прежнем ответе исполнителя чат показывает сохранённый Markdown. Перепроверка создаёт отдельный запуск со своим разбором.

GeekClass передаёт также `qualitative_criteria=true`. Критерий без отдельного веса получает статус `met`, `partial` или `unmet` и комментарий. При получении результата сервер проверяет структуру строк и сверяет начисленные баллы со шкалой. При выпуске сначала обновляют обработчик результата в GeekClass, затем воркер GeekExecutor.
