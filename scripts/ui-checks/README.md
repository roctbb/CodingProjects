# Повторяемая проверка интерфейса

Требования: установленный PHP с SQLite, Composer-зависимости проекта, Node.js, npm и браузер Playwright CLI. Перед проверкой собрать актуальные assets: `npm run build`. Для первого запуска CLI можно установить браузер командой `npx --yes --package @playwright/cli playwright-cli install-browser`.

```sh
npm run ui:baseline          # до рефакторинга: снимки и вычисленные стили
npm run build
npm run ui:compare           # после изменения: проверка поведения и сравнение
npm run ui:check             # самостоятельный проход без сравнения
npm run ui:check -- --flows-only
```

Проверка поднимает собственный PHP-сервер на свободном порту **127.0.0.1**, создаёт временную SQLite-базу из синтетического `fixture.sql` и закрывает только свой сервер и браузер. Запущенный сервер на 8000 и база приложения не используются. Авторизация тестовых ролей разрешена только в этом CLI-роутере; он находится вне `public/` и требует `UI_QA_MODE=1`. HTTP-интеграции, очереди и уведомления подменены. Секреты, реальные аккаунты и рабочие материалы в fixture не входят.

Дата фиксирована на 11 ноября 2026 года. Каталоги для изменяющих сценариев компьютера и телефона имеют отдельные базы. Если меняется схема, обновлять fixture вместе с тестовыми данными; не экспортировать рабочую базу.

Ключ шифрования создаётся заново для каждого запуска. Палитра и параметры ИИ явно заданы тестовым роутером, чтобы локальные секреты и цветовые настройки `.env` не влияли на результаты.

Проход включает:

- 22 экрана на ширинах 1440 и 390, в светлой и тёмной теме: две роли, курсы, Пульс, теория, Notebook, профиль, сообщество, магазин, план, журнал, отчёт, проверка, формы и вход;
- задержку каждого из модулей подсветки: однократное отображение Notebook, токены кода, копирование и обновление оглавления;
- страницы и поиск каталога, добавление и запрет дублей, возврат фокуса;
- комментарии, текстовые записи, редактирование, DnD на компьютере и перенос через меню на телефоне, отмену;
- конфликт ревизий и повтор, провайдеры, обзор и периоды, исключение и восстановление ручных дат;
- настройки и стоимость превью рамки, закрытие диалога и возврат фокуса.

Артефакты: `output/playwright/ui-regression/{baseline,current}/`: PNG, `report.json`, `comparison.json`, журналы CLI и сервера. Они не входят в Git. Сравнение требует точного совпадения CSS-свойств и допускает только 0,5 CSS-пикселя в геометрии из-за метрик математических шрифтов; снимки также следует просматривать глазами. `--flows-only` удобен для отладки действий и не заменяет полный проход.

`UI_HEADED=1` открывает видимый браузер. `UI_PALETTE=violet` проверяет пользовательскую палитру; результаты складываются в отдельную папку `violet/`. Эталон и сравнение должны использовать одинаковую палитру. Для сопоставления с ранее сохранённым CSS можно задать `UI_BASELINE_CSS=/absolute/path/app.css` при создании эталона. Проверка палитры меняет конфигурацию только локального тестового сервера.

Это структурные и браузерные проверки UI. Права доступа, расчёт баллов, сохранение и откат данных дополнительно проверяются PHP-тестами: `php artisan test --compact`. Подключение боевых провайдеров этот стенд не подтверждает.
